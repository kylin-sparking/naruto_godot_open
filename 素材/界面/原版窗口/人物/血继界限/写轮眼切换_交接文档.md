## 三、两套切换机制

### 1. 普通阶段互切 —— RotateFade（1:1 还原原版）
来源：`MainLib_plain.swf → swap/RotateFade.as`

```
p = 已过时间 / 总时长
旧眼.alpha    = 1 - p          旧眼.rotation = 720 × p      （顺时针转出）
新眼.alpha    = p              新眼.rotation = 720 × (1-p)  （反向转入）
```
- 时长 `2.0s`，缓动 `TRANS_QUAD + EASE_OUT`
  （★ 这个秒数**不随** `轮回眼特效速度倍率` 变化 —— 用户 2026-09-24 明确要求
  只加快轮回眼那套特效，"写轮眼之间的切换"保持原版手感）
- 关键：缓动加在**进度**上，不是加在 rotation 上（否则方向会反）
- 旧眼全程保持 `visible`，只靠 alpha 淡出

### 2. 「非轮回眼 → 轮回眼」专属特效
用户明确要求**只进不出**（离开轮回眼走普通旋转淡出）。

| 阶段 | 时间 | 内容 |
|---|---|---|
| 蓄力 | 0 → 0.35s | 红眼几乎不动（QUAD 缓动起手很缓） |
| 同步推进 | 0.35 → 1.95s | **红眼放大** 1.00 → 1.85（领先）<br>**白盘扩张** 0 → 1（稍慢 0.05s 收尾） |
| 收尾 | 约 2.0s | 红眼被挤出眼眶 → 轮回眼铺满眼眶（圆盘被开孔裁成眼眶的形状） |

**实现要点：**
- 红眼（旧瞳孔）：`scale` 从 1.00 补间到 1.85，`TRANS_QUAD + EASE_IN`，时长 1.95s
- 白盘：**圆形裁切 shader** 的 `u_radius` 由 `_扩张进度` 驱动（`_应用扩张()` 里写 uniform），
  延迟 0.35s + 时长 1.65s，同为 `TRANS_QUAD + EASE_IN`
- 轮回眼本体 `scale` **固定 1.00（原尺寸）**，全程不变 → **不缩放、不变形**；
  可见范围由 shader 的圆 + `轮回眼背景` 的开孔共同决定（视觉上就是「嵌在眼眶里」）
- 红眼仍是 `写轮眼背景` 的子节点 → 放大溢出被 `轮回眼背景` 的开孔挡住

> **两条曲线的关系**：红眼全程领先白盘 4~11 个百分点、几乎同时收尾 ——
> 即「轮回眼比写轮眼稍慢一点点」。这是用户明确要求的节奏。

### ★ 调参时最容易踩的规律

1. **缓动的「后置程度」顺序**：`LINEAR < SINE < QUAD < CUBIC < QUART < QUINT < EXPO`
2. **要「A 领先、B 稍慢」**：最稳的做法是**同一种缓动 + 把 B 整体后移**（加延迟、加时长）。
   混用不同缓动会让两条曲线**在中段交叉**，领先关系翻转。
3. **落后方的缓动不能比领先方更极端**，否则会「先躺平再突然爆发」= A 长完了 B 才蹦出来。
4. 半径下限取 `0.5px`（历史值是遮罩 `scale` 下限 `0.02`）。**不要改成 0**：
   半径 0 时整张图 alpha 全 0，动画第一帧会闪「眼睛不见了」。
5. ⚠️ **不要再用 `clip_children` 做这个圆** —— 它是硬裁剪（无抗锯齿），
   再叠加非整数缩放就会出台阶锯齿。要平滑边就用 shader 的 `smoothstep`。

## 六、已知问题

### 1. 写轮眼放大时抖动（**第二十五版已修**）

**"为什么红眼放大抖、轮回眼不抖"—— 用一个数值实验定死了：抖动来自「对贴图做连续缩放」这个动作本身，与素材好坏无关。**

| 对象 | 帧尺寸 | 每帧重采样残差 | 说明 |
|---|---|---|---|
| **轮回眼2.png（194px）** | 194 → 194，**从不缩放** | **0.000** | 像素与纹素 1:1 → 零重采样 → 绝对稳 |
| 六勾玉轮回眼（94px）放大 | 94 → 174px | **4.51** | 细节最密 → 抖得最明显 |
| 轮回写轮眼 | 94 → 174px | 2.54 | |
| 三勾玉 / 永恒万花筒 | 94 → 174px | 2.04 / 1.91 | |
| 净眼 | 94 → 174px | 1.06 | 细节最少 → 最不明显 |
| **★ 对照：把同一段缩放套在轮回眼2.png 上** | 194 → 359px | **2.22** | **连它也会抖** → 证明是「缩放」的锅 |

> "每帧重采样残差" = 把第 N+1 帧缩回第 N 帧尺寸后的差值（只统计不透明区，单位灰度级）。
> 理想渲染应为 0。完整实验脚本与可视化在 `<本机实验目录>\抖动调查_20260924\`。

**机制**：红眼 94px 被线性放大到 174px，**每一帧的缩放比例都不同 → 双线性采样的相位每帧都在变**
→ 细黑线（勾玉 / 环纹）的边缘在亚像素范围内来回「晃」→ 肉眼就是抖动。
轮回眼全程 `scale = 1.00`，成长靠改 shader 半径实现，**一次重采样都没有** → 完全静止。
（`project.godot` 里 `default_texture_filter=0`(NEAREST) 不影响本问题 —— 11 只瞳孔都已显式设为 `2`(LINEAR)。）

**❌ 第二十五版试过「运行时超采样」，失败了，已在第二十六版撤回**

- 做法：`_ready()` 里把瞳孔贴图用 Lanczos 上采样 **4×**（94 → 376）再当贴图用。
- **为什么坏**：节点是 `TEXTURE_FILTER_LINEAR`（不带 mipmap），而**静止时**显示尺寸只有 94px
  → 对 376px 的贴图就是 **4:1 缩小**。**GPU 的双线性永远只取固定 2×2 纹素** ——
  4:1 缩小时每 4×4 个纹素只采到 2×2，**采样不足 → 勾玉细线直接走样**。
  用户反馈「你把我的写轮眼弄坏了」。
- ⚠️ **我当时的验证脚本用 PIL 做的重采样，PIL 的缩小会把滤波核按比例放大（属于正确的缩小），
  所以没暴露这个问题；GPU 的双线性不会。这就是那次误判的根源 —— 量缩放类问题不能只用 PIL 模拟。**
- 撤回方式：删掉 `_瞳孔贴图超采样()` 调用与函数即可。
  **素材 PNG 从未被修改**（只改了内存里的贴图），所以撤回后画面立刻回到原样。

**✅ 正确做法：只做 2×（188），绝不要做 4×**

| | 静止时（显示 94px） | 放大中（显示 94→174px） |
|---|---|---|
| **2× 源（188）** | 94/188 = **正好 2:1** → 双线性 2×2 刚好覆盖 4 个纹素 → **干净、无走样** ✅ | 0.5→0.93，**全程不再有「放大」** → 抖动下降 ✅ |
| 4× 源（376） | 94/376 = **4:1 → 采样不足、走样** ❌ | 但静止画面已经坏了，没意义 |

两条路都可行：① 脚本载入时上采样 **2×**；② 把 11 张 PNG 重导出成 **188×188**
（Godot 导入时会连带生成 mipmap，更保险）。要碰 4× 就必须开 mipmap
（`mipmaps/generate` + `TEXTURE_FILTER_LINEAR_WITH_MIPMAPS`），
但那时 mip 会自动退回等效 94px、收益也就没了 —— **所以 4× 没有意义。**

**其他路线（供日后参考）**：
1. 关闭项目设置 `gui/common/snap_controls_to_pixels`（影响全局 UI，慎用）。
2. ~~`texture_filter` 4 → 2~~：已做，但对本问题作用有限（放大时永远用 mip 0）。

### 2. 轮回眼外圈环纹只露左右两段弧
素材环纹半径 57 / 74 超过眼眶半高 52，所以后两圈环纹在眼眶内只能显示成弧。
**这是几何必然**（第十九版圆盘被开孔裁切后更是必然），用户已明确接受
（「不用管能不能完全在眼眶内展示」）。
若要让三圈环全变完整圆，把 `轮回眼缩放` 调到 `0.70`（36→25、57→40、74→52），
但代价是本体只有 136px，且轮廓会变成「眼眶 + 圆盘圆弧」的**混合形状**（更难看的那个）。

### 3. 白盘扩张的边缘台阶锯齿（**第二十版已修**）
第十八~十九版用 `clip_children` + 白色实心圆贴图做圆形遮罩。那是**硬裁剪**
（二进制遮罩，不带抗锯齿），而且遮罩贴图被**非整数缩放了两次**
（`_造实心圆(256)` 装进 194 的框 = ×0.758，再乘扩张进度），
1 像素宽的过渡带被压到不足 1 像素 → 边界量化成 **2~3px 台阶**。
放大 6 倍看是一圈齿轮状的锯口 —— 用户描述为
「**感觉像是被什么切了一样 / 为什么不是原本的样子出现**」。

**修法**：换成挂在「轮回眼」上的圆形裁切 shader（`轮回眼圆形裁切.gdshader`），
在**片元里用 `smoothstep` 按距离算 alpha** → 边缘天然平滑，且与缩放无关。
圆盘贴图本身一动不动，素材原本的样子（含自带的柔和外沿）被完整保留。

**若将来边缘又变毛/变粗**：① 先查 `u_edge` 是否被改小（默认 1.2，<0.7 会重新出台阶感）；
② 再查是否有人把 `clip_children` 那套加回来了；③ 最后才怀疑素材本身的分辨率。

### ★ 试做项的「一句话回退」
第二十七版把白盘的起手时机与红眼对齐了。要回到参考录影的旧节奏，只改两行：

直接拷回来也行。

### ⚠️ 教训（关于「用缩放治抖动」）
**判断「缩放会不会走样」不能只靠 PIL 模拟**：PIL 的 `resize` 缩小会把滤波核按比例放大（正确的缩小），
而 **GPU 的双线性永远只取固定 2×2 纹素**。所以「把源图放大 N 倍再缩小显示」这条路，
N > 2 在无 mipmap 时必然采样不足。**要验证渲染类改动，得看真机截图/录屏，不能只信离线数值。**

### 核心结论（第十九版重写，别再翻案）
> **可见轮廓由两个边界竞争**：圆盘自己的圆弧 vs 轮回眼背景的眼眶开孔。
> 开孔宽 **167 < 圆盘直径 194**，所以**每个方向都被开孔完整裁到** → 轮廓 = 开孔（眼眶）的形状。
> **用户要的就是这个**：圆盘像嵌在眼眶里（对照他给的 PS 合成图：脸层必须压在眼球层**上面**）。
>
> 代价：素材最外两圈环纹（半径 57 / 74）超过眼眶半高约 52，只能显示成**左右两段弧**。
> 这一点用户已接受 —— 他 PS 成品图里可见紫色量出来是 **172.5 × 109.1 素材像素**，
> 与游戏开孔 **167 × 106** 基本一致（长宽比 1.581 vs 1.575）。
>
> ❌ **别再为了「完整正圆」把开孔脸压到圆盘下面** —— 那会让圆盘溢出眼眶、压住眉毛额头，
> 而且圆盘最外圈是近黑色（r≥88 处 RGB≈20,14,38），压在眉毛黑线/眼窝暗部上边界会糊掉。

## 八、翻页控件

底部 `上一页` / `页码` / `下一页` 三个节点，行为与左栏阶段按钮**共用同一份状态**：

- `页.上一页` → `_on_上一页()` → `_切换阶段(当前 - 1)`
- `页.下一页` → `_on_下一页()` → `_切换阶段(当前 + 1)`
- `页码` 文字 = `当前 / 总数`，在 `_切换阶段()` 最前面刷新（数字与眼睛同时变）
- 到两端时箭头调用 `设置是否可用(false)` → 变灰 + 普通箭头光标（由 `箭头按钮交互.gd` 实现）
- 键盘 `←` / `→` 也能翻页（`_unhandled_input`，不抢 UI 事件）
- ❌ **鼠标滚轮翻页已删除（第三十版）** —— 它和左侧阶段列表（`ScrollContainer`）打架：
  - 列表**还能滚**时：滚轮被 ScrollContainer 消费 → 正常，只滚列表；
  - 列表**滚到两端之后**：ScrollContainer 不再消费滚轮事件 → 事件漏成 `unhandled`
    → 被 `_unhandled_input()` 接住 → 直接调 `_切换阶段()`。
  - 用户看到的就是「**滚到底以后继续滚，滚轮变成了在按按钮**」。
  - ⚠️ **滚轮只应该滚列表，不要再把滚轮翻页加回来。**

## 九、提升写轮眼阶数弹窗（第二十八版接线）

弹窗是用户在编辑器里建好的，结构与柔拳页的**完全一样**：

```
写轮眼内容
└─ 提升写轮眼阶数弹窗  [Control]  clip_contents=true，静止位置 (5,228)，**默认 visible=false**
    ├─ ColorRect / 底图 / 柔拳灵符(Label) / 道具框 / 提升祝福值 /
    │   说明文字1·2 / 消耗说明文字 / 成功率说明文字 / 祝福值进度条 /
    │   购买按钮 / 开始提升按钮 / 自动提升按钮 / 关闭按钮
    └─ 滑出动画  [AnimationPlayer]   滑入 / 滑出 两条 0.5s 动画（改 .:position）
```

- 弹窗挂的脚本 = **`血继界限/脚本/提升写轮眼阶数弹窗滑动动画.gd`**
  （`open_popup()` 播「滑入」/ `_on_close_button_pressed()` 播「滑出」），
  与柔拳页那份**同源**（多处理了「本页弹窗默认隐藏」这件事），
  所以滑动效果完全一致，同时**不再依赖 柔拳/ 目录**（这一页要单独打包发走）。
  > 第二十九版之前这里的 `.tscn` 引用的是 `柔拳/脚本/提升柔拳阶数弹窗滑动动画.gd`，
  > 已改成上面的本地副本（`.tscn` 里 id 不变，只换了 uid + path 一行）。
- 接线（与柔拳页同样的做法，写在 `.tscn` 的 `[connection]` 里）：

| 事件 | 处理 |
|---|---|
| `提升写轮眼阶数.pressed` | → 弹窗 `open_popup()`（先 `visible = true` 再播「滑入」） |
| `提升写轮眼阶数弹窗/关闭按钮.pressed` | → 弹窗 `_on_close_button_pressed()`（播「滑出」） |
| AnimationPlayer `animation_finished("滑出")` | → `visible = false`（避免停在 y=700 被画到面板外面） |

> ★ 另外 `写轮眼切换_修正版.gd::_接线提升阶数弹窗()` 还有一层**运行时兜底**：
> 只有当场找不到 `.tscn` 那条连接时才自己 connect，避免一次点击触发两次 `open_popup`。

> ★ **为什么脚本接 + .tscn 连接两者都留**：`.tscn` 是「正式路径」（和柔拳页一致、可独立打包），
> 运行时兜底防的是「编辑器保存时把连接冲掉」这类意外。

自检脚本的**断言 F** 会校验：弹窗存在、`滑入/滑出` 两条动画都在、按钮已接线、
模拟点击后 `visible` 变 true。
