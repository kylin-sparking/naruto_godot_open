## 一、判"原版到底有没有这张图"的唯一可靠办法

这是最值钱的一条：**只认导出表**

```
SymbolClass（tag 76）  ∪  ExportAssets（tag 56）
```

**不许用解压明文字符串做子串匹配**——Flash 库互相 import 符号名，明文出现 ≠ 该库导出
（实测 `Char_10000075.swf` 明文含某名字但导出表没有：子串匹配会把它报成"可补"，永远补不出来）。
**二手美术包更不能用来判"原版无图"**（它本身不完整；当年 85 条"补不出来"全是照着它误报的）。
判据只有两份 SWF 库：`2.2.3/www/act_web_nya_208_isolated/swf`（客户端）与工程 `素材/原版直解/` 的来源库。

任何"素材是不是补不出来"的问题，先跑 `开发工具/查证素材缺失.py`，别手查。

## 二、SWF tag 头解析（记错的三个点）

```python
头 = struct.unpack("<H", 正文[偏:偏+2])[0]
类型 = 头 >> 6
长   = 头 & 0x3F
if 长 == 0x3F:            # 0x3F 是转义标记，真长度是后面的 u32
    长 = struct.unpack("<I", 正文[偏+2:偏+6])[0]; 偏 += 4
```

- 头部跳过字节数 `8 + (5 + 4*位宽 + 7)//8`，`位宽 = 正文[8] >> 3`。
- **别凭记忆读帧数**：`[4:8]` 是文件声明总长 u32（不是帧数）；fps 是 16.16 定点 4 字节，帧数是紧随的 u16。
  **要帧数就数顶层 `ShowFrame`（tag 1）个数**，实测与头部一致且不依赖 RECT 位数。
- RECT 是**位打包**的（5 位宽 + 2 位符号 + 4×位宽有符号数），不许按 `struct.unpack("<hh")` 读字节。
- 压缩头三种：`FWS` 不压缩 / `CWS` zlib / `ZWS` lzma（raw；`props` 在 `[9]`、`dict_size` 在 `[10:14]`、数据从 `[22]` 起）。

### DefineBitsLossless2（tag 36）直解

ffdec 对这类会卡交互重试 → `开发工具/swf位图直解.py`：

```
UI16 chid, UI8 format, UI16 w, UI16 h, 然后 zlib 数据
format 5（32 位 ARGB）：行距 w*4、不补行尾；Flash 存预乘，还原直通：r' = min(255, r*255//a)
format 3（8 位索引）：按 4 字节补行尾，前有 色数*4 的 BGRA 调色板
```

### 但别养成长期习惯：先试 ffdec

手写解码前**先做决定性实验**（跑一次 ffdec 看能否干净导出）。tag 编号在不同批次文件里 35/36/82 混用，凭记忆写必错。

```bash
ffdec -format image:png  -export image  <出目录> <swf文件或目录>
ffdec -format sprite:png -export sprite <出目录> <swf文件或目录>
ffdec -selectid <chid>   -export sprite <出目录> <某个.swf>     # 只导一个符号，秒级
```

产物命名口径（三处工具共用，别自创）：

```
image  : <出>/<swf名>.swf/<chid>_<类名>.png
sprite : <出>/<swf名>.swf/DefineSprite_<chid>_<类名>/<帧号>.png
包里的图: <库名>.swf_<chid>_<类名>.png
```

### 裸位图 ≠ 客户端看到的元件

判据：**看 SymbolClass 指向的 chid 是什么类型的 tag**。指向位图 → image 模式（`ByteArrayImage` 取的就是
BitmapData）；指向 Sprite → sprite 模式（客户端 `InstanceManager.createInstance(className)` 实例化的是**元件**，
实测两者差 777 像素）。

## 三、避坑清单（症状 → 真因，全是在本工程踩过的）

1. **Bash 工具把非 ASCII 词当命令**——`出=xxx` 被当命令、脚本静默不产出。shell 变量名一律 ASCII。
2. **Bash 每次调用后重置 cwd**——每条自带 `cd X &&` 或全用绝对路径。
3. ~~`验证全部.ps1` 首败即抛看不到全量~~——现状：主门 60 条 fail-fast 是**故意的**，全量账在跑批日志逐条行;
   看全量红绿用退出码 + 日志计数（**数账要数门自己的通过语，别 grep 关键字**——2026-10-03 把 5 红数成全绿过）。
4. **`ResourceLoader.exists()` 对刚拷的 PNG 恒 false**——没 `.import` 元数据。跑门先 `--import`。
5. **`--headless` 截不了图**——量具/对照图必须窗口模式（现仓 Godot：`Godot_v4.7.x-stable_win64_console.exe`）。
6. **控制台 GBK 把中文打成 `????`**——`PYTHONIOENCODING=utf-8` 或脚本里重配 stdout。
7. **`/tmp` 在 Git Bash 和 Windows Python 里不是一个地方**——跨工具传临时文件用显式绝对路径。
8. **`cat <<'EOF'` 会吞 `\`**：`\\d` 变 `\d`，`\\a` 变 `\a`=**BEL 字符把路径写坏**（本工程三次中招：
   `$材` 漏盆、文档路径烂行、生成器 Bell 字节——**写文件一律用 Write 工具，别用 heredoc；含 `\a\w\b` 的路径用 `chr(92)` 拼**）。
9. **导入缓存按"源"去重 → 索引指向没落盘的路径**——去重键必须是**目标文件**（一图多分类号引用）。
10. **索引"键"用单值吃掉复用关系**——被多个节点共用的类名，键要列表。
11. **刷新门禁基线必须有理由，并顺手补一条真不变量**——只改数字 = 把门禁改成摆设。
12. **删数据行之前必须做字段级 diff**——不许靠 git 兜底（现在有了 .git 也不能省 diff）。
13. **别用子 agent 汇报的数字写文档**——凡写进交付物的数字，自己跑一遍拿到。
14. **用户的 Godot 编辑器在跑时会偷偷重存场景**——查"谁改了文件"先看编辑器进程；场景交证据前跑
    `开发工具/审计`（或出标记表）核对，**目标场景别在编辑器里开着**。
15. **按序号取节点，不按名字取**——用户会改节点名。
16. **8× 放大不许不诚实**——大图取"能塞进格子的最大整数倍率"并把倍率标在图上。
17. **原版资源里的第三方水印要单独问**——"原版有的不许简化" vs "这行字不该出现在我们的产品里"
    冲突时，列进未决问题问用户，不自决。
18. **"夹具已预置 X"要看预置在哪个角色身上**——2026-10-04 的 zq 案：种子只给角色 2 种了精华，
    主角色的门被自己人的校验闸挡死、崩得像协议断了。

## 四、素材类模块开工检查单（A4 后仍通用）

```
□ 1  .dat 里这个分区的真实结构是什么？
□ 2  引用集多少条？去重后多少 swf？多少唯一类名？（三个数不一样，别混）
□ 3  每个引用在库里命中吗？（用导出表判，不用明文）
□ 4  SymbolClass 指向位图还是 Sprite？→ image 还是 sprite 模式
□ 5  显示尺寸/注册点从哪来？（origin 在 .dat，方框尺寸在代码常量，XML 里可能根本没有）
□ 6  库里有没有 `[1]` 之类不被引用的副本？导出要跳过
□ 7  索引里被复用的类名，键是不是列表？
□ 8  跑 --import，再跑门禁，再看 ResourceLoader.exists
□ 9  8× 单件放大图（≥3 类）+ 实机截图
□ 10 门禁基线若变，写清为什么变，并补一条真不变量
□ 11 未决问题：涉及"原版有但产品不该有"、"要动别的模块"的，列出来问，不自决
```
