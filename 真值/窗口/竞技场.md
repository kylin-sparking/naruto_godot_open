## ⑰ 这一轮抓到并修掉的两处"声明 ≠ 屏幕"（同一条 Godot 缺省值）

1. **`战报块/底` 被贴图顶大**：`.tscn` 声明 482×140（原版 `PvpZhanBaoPanel.as:19-21` 把 482×198 那张皮
   **整帧压扁** —— `UISwfMovieClipAgent` 的 `set w/set h` 就是 `_content.width/height`，没有 scale9Grid），
   但 Godot 4.7 的 `TextureRect` **缺省 `expand_mode = 0 = EXPAND_KEEP_SIZE`** 把贴图天然尺寸当最小盒，
   而 `Control::set_size` 绝不低于最小盒 ⇒ 140 被静默顶回 198，整页从 567 高的框里掉出去 32 像素。
   ② 那道读 `.tscn` 声明值的几何门对它完全失明，是 `窗口布局体检`（读屏幕值）报出来的。
   修法 = `expand_mode = 1`(IGNORE_SIZE) + `stretch_mode = 0`(SCALE)。同页 `候选块/底` 天然 == 声明 ⇒ 不用动。
2. **英雄榜 `横分隔线` 用了平铺**：原版 `PvpRankWindow.as:75-79` `new LineHPicF(); width = list.width`，
   而 `list.width = 342`（`_contentBg=380−2×8`、`MPane=364−2×5`、`list=354−2×5−2`，`UIConfig:890/892`）
   皮天然 252×2 ⇒ 要的是**整帧横向拉伸**；场景里写的 `stretch_mode = 1` 是 **TILE**（重复 + 接缝）。改 `0`。
   同页那三根 `TableSeparatorLineF`（2×20）天然 == 声明 ⇒ 无差。

⇒ **口径**：`stretch_mode = 1` 在"声明 == 天然"的件上与 SCALE 逐像素相同 ⇒ 全页都写 1 也不会立刻露馅，
只有"声明 ≠ 天然"那几枚才现形。两道都用离线门第⑨段钉住：两扇真装进树里、等两帧、逐件比
`get_size()` == 声明盒（31 枚：主窗 27 + 英雄榜 4），并带一条阳性对照（同一条 482×140 声明压在 482×198 的皮上，
缺省档顶回 198、IGNORE 档 140）。⚠ 对照**必须两个新建实例**：同一节点先 KEEP 顶大之后再改 IGNORE，盒不会自己缩回去。

### ⑳-1 bug1：先排除掉两个假候选，再定位到相机

1. **不是瓦片摆位漏了 origin。** 第一版量法（`<临时目录>/合成竞技场地面.py`）按"瓦片 y = 图上沿"合成，量出脚点线 540 与瓦片行顶 584 差 **44 像素**，看着就像"人浮在地面上方"。

   按同一公式重合成（`<临时目录>/合成竞技场2.py`）后，草地表面正好压在红色脚点线上（523..584 那一档，脚点 540 落在草皮下 17 像素）——**地面本身没问题**。
   全工程普查（`<临时目录>/普查脚点瓦片.py`）：168 张图的"瓦片行顶 − 脚点 y"众数是 **44**（分布 18/19/32/34/36/37/41/43/44/45），
   这套值就是各图块集 `enH0` 的注册点 y（`GameData.dat` 的 `Tile[图块集][u][no].origin`，实测 `zhongjiezhigu/enH0 = (0,61)`）⇒ **每张图都这样，不是竞技场的病**。
2. **不是"地图下面没铺满"。** 竞技场瓦片行 584/645/706 各 61 高，正好铺到 `VRBottom=767` 收口，底下不缺格。
3. **真因是取景。** 竞技场 `VR` 只有 **1921×767**，他实机那扇是 **1920×1032** ⇒ 图比窗口**矮** 265 像素。
   `世界相机.gd` 原来写 `center.y = 地图中心 if top > bottom else clamp(...)` ⇒ 退化时**居中**，屏幕上下各露 132 像素，
   平台岩壁在屏幕 y≈900 处**横向切断**、下面露出一条天空 ⇒ 眼睛读成"整块平台悬空"。
   他截图的竖直剖面实测：地面带 700..912 是岩石，**912 处突变 286**（下面就是背景），与算出来的 899.5 对得上。

   退化时后算那条赢 ⇒ 视口顶边 = 767 − 1032 = **−265**，地图下沿正好贴在屏幕底。
   ⚠ **不许图省事写 `clampf()`**：Godot 的 `Math::clamp` 是 `v < lo ? lo : (hi < v ? hi : v)` ——
   `v < lo` 时**直接返回 lo、不再比 hi**，退化档要的正是"比完近边还要比远边"。所以那两行必须**分开写** `minf(maxf(...), ...)`。

### ⑤ 结论与两条待办

1. **原版没有"对手 AI"这个东西** ⇒ 上一版真值 §⑳-2 那句"未决：对手在原版里是真玩家还是假人"**收口 = 真玩家**。

   上一轮已记，这里再钉一次，防止有人把它当"进竞技场才能打人"的开关去接。
3. **对面不在线时原版怎么办，客户端给不出答案**（协议里没有"假人"这一档，`PkCandidate` 也没有
   online 标志，只有 `inBattle`）。本机没有原版服务端 ⇒ 只能存疑。
   我们的模拟服务端是"从账号库里取 ≥45 级的角色做快照假人"，这是**那份 Python 模拟服务端自己的发明**。

   改成"远程玩家 + 玩家帧(进场/36/187/1328/194)" —— 这条通道我们**已经整条验过**（两个真号互看互打），

   移速也自然用角色自己的 `walk_speed`，不会再出现"借世界BOSS 模板 speed=740 ⇒ 1295 像素/秒"那种事。
