## ② 点它弹四行菜单（`showPvpModeViewHandler:242-270` + `PKModePane2.as`）

  （`:68-71`，不是九宫格）。

  我们把选中条放在行的**最下层**（原版 addChild 在最后=最上层，但它是半透明底，压上去会把字压淡）。
- 行色 = `UIConfig`：和平 `UI_YELLOW 16773120 = #FFF000`、组队 `UI_BLUE 2003199 = #1E90FF`、
  家族 `UI_GREEN 65280 = #00FF00`、全体 `UI_RED 16711680 = #FF0000`（`UIConfig.as:86/106/288/490`）。
  ⚠ 这四个是 `static var` 不是 const，#265 那条"UI_YELLOW 到底 FFF000 还是 FFFF00"待决仍开着。
- 行文案 = `CN.HEPING_MODE / ZUDUI_MODE / JIZU_MODE / QUANTI_MODE` 原文（四句【xx模式】…）。
- 悬停/选中：`overHandler` 亮、`outHandler` 回到"是否选中"（**不是一律灭**）；
  `setCheck(模式)` ⇒ `setSelectdItem`：旧行灭、新行亮。整行 `buttonMode + useHandCursor`。

## ⑥ 这一轮被在线腿逮到的真缺陷（已修）

`PK模式菜单` 原来用 `项.set_meta("选中", 号 == 模式)` 记"哪一行是当前档" ⇒ **Godot 4 的 metadata 键要求
合法标识符**，中文键报 `ERROR: Invalid metadata identifier: '选中'` 且**静默存不进去**（值永远拿不回来）。
后果：`_悬停` 移开时 `get_meta("选中", false)` 恒 false ⇒ **悬停过当前那一行之后，它的选中条再也亮不回来**，
而且每次换档刷一串 ERROR。修法：删掉 meta，改记在脚本自己的 `static var 当前: int`（= 原版
`PKModePane2.selectdItem` 那一位），`_悬停` 按节点名 `模式行<档>` 与 `当前` 比。
⇒ 与 `flash-mbutton3-state-skins` 里"绝不要用 set_meta 存中文键"是同一条坑，**这次是自己踩上去的**。

另记一条观察（不是缺陷）：一次切档对面会收到**两发** `1792:2:<我的号>:1` —— 一发是进图时服务端把
同屏每个人的模式推给新来者（`fake_flash_server.py:14222/15392` 那两处），一发才是 `_send_visible` 的广播。
两发同值、客户端幂等（`_handle_pk_mode_text:3926-3933` 只在 `号 == 自己` 时写权威档），所以只判"收到过 [我号,4]"
这一发（4 只可能来自我点的那一下，变异 B 证明不发就永远不出现）。

## ⑦ 菜单文字落点（真值出处认 **as3_MainLib**，见 真值/系统/PK判定.md §1） + 「打其他玩家」那条链（10-25 夜补）

**菜单那四行的字为什么偏上**：原版一颗 MButton3 里塞一个 `MLabel`，
`MLabel.as:211-212` 是 `setSize(0, 20)` + `textField.y = 2`，而 Flash 的 TextField 自带
2px 上下留白 ⇒ 墨迹顶部落在第 4 格（行 y 20 ⇒ 墨迹 4~16，与钮的可见条同轴）。
Godot 侧照这个数写 `字.position = Vector2(钮宽, 4)`（原来是 0 ⇒ 高 4px，用户一眼看出来）。
量法：`测试/姓名战斗挂机回归测试.gd` 的模式钮腿加了一条"四行文字都在 (23, 4)"，
该行现在 **27 条**（整门末行原文：`汇：判 165 条 / 红 0 条（姓名、战斗模式与挂机回归测试：通过）`）。

**"开了全体为什么打不了人"是另一件事**，判定与文案都不在这扇窗里：
逐句真值、五档模式、四道闸的顺序、13 句文案的逐字比对、离线判定表（91 条）与
在线腿（44 条，两个号真打真掉血）、变异实测六条，全部在
**`真值/系统/PK判定.md`**（#352/#353/#354/#355/#356）。
一句话结论：**木叶村 100000000 在原版 `peaceMaps` 里，村里打不了人是原版规则**；
要在非安全图（如 102010000 木叶森林）、双方都 ≥45 级、模式=全体才打得动。
