## ④ 按钮态与页码那两条呆账

`showProgress(:303-312)`：**一句 `updateButtonState` 都不叫** ⇒ 载入期间被它放开的六枚
（下/末/首/前/刷新/搜索）是 enabled 的，只有 `_progressLabel` 亮着。
`updateButtonState(:109-134)`：
- `页 > 0` ⇒ 首/前 亮，否则灰；`页 < 总页 − 1` ⇒ 下/末 亮，否则灰。
- `if (_totalPage > 0) _pageLabel.text = …`（`:130-133`）**没有 else**
  ⇒ 总页 = 0 时页码格**压根不重写**，屏幕上留的是上一句（门里钉成「1 / 1」）。
`总页 = Math.ceil(总 / 11)`（`:360`）—— 同样**没有 `max(1,…)`** ⇒ 0 条就是 0 页。
`refreshHandler(:385-390)`：`_quickKey = 1`、`_searchKey = ""`、`loadPage(_currentPage)`
⇒ **重载的是当前页**，而且**不碰输入框、不碰下拉显示**（玩家看得见一个已经不生效的词，这是原语义）。
`searchHandler(:97-107)`：框空 ⇒ 先弹 `MDialog.showMessageDialog(CN.STALL_LIST_WINDOW_INPUT_KEY)` 且**直接 return**；
非空才 `_quickKey = selectedItem.data; _searchKey = 框; loadPage(0)`。
`quickSearchHandler(:158-162)`：全文没有一句 `addEventListener` ⇒ **CHANGE 没人听，是死代码**；
类目真正生效是在下一次点「搜索」那一刻 take `selectedItem.data`。
`viewUserInfoHandler(:137-149)`：选中项的 `payerId == stats.id` ⇒ **不发包**，直接
`setDOShow2(charWindow, true)`；否则 `API.ui.clickCharacter(payerId)`。
`viewStallHandler(:346-352)`：有选中项才 `API.ui.viewStall(payerId)`（= `1296:2`）。

## ⑤ 协议：切页的是服务端

`loadPage(:169-181)`：`startIndex = 页 × 11`、`endIndex = startIndex + 11`、带 `quickKey`、`searchKey`
⇒ `1296:0:起:止`（无词）/ `1296:1:类:词:起:止`（有词，`UI.as:800-808` 那两支）。
`setPageData(:354-364)`：`showProgress(false)` → `_currentPage = _requestPageIndex` →
写总数 → 算总页 → **`_pages = param2` 整表交给 `new DataProvider`** → `updateButtonState`。
⇒ 客户端**一律不再切一片**；一屏只显示 11 行靠的是 `_list` 那 240 高 + `verticalScrollPolicy="off"` 的裁剪。
服务端侧证实：`fake_flash_server.py:25430-25475` 切的是 `matching_stalls[start_index:end_index]`，
而帧里的「总」写的是 `len(matching_stalls)`（全量）。
所以端口必须能吞下"多送"：13 行全建出来，第 12、13 行由 `clip_contents` 挡住 —— 门里两条腿各钉一个方向。

## ⑥ 开窗 / 关窗 / 复位

- 背包底部那颗「摊位列表」（`ItemWindow2.as:1547-1557`）= `if (stallListWindow) setDOShow(...,false) else showStallListWindow()`
  ⇒ **点击一跳不发**；`showStallListWindow():4568-4576` = `setDOShow` + `init()`，
  而 `init():152-156` 里才是 `loadPage(0)` ⇒ 发 `1296:0:0:11` 的是**开窗那一刻**（端口在 `功能窗口.open_page`）。
- 回帧的消费者在 `窗口管理._on_stall_list`，判的是 `已打开()`
  ⇒ `StallDataManager.as:88-94` 那句 `if (stallListWindow)` 的等价物：关着时来的帧**丢掉、不把窗顶回来**。
- 关窗 = 复位（`空态()`）：总/行/页/请页/快序/词/载/选 全清，下次开从第 0 页重发、框空、类目回第 0 项。

## ⑦ 无头夹具的一处已知局限（别照着它改端口）

`root.push_input()` 在两扇窗重叠的那一带，命中栈给出的却是**先建的那扇 canvas**
（`gui_get_hovered_control()` 报随身摊位的内容页），与 `窗口管理.gd:315-326` 在真编辑器里
实测的「`layer` 才是说了算的那个」相反 —— 摊位列表窗 `layer=112` 明明高于随身摊位 111，
且 `_盘点` 打出的命中栈里那一点上除菜单自己没有任何控件压着。
⇒ 判为**夹具拾取**局限，真机 800×600 不复现。门里下拉第三项因此走 `pressed.emit()` 钉行为，
`z_index` 那条改钉**结构数值**（把 `底.z_index = 50` 变异成 0，本门靠这条抓红，实测过）。
