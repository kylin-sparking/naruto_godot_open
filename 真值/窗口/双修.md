## §A 同图两个号互相看得见（#210，2026-10-14）

用户实机报：**登两个账号、两个角色在同一张地图，谁都看不到对面**；并指出

### A.1 协议面（行号级）

同族的 **241 怪物移动一直是按 `opcode : 0 : id : …` 读的**（离线门里那条注释就是它），
只有 187 这一条偏了一格 —— 对照自己兄弟就能看出来是笔误，不是协议本来如此。

### A.2 症状与真凶

```gdscript
# 修前（后端连接._handle_move_player_text）
"character_id": int(fields[1]), "x": int(fields[2]), "y": int(fields[3])
```
⇒ `character_id` 读到 command（**0**）、`x` 读到角色编号、`y` 读到 movement_type。
下一句 `if map_players.has(state.character_id)` 拿 0 去查 ⇒ **查不到 ⇒ 整帧扔掉**，
`player_moved` 虽然发了、`地图实体._on_server_player_moved()` 也只能按编号 0 取演员 ⇒ 取不到 ⇒ 直接 return。

结果：**对面的位置永远停在进图那一刻**。两个号都从同一出生点起步（夹具实测主号 (252,206)、
对端帧里 (252,204)）⇒ 先是完全重叠看不出"有别人"，一走开就互相看不见 —— 与用户那句
"谁都看不到对面"逐字吻合。生成/移除两条一直是对的，所以"第一次进图能看到人"这条路本身没坏。

### A.2b 第二条独立根因：远程玩家**根本没进层带**（用户补的疑点"能点着却看不见"）

用户 2026-10-14 追问："就算两个人站的位置不同也看不到对方啊"，并补了一条关键线索 ——
**点他站的位置能选中、能出他头像**。⇒ 节点在、命中盒在，坏的只是"画出来的那一层"。

`_on_server_player_spawned()` 里从来只设 `position`、**没设 `z_index`** ⇒ 远程玩家恒为 0；
而本工程的角色/怪物/NPC 全走 `地表.角色z()` = `层号*512 + 256 + 层内序`（层内三段见
`脚本/调试/渲染配置.gd:38-57`：物件 0..127 → 瓦片 128..255 → 角色 256..511），本地玩家在
`玩家.gd:875` 每帧刷这个 z。于是远程玩家坐在**地面瓦片与装饰物之下**，多数位置整幅被地形盖掉
—— 与"位置不同也看不见"对得上。

平手那一档另算：本地 `Player` 是 `LifeRoot` **之后的兄弟节点**，z 相同时按树序 ⇒ 自己压住别人。
原版全工程 `grep sortChildren|zIndex` **零命中** ⇒ 角色层就是 `addChild` 顺序，
**后进图的人后加 ⇒ 画在上面**。实测用户那两个号的存档坐标：木叶忍者 (2165,1213) 与
油女澪 (2164,1213) —— 同落脚点 ⇒ `层内序` 一样 ⇒ z 一样 ⇒ 不打破平手就谁也看不见谁。
⚠ 我先试的 `sort_offset` 在这版 Godot 上**不存在**（`ClassDB.class_get_property_list("CanvasItem")`
里没有这一项，跑起来报 `Invalid assignment of property or key 'sort_offset'`）⇒ 改成层带 +1。

修法：`_远程角色层次(位置) = _角色层次(位置) + 1`，**生成与每次移动都刷**
（`_on_server_player_moved` 以前只补间位置、不刷 z ⇒ 走到别的落脚点又会被原来的地形压住）。

## §B 看别人走路 / 放招要播动作帧（#211 #212，2026-10-14 用户第二条反馈）

用户原话：**"我的视角看别人走路是平移并不是播放运动帧，并且战斗特效可以看到但是角色还是直板板地站着"**。

### B.1 动作号这张表（唯一真源）

`com/mxw/roles/enums/Action.as:6`
```as3
public static const ActionName:Array = [null,"stand","jump","walk","ladder","rope",
        "alert","sit0","sit1","hit","dead","attack","stab1","stab2","stab3"];
```
**移动与出招共用同一套号**：`AbstractAttackSkill.as:610-626` 出招时 `character.setMovementAction(useStance)`
并把同一个 `useStance` 塞进 `createSkillMsg` 发出去 ⇒ 旁观者拿包里的 stance 直接就能播。
本工程把它落成 `原始动画精灵.动作号表` + `动作名(号)` / `动作号(名)` 两个静态函数（**只此一份**，
别处不许再抄一张）。

### B.2 两处断口

| 面 | 断在哪 | 修法 |
|---|---|---|
| 走路 | `send_movement` 发的是 `36:x:y:<朝向>` —— 第 3 段在服务端是 **movement_action** 槽（`fake_flash_server.py:34625`），±1 的朝向落进去被夹成"站立"；收侧 `_handle_move_player_text` 也从不切动作，只补间 position | 发 6 段 `36:<x>:<y>:<动作>:<速度x>:<速度y>:<状态>`；收侧读 `[10]` 动作号 + `[7]` 速度x，`_播远程动作()` 按 `Action.as` 切 `walk/jump/ladder/rope/sit0/stand`。**停下来那一拍必须发得出去**：`_sync_backend_movement` 原来"位置没变就 return"，会把"走→站"这次翻转吞掉 ⇒ 旁观者看着他原地踏步 |
| 放招 | 入站分发表里**根本没有 1328**（`OP_PLAYER_ATTACK`）⇒ 服务端转发的出招动画帧被整条丢掉，只剩命中特效 | `_handle_player_attack_text` 解 `{character_id, stance, direction, skill_id, x, y}` → `player_cast`；`地图实体._on_server_player_cast` 对远程演员 `play_once(动作名)`，播完回当前移动态 |

服务端**确实会把出招帧转给同伴**：`handle_player_attack_announce():41081`
`self._send_visible(self._strip_timestamp(read_str), include_self=False)`，注释原话
"Only peers should receive the animation packet; self-replay makes one key press execute the visible cast twice"。
`_strip_timestamp` 只剥结尾那段 ≥10 位的时间戳，我们这条帧以 `-:-` 结尾 ⇒ **段序不动**。

### B.3 平手与不打断

出手期间移动帧不许把这一招盖掉（与本地那条 `出手中` 同口径）。第一版写的
`演员.set_meta("出招中", true)` **静默无效** —— Godot 4 的 metadata 键要求合法标识符，
中文键存不进去（这条坑记忆里有，本轮又踩，被在线门当场抓红）。改成 `地图实体._远程出招中` 字典
（编号 → true），演员节点上只挂 ASCII 键 `remote_id`。

### B.5 还没收口的一条（要点头）

**纯普通攻击别人还是看不到挥拳**：普攻走的是 opcode 40（`CLOSE_RANGE_ATTACK`），服务端
`handle_attack()` 只做伤害结算、**不把它转给同伴**；原版是靠服务端转发这条来播施法者动画的。
两条路选一：① 服务端在 `handle_attack` 里加一条 `_send_visible(..., include_self=False)`（改服务端行为）；
② 客户端普攻时补发一条 1328（服务端会照转，但那条帧同时是"伤害授权"帧，会带副作用）。
本轮**两条都没动**。

### B.5 第三条：看别人走路"有延迟"（用户 2026-10-14 追问，实测坐实）

用户："我虽然看不到对面了，但**看玩家2运动时感觉有延迟**，原版本就有延迟吗？"
又说："**原版的延迟我肉眼分辨不出来，很低很低**"。

量出来的结论（不是感觉）：收端每收一包就 `create_tween()` 补间 0.1 秒到"上一个已知点"，
补完**停住等下一包** ⇒ 连续走 8 段、178 个引擎帧里**有 57 帧那个人完全没挪（32%）**。
这就是"走一下停一下"，跟网络无关 —— 服务端每条包都是即时转发的。

原版为什么不卡：`Client.onMovePlayer` → `CommandController.addMovements()` + 每帧 `tick()`
（`CommandController.as:24-38`）—— **没收到新包的时候，他还在按上一段的速度往前走**（外推），
所以两包之间那 6 帧是填满的，肉眼看到的是连续运动 + 几十毫秒的网络偏移。

改法（纯客户端）：`地图实体._远程外推`（编号 → {目标, 速度, 收包时刻, 动作}）+
`_推进远程玩家(帧长)` 每帧追"**期望位 = 采样点 + 速度 × min(过了, 0.1 秒)**"，收敛用指数
`差 * min(1, 18 × 帧长)`，`差 > 200` 才直接落位（传送门/换图）。三条自己踩出来的坑写进注释：
① 速度是**像素/秒**（服务端原样转发 `velocity.x`），当像素/帧用会一步跨 40 再倒回来；
② 外推只能猜一个采样周期，猜远了到期收回来就是一帧倒退；
③ 到期既不许硬拽到目标、也不许半路注销（会停在离真值几十像素处），要收拢到 <0.6 像素才注销。

## §C 延迟量成毫秒 + 别人放招的特效真的看得境（#214 #215，2026-10-14 用户第三次反馈）

用户原话：**"我测试了 延迟还是很大 你调查一下原版本是怎么实现延迟肉眼看不出来的 然后技能特效
还是看不到别人释放技能特效"**。上一轮"平滑度尺子"全绿却被打回 ⇒ 说明**量错了东西**：
静止帧/反向帧只说明"他不卡"，说明不了"我比他晚了 N 毫秒"。这一轮先把延迟**量出来**，再回原版取真值。

### C.1 原版的发送节奏（`com/mxw/roles/samplers/Sampler.as` 全文只有这一份）

| 行 | 内容 |
|---|---|
| `:17` | `SAMPLE_TIME = 5000`（**根本没被用到**，别当采样周期读） |
| `:55` | `if(_lastTimer == 0 || 距上次 >= 100 || 强制)` ⇒ 攒片段的最短间隔 100 毫秒 |
| `:59-65` | 片段 = `AbsoluteLifeMovement(位置, 距上次毫秒, 状态)` + `pixelsPerSecond = velocity` + flag + foothold |
| `:67-74` | `强制 || 列表长度 >= 1` ⇒ **当场就发**，发空列表 |
| `:83-95` `tick()` | 只要 `DIRECTION / ACTION / MOVEMENT_ACTION / POSITION / VELOCITY` 里**任何一格变脏** ⇒ `sampleMovement(true)` 立刻发 + `validate()` |
| `Character.as:2520-2523` | 本地玩家每帧调 `_sampler.tick()`；`World.as:278` 只有本地玩家挂 Sampler |
| `Character.as:2661-2665` | `forceSamplerSend()` = 立刻发，被 `KeyController.as:552/575/769`（停步/跳/落地那一拍）与 `HealHandler` 三处调用 |
| `AbstractPhysicObject.as:513-548` | ⚠ **匀速直行时 `applyVelocity` 直接写 `x += vx*dt/1000`，不走 `setPosition`**（`:688-699` 才是会标脏的那条）⇒ 直行途中没有 POSITION 脏标记 |

⇒ **结论：原版不是"每秒 60 包"**。它是"**状态一变就发（起步/停步/转身/起跳/落地/换落脚点），
两拍之间由收端自己的物理按着速度往前走**"。我们 10Hz 定频 + 每拍带速度，形状是对的。

### C.2 原版的收端：不追点，**自己走**（`CommandController.as:31-68`）

```
addMovements(数组) → _movements.concat(...)          :24-27   ← 排队，不是覆盖
tick():  while 队列非空 且 (已等时间 + 上次余量 >= 该片段的 duration):
            _target.x = 片段.position                 :46-47   ← 落位（硬对齐）
            _target.setVelocity(片段.pixelsPerSecond) :56      ← 把速度交回角色
            _target.status / climbing / grounded / currFootholdId 一起接
            shift() 掉这一段
```
`_target.setVelocity(...)` 之后**没有任何网络参与**：那具身体自己的
`AbstractPhysicObject.applyVelocity()` 每帧 `x += velocity.x * dt/1000`。
⇒ 旁观者与真身用**同一条积分式**，两边每帧挪得一样多 ⇒ **稳态误差只剩「单程网络时间 × 速度」**。
这就是"原版延迟肉眼分不出来"的全部机制 —— 不是它延迟低，是**收端不追点、自己走**。

### C.3 我们的两条真凶（都是"看着对、其实没跑"）

1. **`velocity_x` 那一格根本没解进 state**（`后端连接._handle_move_player_text` 的 state 里只有
   `velocity_y`，没有 `velocity_x`）⇒ `地图实体._on_server_player_moved` 里
   `state.get("velocity_x", 0)` **恒为 0** ⇒ "两包之间按速度继续往前走"这条外推**整段是死的**，
   只剩"指数追一个总在身后的期望位"：稳态永远欠 `速度 ÷ 收敛率`（400÷18 ≈ 22 像素 ≈ **55 毫秒**）。
   ⚠ 为什么上一轮全绿没抓到：`_远程外推` 里 `速度 == Vector2.ZERO` 的"反推兜底"只在**速度整条为 0**
   时才走，而 `velocity_y` 一直在 ⇒ 兜底也不触发。**协议三条断言只钉了 x/y/朝向，没钉速度** ⇒
   离线门 305 条一路绿、真机上人永远慢半拍。
2. **`request_skill_attack` 一遇到空目标列表就 `return false`** ⇒ 整条 1328 广播都不发
   ⇒ 对面既没出手动作也没特效。原版 `AbstractAttackSkill.hitTest():629` 是**一出手就发**，
   前面那个 switch 连"没有目标"那一档（`getSkillTarget()==2`，`:625`）都照样发 ⇒
   只有**结算那条 42** 才需要目标。现在改成：1328 照发（目标槽写 `-`），42 只在有目标时发。

顺带把 `_on_server_player_cast` 里"起手特效"与"身体播这一招"**解耦**（特效先放，再 `play_once`）：
原版这两件事本来就分属技能 effect 对象与 `setMovementAction`；绑在一起时，只要动作名在这套美术里
查不到，特效就被一起 `return` 掉 —— 症状正好是"人直板板站着、什么特效都没有"。

### C.4 延迟尺子（`测试/双人同图在线回归测试.gd` ⑨/⑩，47 条全绿）

两笔账分开量，才知道该修哪一层：
· **单向传输** = 出包那一刻 → 主号把这条 187 解出来那一刻（真 TCP + 真服务端广播，同一进程两条会话）；
· **晚看到** = 出包那一刻 → 主号屏幕上那具身体真的走到同一个点上那一刻（= 传输 + 收端的欠账，
  才是玩家眼里那个"延迟"）。

| 口径 | 改之前（只追点、速度没解出来） | 改之后（本地积分 + 慢对齐） |
|---|---|---|
| 单向传输 中位 / 最大 | 7 / 8 毫秒 | 7 / 8 毫秒（**网络这一段一直没问题**） |
| **晚看到 中位 / 最大** | **62 / 115 毫秒** | **14 / 55 毫秒** |
| 静止帧 / 反向帧 / 终点误差 | 0 / 0 / 0.49 | 0 / 0 / 0.54 |

⚠ 判"跳得大不"钉的不能是像素数：收端按速度自己积分后，一帧本来就该挪 `400 × 帧长` 像素，
引擎偶尔抖一下（起步那 40 像素的追赶）就到 8~10 像素。改成钉**"一帧不许挪过半个采样周期的量"**
= 400 像素/秒 × 0.05 秒 = **20 像素**（实测 7.83）。真"一格一格"是一整段 40 像素挤进一帧，一定越线。

### C.5 端到端的施法链（⑨′，不再靠手工喂文本）

## §D 出手广播的时机 + 攀爬那一层（#216 #217 #218，2026-10-14 用户第四次反馈）

用户原话：**"特效能看到了，但是……我从油女澪的视角看不到木叶忍者的技能特效，木叶忍者可以看到油女澪的；
攀爬动作显示不一致……停止攀爬后角色是站在攀爬物那里并不是攀爬动作；我让油女澪释放技能，但从木叶忍者
视角看技能特效延迟也很高！我个人角色 godot 肯定比 flash 流畅，为什么会这样？"**

答案：**是客户端接线的问题，不是平台性能。** 网络那一段实测 7 毫秒，两笔新账都记在客户端自己头上。

### D.1 投掷技的"出手广播"被上一轮的 #193 一起压到了命中帧（= 特效延迟高的真凶）

#193 为了让"弹到身上才掉血"，把 `request_skill_attack`（**一张 1328 广播 + 一张 42 结算**）
整个挪到飞行物命中那一帧。后果：**旁观者要等整段飞行（≈470 毫秒）才看到出手动画与起手特效**。
原版两件事本来就分在两个时刻：

| 帧 | 原版出处 | 该在哪一拍发 |
|---|---|---|
| **1328 广播**（动作+特效+授权） | `AbstractAttackSkill.hitTest():629` `API.client.requestPlayerAttackInfo(...)`；前面那个 switch 连"无目标"那档（`getSkillTarget()==2`，`:625`）都照样发 | **按下/放出这一拍，立刻**，**有没有目标都发** |
| **42 结算**（打中了谁） | 原版 PVE 伤害本来就是客户端在**命中帧**算的 | 飞行物落地那一拍 |

⇒ 拆成两个函数：`后端连接.announce_skill_cast()`（1328，空目标时目标槽写 `-`）与
`后端连接.request_skill_damage()`（42，空目标直接不发）。`玩家.gd` 在 `_出技能动作` +
`_spawn_skill_effect` 的**同一拍**调广播、命中回调里调结算。

### D.2 攀爬：层带要进"绳子那一层"，停下来不许一律回站立

| 症状 | 真值 | 原来错在哪 |
|---|---|---|
| 爬到一半图层不对 | `AbstractPhysicObject.tikcLayer` 给攀爬角色的是 **`getALayer(currLadderRope.page)`**（绳子自己那层，比地形高 ⇒ 不被梯子美术盖住）。本地玩家早就接了（`玩家.gd:1014-1019`） | `_远程角色层次()` 只按落脚点 y 算 ⇒ 爬着的人还在地形层里，被绳/梯美术压住或盖住 |
| 停在绳上变成"站在半空" | 原版收端**没有"超时算停"这一说**：movementAction 一设就一直挂着，本端停在绳上时也不再发包 | `_推进远程玩家()` 那条"0.45 秒没下一包 ⇒ 回站立"不分姿态 ⇒ 爬梯/爬绳/打坐（4/5/7）被强扭成 stand |

`动作 if 动作 in [4,5,7] else 1`（走/跳才回站立）。
