# 交付后自动再弹对话（#182，2026-10-11）

用户口径（2026-10-10 夜间清单第 3 条）：**「任务完成后如果 NPC 还有接下来的任务时会自动弹出对话框。
这个问题我知道你修复了，但是没修好，我测试了。」**

## ① 上一轮为什么"看着修好了"其实没修

服务端 `_complete_original_quest()` 当时挂着一个形参 **`show_dialog: bool = True`**，
函数体里**一次都没有读过它**，而三个调用点全写着 `show_dialog=False`：

| 调用点 | 旧写法 | 实情 |
|---|---|---|
| `_finish_original_quest_dialog()`（对话翻到最后一句落交付） | `show_dialog=False` | 死参数 —— 看着像"这里可以选要不要重开对话"，其实什么都没接 |
| 编辑器动作「完成任务」 | `show_dialog=False` | 同上 |
| 环任务瞬时完成 `COMPLETE_QUEST_LOOP` | `show_dialog=False` | 同上 |

⇒ 光看代码像已经实现了、跑门也照样绿（那时**根本没有门判这一段**），实际一条重推的包都没发出去。
本轮把形参删掉、改成 `-> bool` 由调用方决定重推，这条假象才没地方藏。

`qusetClickText(3, endNpcId)` ⇒ 走去交付 NPC ⇒ 到点 `KeyController.as:220-224` 自动开对话）
**解决的是"目标刚攒满、人还不在 NPC 跟前"**；本条解决的是"人就站在 NPC 跟前、交完之后"。
两支都在，缺任何一个都会在玩家眼里变成"要我自己再点一次"。

## ③ 落点

`服务端/runtime/tools/fake_flash_server.py`：

- `_complete_original_quest(...)` → `-> bool`：三条早退（交付 NPC 不对 / 状态不是可交付 / 背包放不下）
  返 `False`，走完发奖与解锁后继返 `True`。
- `_finish_original_quest_dialog()` 的交付那一支接住返回值：

```python
交付掉了 = self._complete_original_quest(definition, npc.template_id)
if 交付掉了:
    自动档 = npc.object_id == self.QUEST_NPC_OBJECT_ID
    if self._npc_quest_selections(npc, include_automatic=自动档) != "-":
        self._send_current_npc_dialog(npc, include_automatic=自动档)
```

两条口径要记住：
1. **只在「这枚 NPC 此刻确实还有任务行可说」时推** —— `_npc_quest_selections` 空集返回 `"-"`；
   链尾交完（下一条在别的 NPC，或压根没有下一条）不许弹一扇没有任务行的窗。
2. 重推走 `_send_current_npc_dialog`，**与玩家自己点 NPC 是同一个构造函数** ⇒ 帧同形
   （菜单段/任务行段一样），渲染那条路不需要重新证明。别在客户端另起一条"交完自己再点一次"。

`脚本/界面/小地图面板.gd` / `窗口/NPC对话窗.gd`：**一行都没改** —— 这两处本轮只需要证明
"收到就开窗、点完不自己补"，判据在门里钉着。

## ⑤ 没做/未验（如实）

- **没有**在跑起来的游戏里用眼睛看那扇窗自己弹开：在线用例跑的是无头 `SceneTree`（协议面）。
  窗会亮这件事的依据是"帧到了 + 消费端无条件开窗（静态门第 ④ 腿钉住）+ 与手动点 NPC 同一种帧（在线用例第 ⑥ 条判据）"，
  三者都不是截图证据。
- 交付**之后**那一次 `51 SHOW_QUEST_COMPLETION` 与提示条的相互关系没重查：
  本轮只在"对话翻完落交付"这一支加了重推；从任务面板点「完成任务」（`QUEST_ACTION 2`）那一支
  仍然不弹对话（门 M9 钉住"不许弹"），是否符合原版**没查到出处**，只按"原版那一条不经过对话"的架构事实处理。
- `show_dialog` 这个坑说明**别的死参数也可能存在**：全工程普查未做（可作后续）。
