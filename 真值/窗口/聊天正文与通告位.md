## 1. 原版聊天正文是 HTML，不是纯文本

| 环节 | 出处 | 事实 |
|---|---|---|
| 拼一行 | `com/mxw/uifl/controls/ChatPane.as:1674` | `ChatUtil.formatMessage(msgId, 频道, 频道名, 正文, 玩家名, 是否自己, 目标, tag, 类型)` |
| 存一条 | `ChatPane.as:1676-1683` | 记录形状 `{recordId, position, type, content, recordTag, playId, level}`（本工程 `_push_chat_message` 的 `record_id/position/channel/bbcode` 就是它的对应物） |
| 归页 | `ChatPane.as:1685-1700` | **按 `position` 一条只进一个数组**：`chatRecord1`=MISC、`chatRecord2`=GENERAL、3=WHISPER、4=PARTY、5=GUILD…（旧实现把「综合」当全频道合并，是自造的，已改回） |
| 上色 | `com/mxw/uifl/utils/ChatUtil.as:105/137` | `formatMessagePeiou` 与 `formatMessage` 自己就在拼 `<font color="#…">` ⇒ **返回值是 HTML 串** |
| 渲染 | `ChatPane.as:726 createMsgBox` → `com/mxw/uifl/base/controls/MTextSprite.as:74` | `set text` 里 `textField.htmlText = param1.replace(facePattern, replaceFace)`（`:83` 先拿一份量高度、`:93` 正式上屏） |

⇒ 结论：Flash 那边从来不需要"翻译"，`htmlText` 自己吃标签。Godot 的 `RichTextLabel` 吃 BBCode，
`<font color="#ffff00">` 在 BBCode 里**不是标签**（`<` 是普通字符），不过一遍就是整串原样上屏 —— 玩家
看到的就是 `font color = "ffff00" …` 这种残渣，还因为 `html.escape` 把 `#` 变成实体而更难看。

## 2. 服务端那条「写轮眼进阶」的逐字原文

文案在 `fake_flash_server.py:52917`：

```
f"{self.character.name}成功将【{cultivation_name}】进阶至{next_stage}阶！"
highlights = (玩家名, 修炼名, f"{next_stage}阶")
```

上色在 `fake_flash_server.py:40252 _rare_event_markup`（`@staticmethod`，`:40331 _broadcast_rare_event` 调用）：
外层无条件包 `<font color="#ffff00">`；`highlights` 命中段 **前一个字是 `【` 就粉 `#ff5498`、否则绿 `#00ff00`**；
`【…】` 整段粉；`第?\d+(阶|级|层|…)` 绿；作者指定的 `colored_values` 优先级最高（写轮眼品质色走这条）。
逐段实测（把 `:40252-40329` 原函数抠出来跑，夹具 `木叶英雄成功将【写轮眼】进阶至3阶！`）：

```
<font color="#ffff00"><font color="#00ff00">木叶英雄</font>成功将【<font color="#ff5498">写轮眼</font>】进阶至<font color="#00ff00">3阶</font>！</font>
```

过 `脚本/界面/富文本.gd:32 译文为BBCode` 之后（嵌套四层，栈式补闭标签）：

```
[color=#ffff00][color=#00ff00]木叶英雄[/color]成功将【[color=#ff5498]写轮眼[/color]】进阶至[color=#00ff00]3阶[/color]！[/color]
```

## 4. 本工程的做法与旧账

* `_正文(原文)` = `_parse_chat_faces(富文本.译文为BBCode(原文))`，是正文进聊天的**唯一一道口子**；
  三个入口都走它：`_format_chat_message` 的系统/公告支、普通频道支、`_on_notification`。
  原版顺序是「先换表情、再交给 htmlText」（`MTextSprite.as:93`），这边是「先翻译、后换表情」——
  等价，因为 `[fN]` 只由**本客户端输入链路**产生、服务端 HTML 里没有它；门里以字面钉住这个顺序。
* `_on_backend_chat` 只跳过 `512`（§3.204）与 `1`（本轮）。**旧账**：`1024`(DYNAMIC_INFO) 与 `2048`(COPY_NOTICE)
  仍未按 `UI.as` 分派到 `noticePnl` / `addMidMessageRed`，而是照样落进 `_chat_messages`（只是综合页按
  `position` 过滤 ⇒ 看不到）。要补的是那两块提示面板，不是在这里再多加一个 `return`。
* **旧账**：`addScrollAnnounce`（白字滚动条）、`NoticeMidWindow`（中部通告，含红/黄三个实例）、
  `selectInfoWindow`（信息查询窗）本工程都还没移植 ⇒ `1`/`2`/`2048` 那几路的"该显示出来的东西"目前是缺的。
  本轮只保证**不再往聊天记录里塞错的东西**，缺的面板另开任务做。
