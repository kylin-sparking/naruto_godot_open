# 真值：十拳剑/八咫镜「炼制」的**结果帧**谁在听（2081:0/1/2/3 + 2082:0）

> 触发点：用户 2026-10-25 报修（#71 4.1）「十全剑开光/灵化是不是没实装」。
> 结论：**发送半边一直是好的，回帧半边整条没人接** —— `OP_LING=2081` / `OP_RENJU=2082`
> 两条 opcode 在 `_handle_bridge_text` 里连分派臂都没有，点开光之后客户端只是安静地等。
> 证据根：`2.2.3/map_extract/out/mainlib_as/scripts/`（AS3）与 `2.2.3/tools/fake_flash_server.py`（帧序）。

## ① 分发处（`com/mxw/net/client/handlers/channel/LingEquipProcessor.as:70-99`）

| cmd | AS3 支 | 解码了什么（`readInt` 逐个） | 落到谁身上 |
|---|---|---|---|
| 0 | `onLingEquipKaiGuangResult` | 只有 `success` | `LingQiManager.onLingEquipKaiGuangResult:302-304` = **空函数** |
| 1 | `:25-58` | `success`、`plusSize`、`plusSize × (type,value)` | `onLingEquipLingHuaResult:260-277` |

## ② 两支成功语义**不一样**，这是整条门的核心

```as3
// LingQiManager.as:260-276 —— 灵化成功
if (param1 == 1) { this.plusAttr = 1; … _loc3_.plusAttrList = param2; updateCommonItems; updateInfo(); }
//                 :264                ↑ :266 写的是**字面量 1**，不是 param2[0].subArrtValue × 6
// LingQiManager.as:278-281
public function updatePlusAttr(param1:Array) : void { this.plusAttr = param1[0].subArrtValue * 6; }
//                                                                        ↑ :280
// LingQiManager.as:306-322 —— 洗炼成功
if (param1 == 1) { this.updatePlusAttr(param3); … }   // ← 只有这一支（:312）走 ×6
```

⇒ 同一件剑：灵化那一下把「洗炼效果：攻击 +6」**刷成 +1**；洗炼那一下才按第一条 ×6 往上走。
外层 `if(param1 == 1)` 把**失败帧整个吞掉** ⇒ 失败既不重刷也不提示。

## ③ 开光那枚钮的两族差异

| 族 | AS3 | 语义 |

⚠ 最后一行本工程**故意不照**：服务端 `_open_renju` / `_open_ling_qi` 成功后都会
`_send_inventory_clear(slot)` + `_send_inventory_add(item)` 重发那一格，`_render_ling_forge`

`setDOShow(false)` 在 AS3 只是 `removeChild`（窗口对象仍留在 `_windowMap`）⇒ **开光那枚 latch 不随开关窗复位**；
我们的窗在 `_窗口们` 里"只藏不删"，语义正好一致 ⇒ 开窗时不该顺手把 latch 清掉。
