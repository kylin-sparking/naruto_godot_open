# 真值：进度条 0.5 秒补间（`MBar.setData`）

> 报修 **#55**「进度条没有补间、数值一跳一跳」。结论：**原版确实有**，而且补的不是"宽度"、是
> **填充条的 x**；补间时长 **0.5 秒**、缓动 **二次缓出**（`-c·u·(u−2)+b`）。
> 全部证据在 `2.2.3/map_extract/out/mainlib_as/scripts/` 下，行号按当前反编译文件。

## ① 唯一的补间点：`uifl/base/controls/MBar.as:170`

```as3
170:  TweenLite.to(this.bar, 0.5, {"x": _loc5_});
```

`MBar extends Sprite`（`:10`）—— **不是** `MComponent` 的子类，所以 `MComponent.removeMovieClip`
那套"换页时杀补间"的自动清理**管不到它**（`gs/TweenLite.as:26` 只是把 `killDelayedCallsTo`
指向 `killTweensOf`，不是自动触发）。⇒ 补间对象只有两种归宿：**被下一次 `setData` 覆盖**、
或随 DisplayObject 一起 GC。移植时对应的是"同一根条上新 Tween 必须 `kill()` 掉旧 Tween"。

## ② `setData` 的完整语义（`MBar.as:128-175`，逐条）

| 步 | AS3 | 语义 | 移植必须照做的点 |
|---|---|---|---|
| 0 | `:130-133` `if (cur==_current && tot==_total) return;` | **同数据整条早退** | 重复渲染**不许**重启补间（否则挂机每帧刷一次 ⇒ 条永远在动、数字却不动） |
| 1 | `:134-137` `if (cur > tot) cur = tot;` | 超上限**夹到上限** | 夹完才写进 `_current`（下一步的比例用夹过的值） |
| 2 | `:138-139` `_current = cur; _total = tot;` | 缓存**入的是夹过的值** | 早退判定比较的是夹过的 |
| 3 | `:140-149` `_isShowBar ? (tot>0 ? cur/tot : 1) : (tot>0 ? cur/tot : 0)` | **上限 0 ⇒ 满条**（默认 `_isShowBar = true`，`:19`） | 只有 `GuwanshoujiInfoPanel.as:82` 一处关掉；本工程三条面板**全是满条口径** |
| 4 | `:150` `_loc5_ = barBg.x + (barBg.width - bar.width >> 1) - int(bar.width * (1 - 比例))` | **动的就是 x**，宽度恒定；`int()` 是**向零截断** | 不是 `width = 比例×槽宽`；填充条和槽同宽、靠 x 滑进遮罩 |
| 5 | `:151-168` 文案三分支（见 §③） | 文案**立即**写，只有条补间 | 数字不许跟着条爬 |
| 6 | `:170` 补间 | 0.5s 二次缓出 | 见 §④ |
| 7 | `:171-174` 有 tooltip 就刷一次文字 | — | 本工程走 `人物窗口._挂文字提示` 那条链，不归本件管 |

⚠️ `param3`（第三个入参）非空时**直接当文案**用（`:152-155`），既不算百分比、也不算 `x/y`。

## ③ 文案三分支（`:151-168`）——`?/?` 那条有个反直觉的口子

```as3
if (this.tf) {                                   // 条上没有 TextField ⇒ 整段跳过（含 ?/? 早退）
   if (param3)                 tf.text = param3;                    // 显式文案优先
   else if (!this._showPercent) {
      if (param1 == -1 || param2 == -1) { tf.text = "?/?"; return; } // ← 早退在 tf 块里
      tf.text = param1 + "/" + param2;
   }
   else tf.text = Math.round(Number(_loc4_.toFixed(2)) * 100) + "%"; // 百分比：先两位四舍五入再取整
   TweenLite.to(bar, 0.5, {"x": _loc5_});                            // :170
}
```

三条容易踩的：

1. **`?/?` 的早退在 `tf` 分支内部** ⇒ `showPercent = true` 的条**走不到** `?/?`。
   `SkillDetailPane.as:128-129` 就是 `showPercent = true` + `setData(-1, -1)`：
   `-1 > -1` 不夹；`_total = -1`；`tot > 0` 假 ⇒ `_isShowBar` 默认真 ⇒ **比例按 1**；
   于是文案 = `100%`、条**补间到满**。原版紧接着 `:214 practiseBar.visible = false` 把它藏了，
   所以实机看不见 —— 但语义是"满条"，不是"空条"。移植若照抄这一发**必须连隐藏一起照抄**。
2. `?/?` 早退**发生在写文案之后、补间之前** ⇒ 条停在**上一次的位置**（不是清零）。
3. 百分比口径是 `Math.round(Number(比例.toFixed(2)) * 100)`：**先截两位再四舍五入**，
   和 `round(比例×100)` 在 `0.9949…` 这类值上**会差 1**。

## ④ 缓动曲线：`gs/TweenLite.as`

* `:28` `public static var defaultEase:Function = TweenLite.easeOut;`（所有不写 `ease` 的 `to()` 都用它）
* `:199-202` `easeOut(t, b, c, d) = -c * (u = t/d) * (u - 2) + b`，即 `b + c·(2u − u²)` ⇒ **二次缓出**
  （Godot 等价：`Tween.TRANS_QUAD` + `Tween.EASE_OUT`，`tween_property(..., 0.5)` 缺省就是这两个）。
* `:95-117` **overwrite 缺省 = 1**（`:154-158` `overwriteManager = {mode:1, enabled:false}`，
  而入参没写 `overwrite` ⇒ `_loc4_ = mode = 1`）：新 Tween **杀掉同一 target 上的全部旧 Tween**，
  并从**当前视觉位置**重新起算 0.5 秒。移植 ⇒ 每根条自己记着上一支 Tween 并 `kill()`。

## ⑤b 文案一律按**数据**算，不许读 `条.value`

§② 第 5 步：`MBar` 先写文案（`:151-168`）、后挂补间（`:170`）⇒ **数字立刻到终值、条慢慢爬**。
本轮**改前**有两处在读条子自己（现在都按灌进去的数据算，并由 `进度条补间回归测试` C-3 负闸钉住）：

* 经验/精华百分比 —— 改前 `100.0 × 经验条.value / 经验条.max_value`，改后 `人物窗口.gd:322-323`
  走 `进度条补间.比例(经验数, 经验上限)`；
* 祝福那行 `%d/%d` —— 改前 `int(祝福条.value)`，改后 `人物窗口.gd:2155` 先 `clampi` 出 `祝福`，
  文案与 `灌值()`（`:2156`）用的是同一个变量。

改前"直给"看不出来，接了补间就是**数字跟着条爬**（正是 §② 第 5 步的反面）⇒ 两处都改成按灌进去的数算。

## ⑥ **另一条曲线**：底栏自己血/蓝 = `MMaskSprite`（`CharactorInfoPane.as:80/96`）

全代码库只有这两枚用 `MMaskSprite`（`grep ":MMaskSprite"` ⇒ 仅 `CharactorInfoPane`）。
它**不走 TweenLite**，是**自己挂 tick 逐帧线性插值**：

* `MMaskSprite.as:41` `maxTime = 500`（毫秒）⇒ **也是半秒**；
* `:59-67 set percent(v)`：`_curPercent = _percent`（**从当前渲染值重新起算**，与 §④ overwrite=1 同效）、
  `_dis = v − _percent`、`_overTime = getTimer()`、重新 `addTick`；
* `:158-169 tick(elapsed)`：`_percent = _curPercent + _dis × (经过/maxTime)`，到点**收敛到终值并摘 tick**
  ⇒ **线性**，没有缓出；
* `:83-126 drawMask()`：遮罩宽 = `_percent × width / 100`（`percent` 单位是 **0..100**，不是 0..1），
  方向按 `direction`（默认 `LEFT`）；`isNaN(_percent)` 直接不画。
* ⇒ 移植：这两枚走 **0.5s 线性**，不许套 MBar 的二次缓出；底栏那两枚的"上限 0"没有原版语义
  （原版是 `percent = hp×100/max`，`max = 0` 时是 `NaN` ⇒ `drawMask` 早退、条**停在原位**），
  本工程底栏用 `maxf(1.0, max_hp)` ⇒ 按 0 画空。两处都保留现状，只补"动起来"。

## ⑨ 移植口径（已落地，`脚本/单例/进度条补间.gd`）

`extends RefCounted` 静态件，同 `套装提示.gd` 的形状。**全部 19 处调用点见 §⑧ 的号**。

口径三个：
* `夹过(当前, 上限)` = §②第 1+2 步（注意 `(-1,-1)` **不夹**，原版比的是 `>`）；
* `比例(当前, 上限, 上限零当满 := true)` = §②第 3 步 —— 默认跟原版 `_isShowBar`（**上限 0 ⇒ 满条**），
  传 `false` 才是空条（`GuwanshoujiInfoPanel.as:82` 那一档 + 本工程两处已登记偏离）；
* `滑条终位(槽宽, 比例值, 静止位)` = `MBar.as:150` 的 `起点 − int(槽宽 × (1 − 比例))`（`floorf` 只在正数区间与 `int()` 等价）。

动作四个：
* `补间(目标, 属性, 终值, 数据)` —— 0.5s `TRANS_QUAD` + `EASE_OUT`；
* `线性补间(…)` —— 同一条口子、`TRANS_LINEAR`（`MMaskSprite` 那两枚专用）；
* `灌值(条, 当前, 上限, 数据)` —— `value` 型一次灌完：`max_value = maxf(1.0, 上限)` 直给、
  填充走 `补间()`，终值取**夹过的当前值**而不是 `比例 × 上限`（后者在 `58/62` 这种数上写成 57.999…，
  门里 `int(条.value)` 一比就差 1）；
* `直写(目标, 属性, 终值)` —— **不动条**的那几档用：写完把 §②第 0 步的缓存**作废**并杀掉还在跑的补间。
  ⚠ 直接 `条.value =` 会留**半缓存** ⇒ 下一次同样的数据被早退吞掉 ⇒ 条永远停在手动值。

两者共有的语义：**同数据整条早退** + **新补间 kill 旧补间**（§④ overwrite=1）+ **从当前视觉位置重新起算**。
缓存挂在条自己的 meta 上，键名 `tweenBar` / `tweenBarData`。

⚠️ **键名必须以字母开头**（本轮第一条红）：`Node.set_meta()` 先用 `String::is_valid_identifier` 校验，
中文或 `_` 开头一律 `ERROR: Invalid metadata identifier`，而 **error 不打断执行** ⇒
症状是"缓存根本没存进去"：每帧重启补间、条永远在爬、数字不动，**控制台刷 error 但门可能还是绿的**。
⇒ 门里除了行为腿，另钉一条字面闸（`进度条补间回归测试` B-④）。

* **不在件里管文案**：各点文案早已有自己的分支（百分比 / `x/y` / `?/?`）并且各有已登记的偏离
  （如目标条"上限 0 画空条"是**有意偏离**，记在 `真值/窗口/目标信息条.md`）。
  ⇒ 件只保证**比例与补间**一致，文案留在调用点，但**一律按数据算、不许读 `条.value`**
  （否则数字会跟着补间爬，那是 §②第 5 步的反面）。
