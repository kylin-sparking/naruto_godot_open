## ⓪ 五条会影响整页的先决口径

**① 六扇全是 `内容底: false`**：`UIWindow.as:28-44` 只在第三参 true 时才画 `_contentBg`，
而这六个构造**都没传第三参** ⇒ 宿主不画底，页里自己 `new MYellow_background()`（底2）
+ `new MPane_background()`（底3，修改窗还有底4）。所以 `窗口尺寸.json` 那六条**不许**写 `内容底: true`。

**② `background` = 整幅外框，不是内容区**（`UIWindow.as:30/59-60`：`background = MWindow_background`、
`drawWindowLayout` 把它的宽高直接设成 `_width/_height`）⇒ 类里 `background.width − 12`
代的是**外框宽 − 12**（说明窗 372、一格 258、三格 303），不是 `宽−16`。

**③ 页局部坐标 = AS3 外框坐标 − (0, 29)**（`整框: true` 那一支，容器原点 (0, 拖动区高 29)）。
页面根尺寸 = `宽 × (高 − 29)`：384×353 / 270×311 / 270×311 / 315×311 / 315×315 / 270×196。
⚠ **不许写 `原点`**（口径同 神秘商店/摊位列表）。

**④ 钮宽三档 + 钮高 22**：`btn_width_two = 37`（`UIConfig.as:964`）、`three = 49`（`:966`）、
`four = 61`（`:968`）；`MButtonF` 的 22 高是 `isScale9Grid = false` 时的原生高，

## ① 协议：2309 收/发同号，**两处有意偏离 AS3**

opcode `SECOND_LEVEL_PASSWORD = 2309`（`SendOpCodes`/`ReceiveOpCodes` 两侧同号）。

**上行（本工程两处偏离之一）**：AS3 是 `PacketCreator.getEmptyPacket()` 里
`writeByte(action)` + `writeUTF(...)` 的**二进制**（`SecondLevelPasswordProcessor.as:18-200`），
而本工程走全工程统一的 AMF3 桥：`readStr = JSON.stringify({"action":N,"values":[字符串...]})`，
`后端连接.request_second_password(动作, 值)`（`脚本/单例/后端连接.gd:1700`）。
服务端**两头都认**：`fake_flash_server.py:12418-12442` 把真客户端那串二进制解成同一个 JSON，
`handle_second_level_password:22001-22012` 读的也就是这个 JSON ⇒ 上行动作号是**共用**的。

| 上行动作 | AS3 方法 | values（顺序照 `writeUTF` 的序） |
|---|---|---|
| 0 | `queryFirstTime:195-200` | 空 |
| 1 | `addPasswordFirstTime:18-25` | 密码、确认密码 |
| 2 | `sendContactInfo:45-53` | 邮箱、手机、QQ |
| 3 | `sendQuestionsAndAnswers:27-36` | 问题1、答案1、问题2、答案2 |
| 4 | `sendConformQA:136-145` | 问题1、答案1、问题2、答案2 |
| 5 | `requestDeletePassword:280-285` | 空 |
| 6 | `conformDeletePassword:115-124` | 问题1、答案1、问题2、答案2 |
| 7 | `modifyPassword:126-134` | 旧密码、新密码、确认新密码 |
| 8 | `releaseLock:168-174` | 密码 |
| 9 | `requestModifyPassword:38-43` | 空 |

`values` 里**每一个元素都是串**（AS3 十根 `writeUTF` 一根 `writeInt` 都没有），
端口 `request_second_password` 用 `str(v)` 而不是 `String(v)` 做这层转换：
Godot 4 的 `String(7)` 是**无效构造**（运行期 `Invalid call 'String' constructor` ⇒ 整条上行
静默不发，页面还照着"已发送"那半边刷，比报错更难查）。服务端那边同样是
`values = [str(v) for v in raw_values]`（`fake_flash_server.py:21992`），长度校验读的是**十进制位数**。

**下行（第二处偏离）**：帧体第一个字节是**下行动作号**，和上行那套号**不是一回事**。
AS3 用 `readUnsignedByte` + `readUTF` + `readInt`（Flash 全是**大端**），
而烘这一帧的是本工程服务端 `_send_second_level_password_response:21964-21987`：
`struct.pack("<B")`、`struct.pack("<i")`、`_original_utf = struct.pack("<H", 长) + UTF-8`（`:13263-13269`）
⇒ **全帧小端**。解码器 `后端连接._decode_second_password` 按小端读，且**以服务端为准**
（照 AS3 改成大端就连不上服务端了）。`二级密码下行形状` 那张表逐条对着
`handleAction:310-358` 的 switch 与各个 `action_*` 的读序：

## ④ 草稿 vs 服务端数：两份账不许混

`TwoPasswordManager` 那 12 个静态字段分两类，端口也照分：

* **服务端推进来的**（`类型/修改次数/删除次数/已解锁`）⇒ `后端连接.authoritative_second_password`，
  断线复位。窗口自己**不存副本**。
* **玩家打了一半的草稿**（`mail_Text/handset_Text/qq_Text/problem1/problem2/result1/result2`）
  ⇒ `二级密码窗.gd` 的 `static var 草稿`（跨六扇窗、跨窗实例、**不随断线清**）。
  `isSetPasswordType/updateCount/deleteCount/isunchainLook` 在这份里**一律不出现** —— 那是上一类的镜像，
  存两份迟早和回帧打架（工程既有口径）。
* **死字段四条**，端口不接：`twoPassword`（`:57` 写完**全库再没人读**）、
  `qqRegExp` / `cnRegExp`（`TwoPasswordManager.as:20-22`，声明了没人用）、
  `maxChar_result/minChars/maxChars` 是**常量**不是草稿（40/6/14，端口当常量抄）。

## ⑤ 已知缺口（写了就不算漏）

1. 入口那句 `if (!UIConfig.isEnableDrag) return`（`ItemWindow2.as:724`）——`isEnableDrag` 是全局
