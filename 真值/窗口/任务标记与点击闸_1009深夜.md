## 修复一：NPC 头顶任务标记不点不出现、接了任务不消失
根因：**服务端推 513 只写表、没人发信号**。`后端连接._handle_npc_quest_status_text` 原来只
`npc_quest_status[号]=值`；头顶那枚只有「NPC 生成时」(`地图实体.gd:997-998`) 与「点过一次之后」
两个计算时机 ⇒ 进图时状态包晚到 / 交付后重推，头顶都不动。小地图那边有 0.5 秒轮询兜着，
所以只有头顶错（与用户描述完全一致，也是"两头各刷各的"的又一实例）。
修：新增 `signal npc_quest_status_updated(object_id,status)`，**值真变才发**（进图那批几十枚
不该各全场重挂）；`地图实体._connect_backend_signals` 里
`_backend.npc_quest_status_updated.connect(_refresh_quest_markers.unbind(2))`。
真值：`NPCHandler.as:133-140 updateQuestStatusPacket` 收到就同时 `NPC.setQuestStatus()` +
`SmallMapHandler.setNpcStatus()`。

## 修复二：点 NPC 不限距离
真值 `NPC.as:111-114`：`canPlayerTalkToMe() = abs(player.x-x)<100 && abs(player.y-y)<50`
—— **两轴分别判，不是欧氏距离**（横 100 纵 50 是斜 45° 地面投影；`MarryTable.as:117` 同式）。
`NPC.as:52-65 globalClick()`：够近才 talkToNPC + `requestNPCTalk`(54) + `directionNPC`；
不够近只 `pathFind(x, y-5, skin, false)` —— 第 3 参存进 `KeyController.movingtoLifeId`(:1032)，
走完关节那一帧反查 object_id 再发对话(:211-227) ⇒ **远处点 NPC = 先自动走过去、到点自己弹对话**，
且 `showtip=false` ⇒ 这一种不亮「自动寻路中」。
修在 `地图实体._on_npc_input` 分远近两支 + `_能对话()` + `_走过去找NPC()`（交给 HUD 那份
`_待对话NPC`，与点任务赶路**同一条路**不分两套）；`_走向NPC/前往NPC` 加 `显示提示` 形参（默认 true）。
未做：`directionNPC`（说话时 NPC 转身朝向玩家）= 任务 #153；原版 `y-5` 那 5px 没照搬（同一落脚点）。

## 修复三：点任务绿字没反应（根因是数据形状）
在线那两条列表 **只带 id 与状态**：`444:3` 条目=`id&状态&目标类型&数据&环id&-&次数`、`444:4` 只有 id
（`后端连接.gd:1637-1666`）。NPC 编号要按 id 从 `数据/任务.json` 的 `npc={"0":接取,"1":回复}` 合并 ——
原版同一口径（`QuestTrackerItemRenderer.as:122-125` 用 `quest.npcId`；服务端
`fake_flash_server.py:7760-7761` `start_npc_id=npc.get("0")`/`end_npc_id=npc.get("1")`）。
以前算出 0 ⇒ `_找NPC链接(0)` 拼**空串** ⇒ 那一行根本没有可点的东西，不报错不提示。
修：`_追踪接取NPC/_追踪回复NPC/_任务目标NPC` 三处回落定义表；`_走向NPC` 不再忽略 `走向()` 返回值。
⚠ `npc.0==0` 的任务（如 1003）本来就没接取 NPC ⇒ **不给链接才是对的**，门里钉成判据。

## 修复四：空号被当成"有一枚空角色"
`{"jylx":10,"maxChars":1}`（没角色）以前被无条件 append ⇒ 列表长度 1、内容全空、编号 0 ⇒
`select_character(0)` 第一行 return ⇒ 界面永远停在「正在读取角色」，既不报错也不提示。

`_set_status("需要创建角色","这个账号还没有角色")` 并 return。
