## ⑨ 三条协议面（这才是"点它有反应"的那三行）

### `1283` 角色配置（`ClientOpcode.CHAR_CONFIG`，服务端 `fake_flash_server.py:17897`）

* **查询**：`readStr = "0:<毫秒时间戳>"` —— 载荷**只有一个 0**。
  服务端 `_strip_timestamp` 之后判 `payload == "0"` ⇒ 走 `_send_char_config()` 回一帧。
* **保存**：`readStr = "<整个 JSON>:<毫秒时间戳>"` —— **不带 opcode、不带 action 位**。
  服务端把剥掉时间戳后的整串 `json.loads`，逐键覆盖 `store.state.character_config` 再落存档。
  ⇒ 多发一个 `1283:` 头：查询不再等于 `"0"`、`json.loads("1283:1:{…}")` 抛错被 except 吞掉
  ⇒ **一条回帧都没有、也不报错**。这是本轮最容易踩空的一处，已在
  `后端协议回归测试.gd` 里用「载荷就一个 0」钉住。
* **回帧**：`1283:v1:…:v45:keyData:v46:…:v58` = **60 段、段里没有键名**。
  顺序 = 服务端 `CHAR_CONFIG_FIELDS`（45，`:2658`）→ `keyData` → `CHAR_CONFIG_EXTENDED_FIELDS`（13，`:2675`）。
  值形态：bool → `"true"/"false"`、None → `"0"`、其余 `str(值)`（`_format_config_value:17937`）。
  `keyData` 是 `key&action&position&type` 用 `@` 连（空 = `-`）⇒ 那是**快捷键页**的数据，本门按位跳过。
* 保存时**故意不发 `keyData`**：服务端拿它整张替换 keymap（`:17932-17934` 注释写明），
  跟着发就会把玩家的快捷键表清空。
* `autoSellPickedEquip` / `autoUpgradeSkill` / `unlimitedAutoBattleTime` **不在那 45 个键里**
  ⇒ 发出去会被 `supported_names` 过滤掉、回帧里也没有（原版本来也不靠 1283 存这三样）。
  照 `CharacterConfig.as:211` 的快照一起发是"记录"，别指望它回来。

### `7779` 自动出售（`:786`，服务端 `handle_auto_sell_config:27093`）

`readStr = "<flags>:<maxLevel>:<jobIndex>:<maxQuality>:<ts>"`，flags 位掩码算式**一字不差**照 `:551`：
`enabled?1 | ingredients?2 | fragments?4 | books?8`。
服务端存进同一张 `character_config`、把下一轮 5 秒巡检提前、并 `_send_system_chat`
「自动出售已开启/已关闭」⇒ **点完在聊天栏看得见**。
⚠ 原版第 3 个整数是 `autoSellJobIndex`（下拉**序号** 0..4），服务端按 `& 0x0F` 当**位掩码**用
（`AUTO_SELL_JOB_CODE_BY_MASK = {1:100,2:200,4:300,8:400}`）⇒ 这是服务端的解释口径，
客户端照 AS3 发序号（不改成"猜服务端想要什么"），差异记在这儿。

### `1808` 起/停挂机（`:745`，服务端 `handle_hang_action:18326`）

`0` = 起、`1` = 停。**整族没有下行**：
原版 `stopGuaJi:735-739` 只派发一个本地 `GuaJiEvent.STOP_GUAJI`，`startGuaJi` 也不等回帧；
服务端只把 `self.hang_active` 记一下。
⇒ 原先那条 `request_hang_state()` 发 `"2"` 是**自造的**：服务端既不认也不回，
而 `副本挂机真实回归测试.gd` 照着它去 `await` 一条永远不来的回帧 ⇒ 那三句
「服务端没有确认开始/停止挂机」是**门写错了**，不是服务端坏了。本轮删掉 `"2"`，
把这条在线腿改成用 **1283「写进去再查回来」**当持久化证据（见 ⑯）。

### 一、挑目标那道闸问错了标志（= 上下抖动的正解）

| | 出处 | 内容 |
|---|---|---|
| 原版 | `GuajiHandler.as:729` | 进"空闲大块"的前提是 `!player.isGPathFinding() && !targetHandler.toAttackAnemy && movementAction ∈ {STAND,SIT0,LADDER,ROPE}` |
| 原版 | `Character.as:1645-1648` | `isGPathFinding() = nowInLadderToPathFind \|\| isPathFinding()` |
| 原版 | `Character.as:444-451` + `KeyController.as:1685-1688` | `isPathFinding() = _nowPathFinding \|\| _tempJumpLadderPathObj != null`（后者就是"人在空中/爬梯时先把这条路线记下来，等落到稳定地面再重排"那枚暂存）|
| 原版 | `KeyController.as:1083-1086` + `:1102-1107` | `nowInLadderToPathFind` 为真时**不重排**；等 `STAND && currFoothold && grounded && landed` 才把暂存那条重放出去 |

⇒ 原版的口径是"**身上还挂着路线（含爬梯未完成的那条）就一律不重新点目标、不再发寻路**"。
`LADDER/ROPE` 之所以还在动作表里，是因为它跟 `!isGPathFinding()` **成对**出现（人手动爬上去停住、
手里没有路线时才会重新挑）。

本工程那道闸写的是 `_寻路中()` = `_玩家.自动寻路中` —— 那是**屏幕顶部「自动寻路中．．．」那行提示
的开关**，只有 `走向(..., 自动=true)`（任务赶路、小地图）才点亮，而挂机自己发的
`走向(落点, true, false)` 是 `自动=false` ⇒ **这道闸对挂机自己的路线永远是开的**。后果链：
人在梯子上每一拍重新点目标 → 重新发 `走向()` → 而 `玩家.gd:230-231` 里
`click_climb_direction = 1.0 if 目标.y > position.y else -1.0` 是**按当下目标的 y 现算**的 ⇒
目标在"下层掉落物"和"上层怪"之间来回换 ⇒ 竖直方向来回翻 = 用户看到的"上下上下"。
"只有怪稍微远一点才正常"也对得上：远到掉出活动区矩形，两股力就不抢了。

现改成 `_在赶路线()` = `click_move_active || 自动爬梯中`（`_寻路中()` 这个函数已删，
它照不到任何东西，留着只会让人再拿它当闸）。同一道闸还补在 `移动方向()`（原来只挡 `climbing`）

### 三、原版那条"拾取排队、每帧吞一枚"（同日深夜已照做，不是待办）

原版拾取不是当场逐枚发帧，是**排一条队列每帧吞一枚**：`pickDropItem():1219-1227` 只
`_toPickItems.push(那枚)` + 注册 ENTER_FRAME；`onEnterFrame():1103-1115` 每帧
`pickDropItem(shift())` 之后**立刻 `refreshPickTime()`**（`DropItemHandler.as:94-97` 把
`pickitemTimeLimit` 归 0）⇒ 队列按**每帧一枚**排空，200ms 那个全局节流等于挡不到它
（单枚 `LOCK_PICK_UP=5000ms` 照旧生效，防重复发）。

本工程补成同一形状：`挂机托管.拾取队列` + `排队拾取(号)`（两支"够得着"的路径都改成只排队，
`拾取发过` 仍在**排队那一刻**记下，在线腿那条"说要捡的最后必须从地上消失"照旧成立），
`拍()` 的**开头**调 `_吞一枚拾取()` 吞一枚，走 `LifeRoot.发拾取(号, false)` = 绕开那份 200ms 节流
（等价原版那句 `refreshPickTime()`）。吞这一句放在 `拍()` 一切早退**之前**：预热中、没在挂、
按着移动键、死了都照样排空 —— 与原版那条监听器独立于 `tick` 一致。
**唯一一处与原版不同**：原版监听器挂在 stage 上，停挂机后仍会把剩下的排完；本工程停挂机就没人再调
`拍()` ⇒ `_清目标与寻路()` 里直接 `拾取队列.clear()`，免得把上一场的掉落号带进下一次开挂。

改之前的样子：同一拍把所有够得着的挨个 `发拾取`，被 `_拾取闸` 挡成只发第一枚 ⇒ 实际**每秒约 5 枚**
（原版约每秒 60 枚）⇒ "一地东西清得很慢"这一条是真的，用户看到的"拾取很慢/东西留在地上"有它一份。

门：`壬·①` 与 `壬·④` 各加一条"先看见它进了队列"，`戌·⑧` 钉"连吞三拍要真发出三枚"
（被节流挡住就只发得出 1 枚）。变异 **癸**（`false`→`true`，吞的时候还走节流）与
**癸乙**（把 `拍()` 开头那句吞摘掉）各点名一条红 ⇒ 本轮变异合计 **11 档抓到 11 档**。
