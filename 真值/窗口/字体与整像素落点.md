# 真值：字号 12 与整像素落点（「字发虚」这一族的两条根）

> 报修 **1.1 / 1.2 / 1.3 / 1.4 / 1.5**（2026-10-22，用户实机）。五处的病灶**不是同一个**：
> 1.1 是**整扇窗压在半像素上**，1.2/1.3/1.5 是**字号低于宋体内嵌点阵的下限**，
> 1.4 字号字体落点全对、真正缺陷是**容器往左溢出被裁**。
> 全部证据在 `2.2.3/map_extract/out/mainlib_as/scripts/` 下，行号按当前反编译文件。
> 钉住它们的门：`测试/字体清晰回归测试.gd`（37 判，离线门清单里登记）。

## ① 字号真值 = **12**，而且有三条独立出处

| 出处 | AS3 原文 | 说明 |
|---|---|---|
| `uifl/base/controls/MLabel.as:219` | `this._textFormat.size = 12;` | 本工程所有 `MLabel` 类文字件走这条 |
| `uifl/base/controls/MCountDownTimeLabel.as:116` | `_loc1_.size = 12;`（`init()` 里新建 `TextFormat`） | 倒计时（1.5）走这条 |
| `uifl/controls/TreasureBoxWindow.as:270` / `:277` | `sayTf = new TextField();` / `xunBaoLiuchengTf = new TextField();` | **裸 `new TextField()`、不建 TextFormat** ⇒ 吃 Flash 默认 TextFormat 的 12（亲热天堂两枚说明，1.2） |

第三条容易漏：**没写 ≠ 没有**。AS3 里 `TextField` 的默认 `TextFormat.size` 就是 12，
所以"原版没设字号"的地方恰恰等于 12，**不能**当成"原版没规定、我们自己小一点也行"。

## ② 为什么 10/11px 会发虚：宋体的内嵌点阵只在 **12px** 起存在

`素材/界面/simsun_原版.ttf` 内嵌了 12px 的 **bitmap strikes**（点阵）。字号一旦低于 12，
点阵用不上 ⇒ 退回**轮廓 + 灰度 AA** 渲染 ⇒ 中文小笔画糊成一团。这就是
`开发记录（本地） §3.55.3` 与 §3.184 / §3.191 那张点阵表的直接后果，
不是"字体没加载"、不是"没开抗锯齿"，**改字体文件、改过滤方式都治不了**，只能把字号提回 12。

⇒ 判据口径：**任何正文/标签字号 ≥ 12**。低于 12 的既有例外只有 `场景/界面/窗口/设置/快捷键窗.tscn`
的 **86 处 11px**（生成器 `开发工具/生成快捷键窗.py` 里对应 1 处）—— 早期已判定"不动"，
理由：那是键位对照表、密集排版是刻意的。本文件把它登记为**唯一已知例外**。

## ③ 行高真值 = `textHeight + 4` = **19**

```as3
MCountDownTimeLabel.as:132   this.timeTf.height = this.timeTf.textHeight + 4;
```

Flash 里 12px 宋体 `textHeight` = 15 ⇒ **一行 19**。这条在原版里有第二次独立成立：
追踪页签高 19 = 15 + 4。⇒ `脚本/界面/系统消息.gd` 的 `行高 := 19.0`。

⚠️ 旧值 `10/11` 是**拟合值**，不是真值：它的注释引用
`测试/基线/原版界面/原版_系统消息.png`，而**该 PNG 在仓里不存在**（那个目录 48 个文件里没有它）。
拟合的来源是"13 行要塞进约 120 屏高"，属于**为了塞下而牺牲真值** —— 12px 字塞进 11px 行距会**叠字**。

## ④ 落点必须踩在**整像素**上：原版的居中公式自带截整

```as3
MWindow.as:357/366           y = Math.round(param2 ? Config.STAGE_HEIGHT - height >> 1 : y);
                             x = Math.round(param1 ? Config.STAGE_WIDTH - width >> 1 : x);
PopUpMananger.as:137-142     param1.x = Math.round(Config.STAGE_WIDTH - param1.width >> 1);
UI.as:740-741                _loc1_.x = Config.STAGE_WIDTH - _loc1_.width >> 1;
```

关键在**运算符优先级**：`-` 比 `>>` 先算，`(960 - 275) >> 1 = 342` —— **移位自己就把结果截成整数**。
⇒ **原版不存在半像素窗口**，无论尺寸是奇是偶。

这边旧写法是 `offset_left = -宽 * 0.5`。`数据/界面/窗口尺寸.json` 的 74 条可解析尺寸里
**43 条是奇数宽或高**（人物 517×440、背包 275×394、组队 515×432、好友 295×370、家族 617×390…），
奇数尺寸折半 ⇒ 落点 `.5` ⇒ **整扇窗（含标题白字、含窗里所有文字）被画在 .5 网格上**。
这和 §② 是两种不同的糊：§② 是"没有点阵可用"，§④ 是"有点阵，但位图被整块重采样"。

### 反算式（`脚本/界面/功能窗口.gd` 的 `_居中偏移`）

Godot 侧要保留"视口改了大小还跟着回中"的锚点写法，所以偏移不能直接写整数，要按父尺寸反算：

```
offset_left = floorf((父 − 子) * 0.5) − 父 * 0.5
```

**偏移本身可以带 .5**（父为奇数时必然带），但落点 = `0.5*父 + 偏移`，
两个 .5 互相抵消 ⇒ **落点仍是整数**：`961/275 ⇒ 偏移 −137.5、落点 343`。

⚠️ `subpixel_positioning = 0` **管不了这件事**：它只管字形推进，管不住 Control 的小数全局位置
（canvas transform 照样重采样）。

### 另外两个会把窗推到 .5 的入口（同源，都要收整）

| 入口 | 旧写法 | 收整 |
|---|---|---|
| 拖动标题栏 `_on_title_input` | `event.global_position − _drag_offset`（浮点） | `.round()`。原版 `DragManager` 给的 stage 鼠标坐标**本来就是整数** |
| 视口改尺寸 `_resize_overlay` | 只改覆盖层大小 | 把 `global_position` 收整（只收当前位置，**不重新回中** —— 用户拖到哪还在哪） |

## ⑤ 1.4：字号字体落点全对，缺陷是**容器左溢被裁**

原版 `_contentPanel.width = 170` 是**定宽**，Flash 的 `x` 是**绝对摆放** —— 子件变宽**不会**让父容器平移。
这边 `任务列表`（VBox）在 `anchors_preset = 10` + `grow_horizontal = BOTH` 下，
某行正文有**断不开的词**（如 `寻找：[终结谷浅滩]暗部忍者-`）时最小宽超过 170，溢出量**被对半分**
⇒ 整列左移出父节点 ⇒ 被 `clip_contents` 削掉左边 **14px**（实测 771 vs 父左沿 785）。
⇒ `grow_horizontal = 1`（`GROW_END`）：**只往右溢**，和原版同形。

## ⑥ 本轮明确**不动**的（属别的账，不属"发虚"）

1. `快捷键窗口` 91 处 11px —— 见 §② 的例外登记。
2. 尾兽来袭列的**颜色**：AS3 `65280`（`MCountDownTimeLabel.as:115`）/ `UI_BLUE` vs 我们 `#00ff5a`。
3. **半角冒号**：AS3 超时分支是全角 `：`（`MCountDownTimeLabel.as:93`）、`时/分/秒` 走 `LangUtil`，
   我们烘的是 `89: 05: 31`。
4. **堆叠方向**：AS3 从下往上排（`y = -i * height`），我们是从上往下。
5. §3.243 的两条底栏欠账、§3.244-G 的四条、§3.245-G 的旧账：**原样未动**。

以上 2~4 已登记为欠账，改动要另立报修，**不要**混进字体这一族。
