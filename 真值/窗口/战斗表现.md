## ③ 怪物击飞（不是 `BeatBackEffect`！）

**改判记录**：先前这里写过"击飞 = `BeatBackEffect.as` 那 714 行"，那是**查错支**了。
`BeatBackEffect` 是"把怪拽到指定位置/上抛"的技能特效（召唤、地星那类），
而用户说的"怪物直接被打飞"对应的是**暴击致死**那一条：

| 量 | 真值 | 出处 |
|---|---|---|
| 条件 | `!damage.alive && param1.bsk && !monster.mobInfo.boss` ⇒ **只有"这一发暴击 + 把它打死了 + 它不是 boss"才飞** | `AbstractSkillEffect.as:245-247` |
| 水平速度 | 拿**打者的 x** 与怪的 x 比：打者在右 ⇒ `-3000`，在左 ⇒ `+3000`；取不到打者才退回 `attackInfo.direction` | `AbstractSkillEffect.as:249-264` |
| 竖直速度 | `y = -2000` | `:268-271` |
| 同时 | `currFoothold = null`、`grounded = false`、`isHitAway = true` | `:265-267` |
| `isHitAway` 的作用 | `Monster.tick():1358-1363` 把"要不要走地面逻辑"那个开关按死 ⇒ 重力/碰撞/位移三件全开，怪变成纯物理抛体 | `Monster.as:1360` |
| 物理常数 | `GRAVITY_ACC = 2000`、`FALL_SPEED = 670`；`vy += acc*dt/1000` 后**同一步**就 `min(vy, 670)`，位移用 `x += vx*dt/1000`（dt 毫秒） | `Physics.as:6/10`、`AbstractPhysicObject.as:99-107`、`applyVelocity()` |
| 死亡动画 | 飞不飞都照旧 `die1`：`isDie && action != die1` ⇒ 播 `die1`，到尾帧 `pause = true`；`tickHitAndDie` 里"回 stand"那支要求 `currFoothold != null && grounded`，飞着的怪**不会**回 stand | `Monster.as:1183-1193`、`:1173-1179` |
| 顺带：连斩那一档 | `damage == 999999` ⇒ 只上抛 `y = -2000` + 写「连斩」`FIGHT_LIANZHAN`，不飞 | `AbstractSkillEffect.as:202-205`、`:232-241` |
| 顺带：受击僵直概率 | 打完还活着才掷 `MathAD.rnd(1,100)`（闭区间 [1,100]）：普通怪 `< 11`、boss `< 40` 才 `monster.hit()` ⇒ **不是每下都僵直** | `AbstractSkillEffect.as:217-229`、`MathAD.as:27-30` |
| 顺带：未命中 | `damage == 0` 那一支**只加一条 tip**（无敌怪额外拉仇恨），不掉血、不播动作、不位移 | `AbstractSkillEffect.as:276-284` |
| **在线那个 alive 位** | 184 的 `objId&alive&damage*bsk` 里 alive 是**文本 `true`/`false`**（服务端写 `str(monster.hp > 0).lower()`），**不是 0/1**；同一行 `damage*bsk` 的 bsk 才是数字 ⇒ 用 `int()` 解 alive 会**恒读成"已死"** | `fake_flash_server.py:44177`、`:13025` |

**落法（工程侧）**：`战斗角色.gd::take_damage` 拆成四档 —— `amount<=0` 只飘未命中 / 命中掉血 + 按概率 `_受击()` /
`hp==0 且 暴击 且 非 boss` ⇒ `_起飞(±3000, -2000)` / `hp<=0` ⇒ `_die()`。
`_process` 里 `_飞着` 时**只跑 `_飞一拍(delta)`**（不跑 AI、不跑僵直计时）。
打者位置那一档：原版比的是 `打者.x > 怪.x`，我们传的是打者朝向（朝右 ⇒ 怪在右 ⇒ `+3000`），
两个方向都进了判据（`_飞速度.x == ±3000` 各一条）。
原来那句 `position.x += 方向 × 12.0`（**12 是自造的**）已删。

### 变异脚本自己也踩到的三条（下次直接照这个写）
1. **信号的形参数一涨，通用计数器就静默丢事件**：`_count_signal(_arg1.._arg6)` 只能吃 6 个实参，
   `monster_damaged` 从 4 参扩到 6 参（+`bind` = 7）之后，Godot 在 emit 时报
   `Method expected 6 argument(s), but called with 7` 并**丢掉这一次计数** ⇒ 红的是"243 应分派服务端怪物伤害"
   这种**毫不相干**的断言。⇒ 通用计数器留到 8 格；扩信号参数时**必查所有 connect 点**（`grep -rn 信号名 测试/`）。
2. **落点文件行尾不一样 ⇒ 锚点带换行标记就配不上**：`世界相机.gd`/`姓名战斗挂机回归测试.gd` 是 CRLF，
   `后端连接.gd`/`地图实体.gd` 是 LF ⇒ `换()` 现在按各文件自己的行尾展开 `~`。
3. **往 .gd 里插代码时，插入行的缩进档要照周围数**：今天给协议门加 `汇：` 行时少写一档 Tab ⇒
   `Expected statement, found "Indent"`，全项目跑出来的红看着像业务回归。
   ⇒ 加完立刻 `--check-only` 单跑一次再说"改好了"。

### 变异反过来抓到两条「门自身」的毛病（比代码 bug 更值得记）
1. **M23（不看设置就抖）第一次跑居然是绿的**：那条判据只比 `offset == ZERO`，而原版第一拍本来就延后 50ms
   ⇒ 闸坏掉时刚喊完也还是 0。**已补强**成"喊完再喂一拍，要求剩余 0 拍且偏移仍为 0"，M23 才响。
   教训与 `N28` 同一族：**判据观测的时刻正好落在"坏行为也还没表现出来"的窗口里，这条门等于没判。**
2. **锚点两处写坏让变异白跑**：M16/M17 缩进写多了一档（函数体是一档 Tab）⇒ 插进去的脚本 parse 不过，
   门卡在等节点上 300 秒不结束；M19/M20 锚点结尾带了换行标记，而 `世界相机.gd` 是 **CRLF** ⇒ 「命中 0 次」。
   ⇒ 工具里加了两道自检：**变异先过 `--check-only`**（parse 不过记「parse坏」，不冒充证据）、
   **锚点结尾不许带换行标记**。
3. **一次只能跑一个变异脚本**：这次两条同时在跑（一条被工具报了 completed 其实没死），
   互相把对方的变异还原掉，日志看起来像"门卡了 13 分钟"。杀完必须按字节比对那 5 个文件确认干净。



### 像素量法：怎么证"抖的是世界、HUD 不动"（10-11 收口，`开发工具/截震屏.gd`）

四条口径，都是踩出来的：

1. **不能拿半透底栏当判据**。底栏那条皮是半透的（`世界相机.gd:6-9` 早写着"顶部 16px 是半透明边框，
   透过它能看见世界"）⇒ 相机一挪，**透出来的世界**就在变：实测同一条 260×26 的带子，两帧静止之差 0，
   钉上 offset 后变 2736 个。这不是 HUD 在晃，原版也一样（Flash 只裁 `map.scrollRect`，HUD 那层照样透出
   底下在动的地图）。⇒ 这种差只许**报数**，不许当判据。
2. **要判 HUD，先把世界整个藏掉**。做法：把地图场景的**直接子节点**里凡是 `CanvasItem` 的都 `visible=false`
   （`CanvasLayer` 跳过、`Camera2D` 跳过——它也是 CanvasItem，藏掉就没相机了）。
   ⚠ 别用 `get_canvas_layer()` 判归属：本机这版 Godot 在 `Node2D` 上**没这个方法**
   （实测 `Nonexistent function 'get_canvas_layer' in base 'Node2D (地图块.gd)'`）。
   藏完之后钉 `offset=(15,-9)`：头像面板 140×130、**整条底栏 960×101**、小地图 150×120、顶部条 300×24
   四块**逐像素全等（差异 0）**，两张成图**逐字节相同** ⇒ HUD 一格没动。
   （HUD 各面板都在独立层：头像/小地图 `layer=20`、技能/聊天 100、功能窗口/窗口管理 110，都不吃相机变换。）
3. **"画面变了"不等于"世界被挪了"** ⇒ 加平移一致性：把静止帧整体搬 `(−15,+9)` 之后与钉住帧逐点比，
   **带内 51169/60000 = 85% 对得上**，反方向搬只有 12171（20%）⇒ 世界确实整块平移了那个偏移。
   对不上的那 15% 是**视差层**（这图后景 `rx=-10` ⇒ 只跟着相机走 1/10，本来就不该等距平移）加上怪物自己在走。
   两个方向都判（⑧a ≥70%、⑧b ≤35%）才是反向对照：只判"变了"的话，把偏移抖反方向也照样绿。
4. **判据文案里不许引用节点**。点完那枚框，设置页会整页重画把节点 free 掉；我在 `②c` 的说明串里写了
   `str(钮2.global_position)` ⇒ `Invalid access ... on a previously freed` ⇒ **协程当场死掉、`quit()` 永不执行**，
   看着像"量具卡死"（白等 300 秒）。⇒ 几何量在点之前抓成普通变量，文案只用普通值。
