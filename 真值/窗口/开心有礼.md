## ② 原版三页的判定规则（逐条行号）

**限时大奖 `PrizeActivityPanel.as`**
- `:103-156 onCzHuodong_updateStatus`：`:107` `active == 0` 整页不画；`:110-113` `path` 变了才重取配置；
  `:118` 标题；`:119` `_moneyInput.text = param1.chargeTotal`；
  累计九档 `:121-136`（`count = statusTotal[i]`，未领时 `enabled = count > 0`）、
  额度四档 `:137-152`（`enabled = statusEach[i] != 0`，并把 `statusEach[i]` 写进那格数字）；
  两段的已领判据都是 `detail*.count > 0 && curr >= count` ⇒ 「已领取」(`CN.PRIZE_GETED`) 置灰。
- `:67-91` 档位文案：`actions.total` 九档 / `actions.each` 四档，门槛数字取的就是**配置里的 `cash` 字段**。
- `:196-204 clickPrizeBtnHandler`：`:204` `requestCzHuodong_gain(this._configure.info.id + "", type, gainId)`
  ⇒ **活动 id 取的是本页（`limit`）的配置**，不是首充那份。

**新服有礼 `PrizeXinFuWindow.as`**
- `:240` `_countInpt.text = _cash`（那格显示的是点券数）；`:242` `curr >= count && count > 0` ⇒ 「已领取」。

## ④ 本轮经用户点头的偏离（**登记：这不是修 bug，是改产品**）

**别哪天又"改回原版"** —— 下面四条都是有意偏离，原版真值在 ①② 里留着。

1. **首充礼包 → 首日礼包（2026-10-31 再改 → 首杀礼包）**：页签与页名、`奖励框标题`、`礼包标题`、
   `开启说明`、`奖励说明` 全部改名；页头那行「累计充值 __ 元宝」和那枚充值按钮**从场景删掉**。
   领取条件两改：2026-10-28 曾定「建号当天可领、跨天置灰『已过期』」（`first_gift_day_key`，已随本轮退休）；
   2026-10-31 用户改为**「击杀任意 BOSS 一只」** ⇒ 服务端 `_send_czhuodong_first_kill_status`
   发 `{active, bossKills}`，`handle_czhuodong` cmd 4 判 `state.activity_boss_kills < 1`；
   与限时大奖同一把尺子。存档键 `first_charge_claimed` 不动（旧档"已领"照旧生效，不会白送第二份）。
2. **限时大奖：累计充值元宝 → 累计击杀BOSS数**。额度表整排重排：
   累计 **1 / 2 / 3 / 5 / 8 / 12 / 20 / 30 / 50**，每档满 **2 / 4 / 8 / 16**（用户选项原文）。
   ⚠️ 不是换单位——原九档是 0/100/300/500/1000/3000/5000/10000/**300000** 元宝，
   原样读成"只BOSS"就是最后一档要杀 30 万只、永远够不着。**奖励物品一条没动。**
   计数口径 = `MonsterDefinition.boss`（世界/副本/野外 Boss 同一把尺，`_grant_party_kill_credit`
   让队友也记账），落 `state.activity_boss_kills`。
3. **新服有礼「免费10点券」→ 送物品、点券显示整块删**（用户选项原文）。
   ⚠️ 原版那条送的 `11000160` **本身就叫「10点券」**——换成它等于没换，所以改送
   `15012001 修炼灵符（小）` 一件真物品，场景里那一格画它的图标。
   「可领 / 点券数 / 点券」三个节点从 .tscn 删掉，`排行2` 下移让位（`offset_top` 96）。
4. **商城里那枚充值钮**（上一轮删的）与**福利窗这枚**现在口径一致：两处都不许再有充值入口，
   由 `测试/商城购买窗回归测试.gd` ⑧ 的**文本层** tripwire 钉住（节点名 `node name="充值按钮"`
   与皮肤 `充值按钮.png` 都不许回到 .tscn）。

**刻意没动的三样（动了会出事，别顺手改）**
- **存档键名**：`recharge_total` / `first_charge_claimed` / `limited_recharge_{total,each}_claims` 保留原名。
  改名 = 老存档的"已领记录"被清零 ⇒ 同一份奖励能**再领一遍**（发奖类回归是最不该省的）。
  新口径只**加**字段：`first_gift_day_key`、`activity_boss_kills`。
- **线格式键 `cash`**：`config.limit.actions.{total,each}[i].cash` 这个**键名留着**，
  因为 Flash 那侧 `PrizeActivityPanel.as:72/:88` 就是读它拼文案；键名一改，原版参照物读不到。
  值的含义已经变成"只BOSS"，这件事写在常量头的注释里。
- **物品表与协议号**：`FIRST_DAY_GIFT_ITEM_ID = 11010041`、`1814` 的 1/2/3/4 命令号、
  六页的 `1344` 全部原样。物品 **id 不动**，只把目录里的显示名从「首充礼包」改成
  「首杀礼包」（`开发工具/改首杀礼包道具名.py`，2026-11-01；另一件 `11010067`
  「回归首充礼包」不动）。服务端不参与：`_encode_item_payload` 只发数值字段。
