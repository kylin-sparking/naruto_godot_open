## 2. 三段动画（原版是 `tick(毫秒)` 逐帧改坐标，不是补间）

| 段 | 出处 | 算式 |
|---|---|---|
| 出场抛物线 | `:381-409`、`:125-126` | `_timeDrop = 800ms`；`yMinist = min(from.y,to.y) - 115`；`_yPerTime = (from.y-yMinist + to.y-yMinist)/800`；`y = from.y - _yPerTime*t`，越过顶点就 `y = yMinist + (yMinist - y)` 镜像回来；x 线性插值；**非金币**还转 `contentContainer.rotation += 2160 * t/1000`（度/秒） |
| 落地 | `:388-396` | `x=to.x; y=to.y-15`；`_pastTime += _upDownRnd`（`:119 = MathAD.rnd(0,600)`）；`contentContainer.rotation = 0` |
| **待机上下浮动** | `:478-483` | `_pastTime += 步进`；`while(_pastTime > 2π·300) _pastTime -= 2π·300`；**`contentContainer.y = floor(3 * sin(_pastTime/300))`** ⇒ 幅度 ±3 像素、一圈 ≈ 1885ms、`floor` ⇒ 只有 −3..2 六档；每枚相位不同（不然满地一起动，一眼假） |
| 拾取 | `:433-457` | `PICKUP_TIME = 600ms`；`alpha = max(剩/600, 0.3)`；`y = to.y - (600-剩)*80/600`，升到 `to.y-50` 处镜像弹回；`x += min(拾取者.x - x, 200*步进/1000)` |
| 消失 | `:416-432` | `DISPAIR_TIME = 1000ms`，`alpha` 掉到 0.3 |

## 3b. 捡取这条链（10-12 第二轮：用户"修掉落物捡取效果，还是跟原版本一致"）

原版四步，本工程逐条对齐；**点下去不播动画**是这一轮最核心的改动。

| 步 | 出处 | 内容 | 本工程落点 |
|---|---|---|---|
| ① 点 | `DropItemHandler.gotoPickUpItem():131-164` | 不能动 / 死了 ⇒ return；`_curItemGoToPickUp != 这枚` 才继续；**距离 < 50 ⇒ 当场发**，否则 `API.player.pathFind(item.x, item.y - 5)` **先走过去** | `_点掉落物()` |
| ② 每帧 | `tickItemGotoPickUp():451-467` | 走近到 < 50 ⇒ 发拾取；**玩家已经不再寻路 ⇒ 放弃这一单** | `_推进去捡()`（读 `玩家.click_move_active`） |
| ③ 发 | `pickDropItem():543-565` | 全局节流 `PICK_ITEM_TIME_LIMIT = 200ms` + 这一枚锁定 `LOCK_PICK_UP = 5000ms`（`_hasPickUpDic`）⇒ 才 `requestItemPickup` | `_发拾取()` + `_拾取闸` / `_锁定表` |
| ④ 回帧 | `removeDropItem():401-422` + `RemoveItemInfo.decode()` | `animation` 0=过期 1=无动画 **2=拾取** 5=宠物捡；**≥2 才起动画**且 `picker = cid 那个角色/宠物`；0/1 ⇒ **直接消失、不播** | `_on_server_drop_removed(编号, 动画, 角色号, 是宠物)` → `_起拾取动画()` |
| 键 | `KeyController.tickPickUpDropItems():793-811`、`PICKDELAY = 100ms`(`:52`) | **按住 Z** ⇒ 每 100ms 挑一次；`onRoadGoToPickUp()` 为真（已经在去捡的路上）⇒ 不重挑；挑的是 `getOnePickableDropItem():99-124` = **能捡的里面离玩家最近的一枚** | `快捷键.默认["pick_up"] = [KEY_Z]`（原版 `KEYBOARD_SHORTCUT_KEY_PICK` 默认 `KEY_ID_44` = Z，`canSet=true`）+ `_最近可捡掉落物()` |
| 身体捡 | `pickItemLose():77-83` + `touchPlayerNow():513-520` | **只对 `touchUp=true` 的那一档**：±200 粗筛 + 玩家身体盒压 `itemTouchRect(-17,-34,34,34)` ⇒ 自动发拾取，且**不吃 200ms 全局节流**（`canItemPickup(item,false)` / `pickDropItem(item,false)`），但仍吃那一枚的 5 秒锁。这种掉落物**没有名字标签、不挂鼠标**（`ctor:142-151` + `render():311/355`） | `_推进身体捡()` / `_身体碰到掉落物()` / 建节点时 `touch_up` 直接早退 |
| 能捡 | `canItemPickup():478-486` + `canPickUp:294-297` | 没死 && 这枚没被 5 秒锁挡住 &&（**无主 或 我掉的 或 同队掉的**）&& 已落地 && 不在拾取动画里 | `_可捡()`（⚠ 同队那条没接，见 §6） |
| 服务端帧 | `fake_flash_server.py:46631/47034`、`58068` | 文本面 `273:animation:oid:pet:cid[:slot]`，转成原版二进制体时字段序完全照 `RemoveItemInfo.decode()` | `后端连接._handle_remove_drop_text()` 原先**只取 oid、把 animation/pet/cid 全丢了** ⇒ 客户端只能"点下去自己播" |

⚠ **一个自己踩出来的坑（值得记）**：`_要去捡` 的"没有目标"哨兵原来写 `-1`，
而**离线掉落物的编号正是从 −1 往下走**（`_离线掉落序号`）⇒ `_点掉落物` 第一行
`if _要去捡 == object_id: return` 对离线掉落**永远早退**，表现就是"离线掉的东西点不动"。
现在换成 `const 无拾取目标 := -999999999`。原版这里用的是对象引用 `null`，天然不会撞。

## 4. 三条被打回的现场问题（10-12）与处置

| 用户报的 | 查到的根因 | 处置 |
|---|---|---|
| 金币图标**有时**整块变纯白 | 四档钱堆的**每帧尺寸不一样**（90000000 = 23/25/23/**5** ×24、90000002 = 31/32/**33**/32 ×30、90000003 = 四张同为 32×31）。`AnimatedTexture` 是把各帧叠成一张 texture array 的，尺寸不齐时它报出来的宽高就是错的（实测改前报 23×24 / 32×30，真实最大 25×24 / 33×30 ⇒ 有一列被切），采样越界在部分机器上出白块。**"有时"与档位对得上：只有 ≥1000 那一档四帧同尺寸、不会犯**。⚠ 我在本机受控复现（四档 × 四帧逐个裁屏 + 藏掉图标拍底片做差分）**没能当场逼出白块**，所以这条是"结构上唯一坏掉的地方 + 与现象吻合"，不是复现出来的因果 | 逐帧垫成同尺寸 ⇒ 越界这条从根上没了；同时动画不再逐帧跳位 |
| 大小不对 | 尺寸 34×34 本身没错，错在**摆位**：原来摆 `(-17,-34)`（底边贴锚点）⇒ 整枚图标高了 17 像素；金币原来是"居中在 34×34 盒里"，与 §1 的"注册点压地面线"差 15 像素 | 物品 ⇒ 盒 = 锚点 ±17（中心重合）；金币 ⇒ 盒底边 = 锚点+15 = 地面线、水平居中 |
| 不会动 | `_推进掉落动画()` 只有出场与拾取两段，**待机那一整段没写**（有头量具连拍 60 帧实测图标 y 只有一个值 157.0） | 补 §2 的浮动算式 + 落地随机相位 |

顺手补的一条静默：**图标取不到时地上是完全空的**（一个像素都没有，玩家只会觉得掉了个寂寞）。
原版这种情况下 `PicTool.getItemObject()` 会 `DatManager.loadDat()` 把缺的那包物品图拉下来再补画，
本工程没有那条兜底 ⇒ 现在至少 `push_warning` 报出 `item_id`。

## 5. 门与量法

- 离线门：`测试/离线掉落表现回归测试.gd`（**52 条断言**：原 12 + 表现轮 13 + 捡取轮 15 + 身体捡/同队 12）。
  钉：四帧同尺寸、图标盒 = 贴图天然尺寸（不缩放）、金币盒底边压地面线 + 水平居中、
  名字盒中心在锚点下 30、四档 = 四张不同贴图且同档复用、落地后 `drop_air=false` 且名字显形、
  2 秒里 y 至少 3 个值且全部落在 `落点y−15 ±3` 带内、`drop_phase ∈ [0,600)`。
  捡取轮钉的是：点远处 ⇒ 只记「要去捡」**不起动画**；走到跟前 ⇒ 才发拾取；发过之后哨兵复位；
  `_可捡` 的四种否决（在空中 / 已叫收 / 别人掉的 / 5 秒锁定）与"自己掉的就放行"；
  `_最近可捡掉落物` 挑近的不挑远的、正在被捡的那枚要跳过；默认键位表里有 `pick_up` 且 = **Z**。
  **变异实测八条都响**（同一枚掉落物点不动的哨兵撞号那条是当场撞出来的，不是变异造的）：去掉垫尺寸 → "四帧必须同一尺寸"；金币 y 15→0 → "盒底边该压地面线"；
  删掉浮动两行 → "2 秒里 y 至少该有 3 个值，实得 1 个"；`_可捡` 里删掉 `drop_air` 判定 →
  "还在空中飞的不算可捡"；把挑最近的 `<` 改成 `>` → "该挑离玩家近的那枚（实得 −999999999）"。
- 有头量具（不进门禁）：`开发工具/看掉落物.gd` —— 造 7 枚（四档金币 + 两枚真物品 + 一枚查无此 id），
  落地后逐帧裁屏拼 6 倍图 `测试/截图/掉落物/掉落物六倍.png`，并打印"盒左上 − 锚点"、
  贴图尺寸、浮动取值集合。**裁屏必须用 `get_screen_position()`**：`global_position` 是画布坐标，
  相机跟着玩家走 ⇒ 拿它裁视口图会裁到别处（第一版就栽在这，拼出来一片空）。

## 6. 未收口（如实）

1. **金币的注册点只到"底边中心"，没到像素级**。原版 `content.x = -15` 那个 −15 是相对锚点的
   水平偏移，而每帧的 `origin` 存在客户端 `GameData.dat` 的物品记录里（`iconRaw` 段），
   本工程的服务端 GameData 没建模这一段 ⇒ 取不到。现在按"底边中心贴地面"摆，
   四档宽度 23~33 ⇒ 与原版差 ≤ 3 像素。**要精确就得解 `GameData.dat` 的 `iconRaw[i].origin`。**
2. **悬停白色辉光没做**（`GlowFilter(0xFFFFFF,1,6,6,5)`）⇒ 鼠标移到掉落物上现在没反馈。
3. **神器的掉落图**（`PicTool.getShenQiDropUpPic` → `iconDropUp`，60×150 盒、命中片 60×120）
   没导没接 ⇒ 神器现在按普通物品图标画。
4. **神器的 `touch_up` 例外没做**：原版 `render():322-338` 那一支的名字标签是
   **无条件建**的（金币/普通物品那两支都被 `if(!touchUp)` 包着）。本工程现在
   `touch_up` 一律无名无钮 ⇒ 将来接神器掉落图（`iconDropUp`，60×150）时要给这一支开口子。
5. **`nowInNotFindPathMap` 那条分支没接**：原版在这种"不能寻路"的地图里改用
   `pickItemInARect():428-449`（玩家盒 `(x−20, y−42, 42, 42)` 压掉落物盒
   `(x−17, y−17, 34, 34)` + 同一枚 1 秒内只算一次 ⇒ `onTouchItem`）。
   本工程所有地图都走 `pickItemLose` 那一条 ⇒ 若真有这样一类地图，身体捡的判定会比原版松。
6. **`isStrict` 那条没接**：原版 `DropItemHandler.isStrict`（默认 false）为真时走
   `pickItemStrict():393-399`（横向只认 `x−5 ~ x+50` 的窄带）。本工程没有这个开关。
6. 离线掉落**给多少金币**仍是自定的 `离线掉落金币 = 5`（原版由服务端 `_itemid` 给）。
5. 纯白那条**没能在本机复现**（见 §4 第一行）⇒ 如果改完还犯，需要一张当时那一帧的截图。
