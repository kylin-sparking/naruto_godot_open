| 件 | 窗口坐标 | 行号 |
|---|---|---|
| 内容底 MYellow | (5,39) 488×381 | `:371-376` |
| 子面板 MPane | (11,65) 478×336 | `:377-382` |
| 4 枚页签 MTabButtonF | (17+i×70, 45) 70×22，第 0 枚选中 | `:329-341` |
| 副本名 TextField | x=11 宽 84，高 = textHeight+5，y = 65+(110−高)/2 | `:197-205`、`:300-305` |
| 格滚动 ScrollPane | 与子面板同矩形，竖 ON 横 OFF | `:384-393` |

格（`BailianCell.as:79-136` + `EliteCopyWindowCell.as`）84×124，子件序 =
格底 → 锁 → 选中底 → 名(0,84,84×18 `#FDB799`) → 章节(21,64,43×18 白) → 头像 → 次数(0,100,84×20 白)。

**头像不许缩放**（2026-10-03 用户拿原版对照图打回）：`PortraitHead` 构造是
`(true, -1, -1, TYPE_MONSTER)`，`tick()` 里 `if(_w != -1 && _h != -1)` 那段缩放**根本不执行**
（`PortraitHead.as:94`），位图按**自己原生尺寸**画、再用 `info.portrait.origin` 对齐
（`:86-87` `bmp.x = -origin.x`）。PortraitHead 那个位置是 `42,36`
（`EliteCopyWindowCell.as:60-61`）⇒ **格内左上角 = (42 − origin.x, 36 − origin.y)**。
实测 21 张头像有 **11 种原生尺寸**（41×54 / 43×52 / 44×54 / 48×50 / 48×54 / 49×54 /
51×51 / 51×54 / 54×53 / 54×54 / 62×62）⇒ 套一个固定 62×62 的框去 `STRETCH_SCALE`
会把 54、41 那些放大变形还发糊。现在 `出精英副本布局.py` 把 `头像尺寸` / `头像位` 逐张算进
布局表，生成器按它落矩形，量具额外钉「矩形尺寸 == 位图原生尺寸」。

头像取图走 `PicTool.getMonsterObject`（`PicTool.as:52-92`）的 **`info.link` 兜底**（`:76-88`）：
BOSS 自己 `info.portrait` 为 null 时，克隆它 `link` 的基础怪并把**那个怪的 portrait** 搬过来
⇒ 5200001~5200014、5200045 这 15 张实际取的是 1000016 / 2000001~2000023 的头像，
**名字仍用 BOSS 自己的**（剥「【BOSS】」前缀，`EliteCopyWindowCell.as:48-55`）。

**格位不是等距网格**：`createCell():101-149` 是个带状态的循环 —— 第 1 行只 4 枚
（x=84/178/272/366，y=5），从第 5 枚起 `colCount` 偷偷变成 5、且该行第一枚落在 **x=0**
（正好压在左侧副本名下面），并在上一行下方补一根 `LineHPicF`（y = 上格y+120+8）。
`i==5` 被单独排除不画线。这套怪算法由 `开发工具/出精英副本布局.py` 原样算进
`数据/界面/精英副本_布局.json`，量具/生成器/控制器三方共读 —— **不许"顺手修好"**。
