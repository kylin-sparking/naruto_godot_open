# 经验条（底栏 + 人物面板）真值 —— 2026-10-11 #180

用户 2026-10-10 原话：「修复角色经验值条不是实时跟随经验显示问题 和角色面板经验条不是实时显示问题」。

## 0. 一句话根因

**分母从来不在服务端属性包里，是客户端查 `ExpTable` 现算的**；本工程没查表，
`player_stats.max_exp` 一直停在 `离线示例数据` 那个 `100` ⇒
两根条算出来的比例 `exp/max_exp` 被 clamp 成 1.0 ⇒ **条子永远满格、百分比永远 100%**，
经验再怎么涨都不动 —— 玩家看到的就是"不实时跟随"。

修前实测（`开发工具/截经验条页.gd` 同一套喂法）：`{level:7, exp:300}` 之后 `max_exp` 仍是 100。

## 1. 原版四处落点（2.2.3优化版反编译，逐条到行号）

| 用途 | 出处 | 原话 |

| 人物面板那根条 | `DataCenter.as:1447-1462 getDataForCharacterInfoWindow` | `_loc1_.experience = this.stats.experience;`<br>`_loc1_.maxExp = ExpTable.getExpNeededForLevel(this.stats.level);` |

⇒ 结论：**分母只有两个来源** —— 客户端查表（`ExpTable[level]`）或角色包里的 `expTotalNeed`；

## 2. 等级经验表（`ExpTable.as`）

`com/mxw/data/ExpTable.as` 的 `private static const exp:Array`：**121 项，索引 = 等级，0..120**，
`getExpNeededForLevel(l)` = `l >= 长度 ? 最后一档 : exp[l]`（超范围回最后一档，原版就这么写）。

| 等级 | 本级所需 | 等级 | 本级所需 |
|---|---|---|---|
| 0 | 0 | 9 | 2163 |
| 1 | 20 | 10 | 2595 |
| 2 | 84 | 11 | 3114 |
| 3 | 190 | 44 | 1276272 |
| 7 | 1196 | 50 | 4128502 |
| 8 | 1602 | 100 | 29894279463 |
|  |  | 120 | 65502047576 |

**两份独立来源逐条相同**（生成时当场对，对不上直接炸）：
① 上面那份 `.as`；② 工程内服务端 `服务端/runtime/tools/fake_flash_server.py:491 EXP_BY_LEVEL`
（`:46407 _experience_required_for_level`、`:46487` 升级扣经验用的都是它）。
⇒ 服务端 `character.exp` 是**本级内经验**（升级时 `exp -= required`），和客户端比例口径天然一致。

落地：`脚本/单例/等级经验表.gd`（**由 `开发工具/生成等级经验表.py` 生成，别手改**；
`--只核不写` 给门做"重跑生成器比对"）。

## 3. 本工程改了哪三处

| 处 | 文件 | 做什么 |
|---|---|---|
| 权威落地 | `脚本/单例/服务端会话同步.gd` `应用人物()` 赋值循环之后、`player_stats_changed.emit` **之前** | `会话.player_stats["max_exp"] = 等级经验表.本级所需(等级)` |
| 离线重算 | `脚本/单例/游戏会话.gd` `_recalculate_stats()` 末尾 | 同一句（离线启动那一帧也不停在 100） |
| 离线升级 | `脚本/单例/游戏会话.gd` `_apply_level_ups()` | 阈值改成查表；**删掉自造的 `max_exp *= 1.25`**（原版没有任何一处按等比数列算升级所需） |

⚠ 顺序是判据之一：**补分母在 emit 之后** ⇒ 第一根条拿旧分母画（门里 M2 那条变异专门钉它）。

## 5. 未收口（如实）

- 经验条**外观**（底栏那根是 shader 进度条、面板那根是 ProgressBar）与原版 `MBar`/`MBarExpF`
  的逐像素对照没做 —— 本轮只修"数值不动"，条子本身的皮/尺寸另计（#164 那类逐像素四件套）。
- 原版 `CocoStatType.EXP` 那一号还会顺手出 `player_addAttriChangeTip`（头顶飘字）⇒ 那是 **#175**，没并进来。
- `_apply_level_ups` 里"每级 +5 潜能 / +1 属性点"是工程原有写法，本轮只换了分母；
  服务端那份是 `10 if level>=70 else 5`（`fake_flash_server.py:46494`）⇒ **离线档位对不对没查**（门里只钉了形状没变）。
