# 真值：弹窗该挂在哪一层、"给个说法"那行字该活多久

> 触发点：用户 2026-10-22 实机报修 **10**「商城购买道具的面板显示优先级过低，老是点一下就下降到最下面」
> 与 **9**「商店购买东西、宝石合成，会有灰色字体一直挂在面板上方，不消失，除非关闭面版」。
> 两条是同一次收口（§3.248），但**根完全不同**：一条是**层**，一条是**生命周期**。
> 证据根：`2.2.3/map_extract/out/mainlib_as/scripts/`（AS3）。

## ② 本工程为什么会沉 —— 我们的窗是**各自一层 CanvasLayer**

| 位置 | 现有实现 | 后果 |
|---|---|---|
| `脚本/界面/窗口管理.gd:527-531` | `重排层级()`：`窗.layer = HUD基(110) + i + 1`，`i` 是它在 `_顺序` 里的下标 | 每扇功能窗一个 CanvasLayer，**层号说了算**（同 layer 时 Godot 按创建顺序画，`move_child` 不够 —— `:516-519` 已实测并写死在注释里） |
| `脚本/界面/窗口管理.gd:504-510` | `_置顶(页名)`：`_顺序` 尾部 + `move_child` + `重排层级()` | 点任何窗的**任何位置**都提（用户 2026-09-24 定的规则） |
| `脚本/界面/功能窗口.gd:4867-4869` | 购买窗 `instantiate` 之后 `add_child` 到 **`_overlay`**（宿主的遮罩 Control） | ⇒ 购买窗**住在宿主那一层里**。宿主 layer 一被别的窗超过，弹窗跟着一起沉 = 报修 10 |

**等价物不是"把弹窗搬到窗口管理那一层"**（那要改宿主关系、动 8 扇窗的开法），
而是把原版那句"遮罩铺满整舞台"在拾取层复现出来 —— 本工程已有的机制就是 `模态弹罩住`。

## ③ 模态形状契约（`脚本/界面/功能窗口.gd:805-816`）

```gdscript
func 模态弹罩住(点: Vector2) -> bool:      ## 三条件，认形状不认节点名
	if 层.z_index < 100 or 层.mouse_filter != Control.MOUSE_FILTER_STOP:
		continue                            ## ① 铺满 ② STOP ③ z_index ≥ 100
	if 层.get_global_rect().has_point(点):
		return true
```

`窗口管理._input:541-561` 的口径：**先**从 `_顺序` 末位往下问一遍 `模态弹罩住(点)`，
有一枚罩着这一点 ⇒ **一票都不提**；否则第二段循环按 `窗口矩形()` 找**最上面**那扇命中窗 `_置顶`。

工程里现存的模态层，三条都齐：`输入确认弹`（输入/消息/勾选三型）、老的 `_弹出确认` / `_弹出输入`
⇒ 一律 `PRESET_FULL_RECT` + `MOUSE_FILTER_STOP` + `z_index = 100`。
**购买窗遮罩是唯一的漏网**：`_前置购买窗遮罩` 建 `ColorRect` 时只写了 `set_anchors_preset(FULL_RECT)`
与 `mouse_filter = STOP`，**`z_index` 留默认 0** ⇒ 形状认不出来 ⇒ 购买弹开着期间点隔壁窗，
`_input` 照提隔壁 ⇒ 隔壁 layer 变大 ⇒ 宿主连同弹窗一起被压下去。

⇒ 修法两行（`功能窗口.gd:4802-4803`）：`遮罩.z_index = 100`、`窗.z_index = 遮罩.z_index + 1`。
第二行**不给死值**：这两枚是 `_overlay` 的兄弟，画序除了 layer 还要比 `z_index`，
断言 `窗.z_index > 遮罩.z_index` 钉的是「**窗压遮罩**」这条不变式，写死 101 就允许有人把遮罩改成 150。

⚠️ 同一段里那段 `move_child(遮罩, 目标位)`（`:4804-4814`，§3.240 修的"第二次进购买界面就变灰"）管的是
**兄弟序**，与 `z_index` **互不冲突** ⇒ 那条 `挡.get_index() < 窗.get_index()` 判据照旧成立，两件事别并成一条。

## ⑤ 本工程现状与本轮取舍

* 那枚**黄色飘字整条没移植**（没有 `messageTipContainer` 的等价物，`_notify` / `notification_requested` 走的是**系统消息**那条聊天/通告带）。
  ⇒ 这是**已登记的缺口**，不是本轮要补的东西：补它要新建一个跨窗的全局容器，跟报修 9 的"不消失"是两件事。
* 本轮的反馈落点是**窗内那根灰 `Label`**：`功能窗口.gd:1177` `_status = get_node("遮罩/主窗口/后端状态")`，
  `_show_hint(文本)`（`:4965`）写它。老写法**只写不清** ⇒ 用户看到的"灰色字体一直挂在面板上方，不消失，除非关闭面版"。
* 对齐 AS3 的做法是**给它一个 5 秒的生命周期**（`提示自收秒 := 5.0`，`:200`，值直接取 `MessageTipPane.as:69` 那个 `5`）：
  写完排一发 `SceneTreeTimer`，到点走 `_收起提示(代号)`（`:4982`）清空 + 隐藏。
* **代号闸**（`_提示代号`，`:201`）：`SceneTreeTimer` 一次性、发出去就收不回，连点两次会挂着两条定时器；
  没有代号的话**上一发会把下一句刚写的字收走**。⇒ 每次写行都 `_提示代号 += 1` 并把它 `.bind()` 进回调，
  只有"仍然是最新那发"才动手。这条是原版没有的（原版每行是独立 `MessageTipPane` 实例，天然不互相干涉），
  我们的等价物是**单枚标签复用**，所以要自己补上"哪一发算数"。
* `close()` 里 `_提示代号 += 1` + 清行（`:1047-1050`，`close()` 本体从 `:1005`）：换页/收窗之后那发定时器还会到点，
  让一个已经看不见的标签去"清空自己"没有意义，也可能清掉**下一页刚写的那句**（同一实例、同一 `_status`）。
* ⚠ `_on_backend_status(…)`（`:5357`）写的也是这枚 `_status`，但那是**连接状态**（`后端：xxx`），
  **它自己不排自收**；而上一发 `_show_hint` 那枚定时器到点时**照样会把这一句一起收掉**
  （闸只认 `_提示代号`、不看文本是谁写的）。这是有意的：那句只在连接状态变化时重刷，
  不是玩家要点操作时读的东西 ⇒ **判"该不该留"只认代号，绝不按文本内容猜**。
