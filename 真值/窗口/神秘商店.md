## ③ 线的形状（324 下行 / NPC_SHOP 上行 6·7·8）

`SecretShopInfo.decode`（`:21-40`，**前 2 个 int + 每条 6 个 int + 尾巴 1 个 int**）：

```
remainSecs:int, count:int, [ itemid, count, yb, moneyType, meso, hasBought ] × count, discountPercent:int
```

本工程文本线序（`后端连接._handle_secret_shop_text`）：`324 : 剩余秒 : 每条用 & 分 6 段、@ 分条 : 折扣`，
空列表那一条服务端发 `-`（`fake_flash_server.py:55607-55611`）⇒ 解析要认 `-`。

上行（`NPCShopProcessor` + 服务端 `55658-55675`）：

| 动作 | 载荷 | 服务端行为 |
|---|---|---|
| `6` 开 | 无 | **等级 < 25 ⇒ 只发一句系统聊天「达到25级后才能开启神秘商店。」、不发 324**；够格 ⇒ `_send_mystery_shop()` |
| `7` 买 | **`fields[1]` = item_id**（不是下标！） | 不在货架或已买过 ⇒ **重发整张 324**（不是错误帧）；否则走商城那套扣款再重发 |
| `8` 刷新 | 无 | 同样先过 25 级闸；`_refresh_mystery_shop(manual=true)` 后重发 324 |

⇒ `request_secret_shop_buy(index)` 那个形参名是**旧的**，传的是 **item_id**。

货架 **5 件**（`_ensure_mystery_shop:55564` 判 `len == 5`）、刷新周期 **6 小时**（`:55556`），
`money_type` 由下标奇偶给（`:55570` `1 if index % 2 else 0`）⇒ 本机夹具**永远不会给 2**（双币那档），
门里要判 2 得自己喂帧。

## ④ 谁开窗、谁重灌（原版语义）

`ItemWindow2.as:1763-1765 openMysteryHandler` ⇒ `MysteryManager.requestOpenMystery()` ⇒
`client.requestSecretShopOpen()` —— **点钮只发一跳，不开窗**。
开窗的是回帧：`Client.as:8723-8726 onOpenSecretShop` ⇒ `MysteryManager.receiveRefItem`（`:30-46`）：

1. `shopInfo = param1`（**先存数据**）；
2. `windowMap[MYSTERY_WINDOW]` 已存在 ⇒ `updateview(items, remainSecs)`（**只重灌，不重起秒表**）；
3. 不存在 ⇒ `centerTwoWindow(MYSTERY_WINDOW, ITEM_WINDOW2_F)` ⇒ **神秘商店在左、背包紧贴右 1px、整对居中**。
   对应本工程 `窗口管理.伴随背包 + 成对摆位`（同「交易 / NPC商店」那一族）。
4. 新建那扇的 `initUI` 末尾 `setTimeout(openMysteryWindow, 500)`（`:116`）⇒ **开窗 500ms 后**才
   `updateview` + `_timeLabel.start()`。本工程：开窗即渲染、秒表随渲染起（500ms 那一跳是 Flash 的
   建帧延时，没有可观察差别 —— 记在这里，不当已实装）。
5. `initUI:91` 在建秒表时就写死 `_timeLabel.passTime = 10` —— 那是**占位**，真数由
   `openMysteryWindow → updateview:164` 覆盖。别把它读成"神秘商店只倒计时 10 秒"。

⚠️ 第 2 条是**这条链最容易接错的地方**：刷新（动作 8）与买成（动作 7）都会再推一整帧 324，
原版那时**只换数据、不重起秒表**。口径要说准（第一版写成"倒计时不重置"是不准的）：
`updateview:164` **照样把 `passTime` 覆盖成这一帧的 `remainSecs`** —— 数字跟着最新帧走；
它守的是另外两件事：**表没被重起**（`start()` 有 `running` 闸，且 `updateview` 根本不调它），
以及**文案不立刻重绘**（`set passTime` 只写数、不出字，见 §④之半 那条）。
照"每次收到 324 就重开一遍"写，玩家每刷一次倒计时就回到 6 小时 —— 那是自造。

1. 判的是 `<=` 不是 `<` ⇒ **余额刚好等于价也不让买**（点券、元宝、刷新三处全这样）。
2. `moneyType == 2`（元宝 + 券都收）**既没守卫也没文案** —— `buyItem` 只判 0 和 1 两支，

   到 `:203` 就成 `CN.replaceString(null, param3)` ⇒ 里面 `null.replace(...)` 抛 **Runtime #1009**
   （`null` 上没有方法），弹弹不出来、7 也发不出去。所以双币那一档点下去**什么都不发生**。
   本机夹具发不出 2（`money_type` 按下标奇偶给），门里靠喂帧判这一支。
3. `showSureRefWindow` 是**运行期量**（`MysteryManager:18`，单例字段，不落盘）⇒ 重启客户端又会弹一次。
   本工程放控制器**静态变量**（会话内有效），与"不落盘"这条对上；别写进 `game_settings`。
4. `_refYuanBao = 50`（`MysteryManager.as:16`）与 `refMoney = 50`（`MysteryWindow.as:32`）是**两处各自写死**
   的同一个数 —— 守卫用后者、文案填前者。本工程 `刷新花费` 一个常数供两处，改的时候记得这两条都得跟着改。

## ⑦ 门与量法（`测试/神秘商店窗回归测试.gd`）

## ⑧ 弹层 vs「点击置顶」——本工程特有的一条坑（原版没有）

原版 `MysteryWindow.buyItem:204` 把确认弹交给 **`PopUpMananger.stage`**：那是**所有窗口之上**的
独立一层，点弹上的钮不会动窗口层级 ⇒ 弹永远压着窗。
本工程每一枚模态弹挂在**各窗自己的** `_overlay` 里，而神秘商店是 §④-3 那对**成对摆位**的窗
（神秘商店 + 紧贴其右的背包）。弹在屏幕上居中 ⇒ 落点恰好也在**隔壁那扇窗的矩形里**；
而 `窗口管理._input`（2026-09-24 定的"点窗口任何位置都提到最上"）跑在 **GUI 拾取之前**，
于是点「取消」这一步先把背包提起来 ⇒ `重排层级` 把背包的 `CanvasLayer.layer` 排到神秘商店之上 ⇒
弹被画到背包底下、点击也落到背包的控件上。**10-19 实测**：点神秘商店确认弹上的「取消」，
`gui_get_hovered_control()` 命中的是背包第 18 格 / 物品菜单项，取消与确定**都点不动**。

⇒ 修法在引擎侧不在页侧：`功能窗口.模态弹罩住(点)` 按**形状**认弹
（`_overlay` 的直系子件、`z_index >= 100` 且 `mouse_filter == STOP` 且矩形罩住这一点），
`窗口管理._input` 先扫一遍已开窗，**只要有弹罩着这一票就整轮置顶都不做**。
认形状不认节点名 —— 同名叠两层时 Godot 会把后一个改名 `@Control@N`，名字靠不住。
这条对所有成对摆位的窗都成立（商城 / NPC商店 / 交易 / 仓库的弹同样受益），门 §⑤ 那条层号断言
就是钉它的；改 `_input` 之前先看这段。
