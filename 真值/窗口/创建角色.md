## 3. 随机（randomChar():199-225，随机整组不是只随机名字）
`r=Math.random()*100`：`r>=70`→框3(风女)、`r>=40`→框2(水女)、`r>=20`→框4(雷男)、否则框1(火男)；
随后 `randomHandler()` 取随机名，并挂 `CreateButtonMovie`。

## 4. 名字校验（createCharFail():145-178，判序即顺序）
1. `textWidth > MAX_NAME_WIDTH(76)` → 名字太长
2. 空串 → 不能为空
3. （泰服才走 ThaiGrammerCheck，本工程不需要）
4. 正则 `/^(?!\d)[a-zA-Z0-9一-龥_]{1,}$/` 不过 → 红字弹框（`16711680`）
5. `length > MAX_NAME_CHARS(12)` → 超长；`length < MIN_NAME_CHARS(2)` → 太短

## 8. 建角回帧（jylx:17）**不许**刷角色列表 —— 2026-10-10 #179
用户原话：「注册完账号选完职业输入名字后点击进入游戏 应该直接进入游戏世界内
不应该在选择角色登陆一下 纯多余」。

原版这一号的完整语义（三份 AS3 对起来读，中间没有任何一步要玩家再点一次角色）：

| 层 | 出处 | 做什么 |
|---|---|---|
| 协议派发 | `LoginProcessor.as:326-339 handleAddNewCharacterEntryPacket` | 解出 `charInfo` 塞进 `CharacterList`，回调 `onAddNewCharacterEntry`，**不调 `updateCharList()`/不刷 UI** |
| 客户端 | `LoginServClient.as:439-449 onAddNewCharacterEntry` | `Config.sendPlayerCreated()` + `callBack.onCharCreated()` |
| 界面 | `MainLoader.as:265-282 onCharCreated` | 拆掉创角窗、挂"正在登录服务器"的 loading |
| 界面 | `MainLoader.as:1190-1207 oncheckLoginStatus` | 走 `loadVersion` **直接进游戏** |

⇒ 本工程两处对应改动：
1. `脚本/单例/后端连接.gd` jylx `17:` 分支只 `characters.append()` + `character_created.emit()`，
   **不再 `character_list_received.emit()`**（多这一发就是选角窗弹出来的直接原因）。
2. `脚本/界面/登录界面.gd` 加 `_刚建好角` 闸：`_on_character_list` 收到非空列表时，
   本局已经建过角就直接 return（原版那一步只有 loading 文字）。

验收：`测试/创角进图在线回归测试.gd`（11 条，从**真登录界面**一路真点：注册弹窗 → 填号密 →
点登录 → 创角窗自己冒出 → 选格填名 → 点「进入游戏」）。判据不是"最后有没有弹窗"，
是 `选角窗.visibility_changed` —— `_显示选角窗()` 一置 visible 就立刻记一次露脸，
所以"先弹出来、下一帧又被建角回调关掉"这种肉眼难抓的闪动照样红。

反向对照（`cp` 副本改回去再跑，没进 git）：

| 变异 | 结果 |
|---|---|
| A：把 `character_list_received.emit(...)` 加回 jylx 17 | **红 1 条**（正是那条"选角窗一次都没露过脸"），退出码 1 |
| B：只删 `登录界面` 的 `_刚建好角` 闸 | 不红（退出码 0）⇒ **本条用例照不到这一半**，它只是兜底、不是病因 |

⇒ 结论要说全：**根因是 A 那一发多出来的信号**；B 那道闸是"再推列表也不许弹"的保险，
运行期这条路没验证过它的必要性（未验，别当成已证）。
