# 真值：「徽章打造合成」两页的**料格 / 产物格 / 回帧**（报修 1.1・1.2）

> 触发点：用户 2026-10-25 报修「放入徽章后，徽章打造石没有自动放进去显示数量，当前一直是灰的
> （正常只有数量不足才是灰的）」+「合成/强化都没有显示打造成功的产物，鼠标放在放入的物品以及
> 产物上要显示详情框」。
> 结论：**这两条都是原版有、我们没做**，不是新增诉求。证据根
> `2.2.3/map_extract/out/mainlib_as/scripts/com/mxw/uifl/controls/beastBadge/`
> （`BadgeComposePane.as` 278 行 / `StoneComposePane.as` 284 行）。
> 工程侧落点：`脚本/界面/窗口/徽章打造窗.gd`，门 `测试/徽章打造投料回归测试.gd`（⑧~⑫ 那五条腿）。

## ② 键形态与表里没有的字段

`StringTool.getHuiZhangStageUpconfig(int(徽章id))`（`StringTool.as:319-323`）拿的是**去前导零的十进制 id**，
`数据/装备打造.json` 的 `huiZhangStageUp` 键就是 `"1410001"…"1410010"` ⇒ 查表前必须 `str(int(八位id))`。

十行全表只有两个字段：`{needItemId, needItemCnt}`（1410001 要 `13200000`×1、1410002 要 `13200001`×1…）。
**没有 `needMoney`** ⇒ `upgradeEquip:232` 那句 `this._configInfo.needMoney > API.dataCenter.cocoNuts`
是 `undefined > number` = **恒 false**，金币这一闸**实际不存在**，别自己加。

## ⑤ 页0 的成功/剩余两格**只有 2317 那一帧**填得上

```

  ItemChangeProcessor.handleHuiZhangStoneMergerResponse:20-43 → 读四个 int
  Client.onHuiZhangStoneMergeResponse:10020-10023
```

⇒ 我们以前**没有这一帧的消费者**，用户看到的"没有显示打造成功的产物"就是这两枚空格。
现在 `功能窗口._on_item_change_result` 认出 `kind == "badge_stone_merge"` →
`徽章打造窗.收石合成回帧(帧)`（存进会话级 `_石合成结果`、同帧清 `_投料[0]`），
后面的 `_refresh_current()` 重渲染时由 `刷新合成结果格` 摆出来。

另外两处清这两格，都照抄：`dropItemHandler:76-77`（**落新料先清上次的结果**）与
`backItemToEquip:275-276`（**取出也清**，整支 `:269-281`）。

页1 **没有**专属回包：`requestStageUpHuiZhang` 的子命令 27 只换背包增删 + 属性帧，
成品靠 `ITEM_DATAS_CHANGED` → `BadgeComposePane.itemDatachanged:241-255` → `updateView()` 重刷。

## ⑥ 悬停详情框：五枚格全是 `SimpleItemCell` ⇒ 每枚都挂 `MToolTipItem`

`SimpleItemCell.as:220` 三参调用（**不带**"跟身上那件比"那个开关）⇒ 本窗的提示框**只有一列**；
分发照 `MToolTipItem.as:73-109`：`EqpData`（徽章）→ `装备提示框`，其余（打造石 / 石产物）→ `物品提示框`。
工程走共用的 `组件/格子提示框.gd`；场景里那些格是 `NinePatchRect`、皮件 `mouse_filter = 2`（IGNORE），
⇒ 接线前必须抬到 **PASS**（同 `功能窗口._接打造提示:4020-4028`），两套框场景没烘 ⇒ 运行期建
（口径同 `福袋窗._建提示框`，`.tscn` 是 SPEC 生成物不许手改）。

## 已知偏离（本轮记下、没动）

1. `装备打造表.拥有数` 只返回**第一摞**的件数，原版 `isBagExistItem` 是**同 id 全摞相加**
   ⇒ 同一枚石分两摞放时，本窗（以及 10+ 处调用它的打造页）会比原版更早判"不够"。
   改它要连着审所有调用方，另开一轮。
2. `ItemCaiLiaoBox.buyHandler:45-54`（点材料盒那格跳**现金商城**）与
   `StoneComposePane.validateItem:104` 那句顺带的 `requestHuoDong_activeList()`（1809:0）未移植。
3. 切页签时原版会 `showView()` → `backItemToEquip()` 把成功/剩余两格清掉；本工程 `_石合成结果`
   是会话级、跨页签留着（`_宝石合成结果` 同口径），换来的是"回帧刚到账就被重渲染抹掉"不再发生。
