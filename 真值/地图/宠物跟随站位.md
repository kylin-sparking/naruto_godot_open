# 出战 / 附身两只宠物的站位、水平线与跟随速度（#66 §3.241 + 2026-10-24 报修 §3.257）

用户 2026-10-21 报修 4：**「附身、出站的两个宠物距离间隔还是太近，有重叠」**（10-18 已经报过一次同一件事）。
用户 2026-10-24 又报两条：**1.1「宠物移动和人物不是一个水平线」**、**1.2「宠物移动速度，随人物速度提升而提升（比人物略微慢一点）」**。
本页只写一件事：**原版这两只到底靠什么分开、本工程落在哪一行、偏离在哪、还有什么没查**。

数据源钉死：`<原版目录>\map_extract\out\mainlib_as\scripts\com\mxw\`。

## ① 原版只有「停止阈值」，压根没有「固定偏移」

| 事 | 出处 | 内容 |
|---|---|---|
| 折叠跟随的全部逻辑 | `PetController.as:262-299`（`movePetFold`） | `var dx = 主人.x - 宠物.x`；`:271` **`if (abs(dx) < _follow_xDis)` → `stopPet()` 原地站住并 return**；`:285-293` 否则按 `walkSpeed` 朝主人走。没有一行写「宠物在主人左边 N 像素」。 |
| 朝向 | `:269-270` | `pet.direction = dx > 0 ? RIGHT : LEFT` —— 朝向跟着"主人在哪边"，不是固定朝左。 |
| 基类默认阈值 | `PetController.as:31` | `_follow_xDis = 150` |
| **出战**阈值 | `AttackPetController.as:24`（构造 `:21-25`） | `_follow_xDis = 200` |
| **附身**阈值 | `FuShenPetController.as:6-10` | 构造里 `_follow_xDis = 100`；`tick` 只有 `movePetFold` ⇒ 附身**只跟走、不出手** |
| 两态同屏 | `PetHandler.as:486-499` | 自己的宠物按 `param2`（`isAttackPet`）分流：`true` → `_attackPet` + `AttackPetController`，`false` → `_fuShenPet` + `FuShenPetController` ⇒ **两只同时在场是原版行为** |
| 出生坐标 | `PetHandler.as:430-432 / :474-475` | `MapDataHelper.getPointOnFootholdBelow(PetSpawnInfo.position)` ⇒ 第一帧站的是**服务端给的那个点**（不是主人旁边算出来的） |
| 换平台 | `PetController.as:50-58`（`needSeachPath`）+ `:301+`（`beginPath`） | 主人和宠物 `floor` 不同 ⇒ 用 `PathFinder` 寻路走过去；寻不到路径 → `moveToTarget()` |
| 拉回 | `PetController.as:94-97` + `:148-167` | 没有目标且 `abs(dx) > 500` 或 `abs(dy) > 500`（`MAX_RANGE`）⇒ 直接把宠物 `setPosition(主人.x, 主人.y)` + 闪光特效 + `requestPetEffect(uniqueId, 0)` |

**结论**：原版两只宠物分开站，是**两个阈值之差涌现**出来的 —— 主人朝一个方向连走时，出战那只停在"距主人略小于 200"、
附身那只停在"略小于 100"，**稳态间距 100**。没有任何代码写「隔 100px」。

## ② 本工程：`脚本/角色/宠物伙伴.gd`

| 落点 | 内容 |
|---|---|
| `const 偏移_出战 := -200.0` / `const 偏移_附身 := -100.0`（`:27-28`） | 把两态的 `_follow_xDis` 当作**稳态站位**来落；相对主人、按朝向镜像（`_横向偏移() * _朝向()`） |
| `_process:88-121` | `目标x = 主人.x + 偏移 × 朝向`，`move_toward(_跟随速度() × delta)`，`> 瞬移距离 420` 直接吸过去；**只在 `距离 > 8.0` 时才走** ⇒ 每只最多停在理想位前 8px（门里的"死区"就是它） |
| `:107` 的脚点 | `目标 y = _地面y`，**不减任何偏移**（§3.257 修 1.1）。以前写的是 `_地面y - 18.0`，那 18 像素没有出处：`原始动画精灵.gd:264-266` 已经 `_sprite.position = -origin` ⇒ **节点 y 本身就是 flash 注册点（脚点）**，和主人同一个口径（`玩家.gd:800` 命中盒也以施法者脚点为原点）。再减一次就是把整只宠物提到半空，视觉上"宠物和人物不是一条水平线" |
| `_跟随速度():152-160`（§3.257 修 1.2） | **主人现值 × 0.9**。主人的 `move_speed` 由 `玩家.gd:197-201 应用移动速度属性()` 按服务端 `player_stats.move_speed` 现算（`跳落.走路速度()` = 原版 `Physics.WALK_SPEED × walkSpeedFactor`）；取不到（假主人 / 属性帧未到）退回 `基础跟随 125`（`Physics.as:8`）。以前是死数 245 ⇒ 主人 175 时宠物比人快、主人吃到加速反超 245 后宠物掉队 |
| `_process:72-78` 的地面采样点 | **取主人 x**，不取宠物自己的 `目标x`。偏移 54 时两者同层看不出问题；抬到 200 之后 stepped 地图会跨一级台阶 ⇒ 按 `目标x` 采会让宠物顺台阶滑下去。原版由 `needSeachPath`(`:50-58`) + `beginPath`(`:301-311`，目标点 `主人.x, 主人.y - 10`) 用 PathFinder 把宠物带上主人的平台，本工程不寻路 ⇒ 直接把"主人那条地面"当它的地面 |
| `_地面高度:162-177` | 主人腾空（`on_ground=false`）时返回上一帧地面 y ⇒ "不踏空"（10-18 那三条硬要求之一，未动） |
| `_try_attack:215-272` | **检索参照 = 主人坐标**（不是宠物自己），半径 145、竖直 90 都没动 |
| `_build_visual:179` | `_sprite.scale = 1.15` ⇒ 一帧立绘盒宽 = 47 × 1.15 ≈ **54** |

### 有意偏离（都写在代码注释里，别当 bug 改回去）

1. **固定偏移代替「阈值内停止」**：移植没消费服务端出生 x（`后端连接.gd:4286` 的 `pet_spawned` 一个接收者都没有）。
   照搬原版的纯阈值模型，两只起步都贴着主人 ⇒ **站着不动时永远重叠**，用户报的就是这个状态。
   所以取"稳态位置 = 各自阈值"，间距与原版稳态**同值 100**。
2. **选敌参照取主人、但不为目标寻路**：原版目标本来就是主人的（`petTarget`），参照改成主人 ⇒ 出战那只被推到身后
   200px 也不影响挂机打怪；缺的是 `fireTo` 的 `movePetToPoint`（射程外走过去），本工程只在射程内出手。
3. **地面按主人那条采、不给宠物跨层寻路**：原版会 `PathFinder` 把宠物找上主人的平台（找不到就 `moveToTarget` 直接搬到主人点）；
   本工程把"主人脚下那条地面"当成宠物的地面 ⇒ 宠物永远与主人同层站，代价是它可能"悬空横穿"一级台阶的上方（看不出来，因为立绘贴地）。
4. **跟随速度取主人的 0.9 倍**（§3.257，用户 2026-10-24 点名要"比人物略微慢一点"）：原版是**等速**（同一个 `walkSpeedFactor`
   推给三个对象，见 ④）。0.9 这一档带来的代价写在 ⑤ 第 6 条，不要把它当成"移植漏了 factor 同步"改回 1.0。

## ③ 数字核对（重叠为什么会发生）

* 立绘：`素材/角色动画/宠物/宠物_00000101/Pet_00000101.swf_*_Pet_00000101_stand0_*.png` 四帧宽 **45 / 43 / 46 / 47**，
  `scale 1.15` ⇒ 盒宽 **≤ 54.1**。
* 旧值：`|−54 − (−100)| = 46 < 54.1` ⇒ 两个立绘盒**必然相交** —— 这就是"还是太近、有重叠"。
* 新值：间距 100 ⇒ 净空 100 − 54.1 ≈ **46** ⇒ **立绘不叠**（用户报的是立绘）。
* 名牌：`RoleNamePane.as:110-113`（`PanelWidth = textWidth + 10`）+ `:131`（`_bg.x = -PanelWidth/2`）⇒ 文字**以宠物 x 居中**。
  本工程实测（12px 宋体，`get_string_size`）「一阶忍犬(普通)[出战]」宽 **120** ⇒ 半宽 60，两只半宽和 **120 > 100**
  ⇒ **名牌边缘相切约 20px**。⚠ 这条**不是移植引入的偏离**：原版同样是 120 宽的居中牌子 + 100 的稳态间距，
  一样相切。门里只钉"这个事实别漂"（半宽和落在 100~125），判据不卡它 —— 真要改得先定夺（换行 / 缩字 / 分侧站）。

## ④ 水平线与跟随速度（§3.257，用户 2026-10-24 报修 1.1「宠物移动和人物不是一个水平线」/ 1.2「宠物移动速度，随人物速度提升而提升（比人物略微慢一点）」）

**脚点口径（1.1）**：原版宠物的 y 由它自己的物理/foothold 得出（`AbstractPhysicObject.as:602/813/850`），
和角色一样是"注册点落在落脚点"。本工程这个口径本来就对 —— `原始动画精灵.gd:264-266` 把每帧立绘按 flash 的
`origin` 抬过了，所以 `_process` 里那句 `_地面y - 18.0` 是**多减的一次**（无出处、无门钉），
两只宠物因此常年浮在主人脚下 18px 之上 ⇒ 修法是直接取 `_地面y`。`configure` 的初始落点同一句一起删。

**速度口径（1.2）**：原版**宠物与主人严格等速**，而且不是"各自算一次"，是**同一个 factor 推给三个对象**：

| 出处 | 内容 |
|---|---|
| `Physics.as:8` / `:16` | `WALK_SPEED = 125`、`CLIMB_SPEED = 125`（本体常数） |
| `AbstractPhysicObject.as:850` | `walkSpeed = Physics.WALK_SPEED * walkSpeedFactor` —— `movePetFold` 走的正是这个 `pet.walkSpeed`（`PetController.as:287-288`、`AttackPetController.as:118`） |
| `DataCenter.as:2783-2790` | 收到 `WLK_SPEED`：`getWalkSpeedFactor()` 之后**同一个值**依次写 `player` / `attackPet` / `myFuShenPet` |
| `SkillHandler.as:967-974`、`:1273-1280` | 技能加/减速同一条：三个对象一起写 |
| `PetHandler.as:488` | 宠物**刚生成**时立刻继承当前 factor ⇒ 不会出现"主人已加速、新宠物还是 1.0" |

⇒ 原版的语义是"主人多快、宠物多快"，**没有"略慢"这一档**。本工程按用户要求取 `× 0.9`（`跟随比例`），
是**有意的第三条偏离**；主人吃满加速时宠物会以 10% 的速度差被拖远，到 `瞬移距离 420` 才整只吸回（原版 500 拉回、带闪光）。

| 门钉的位置 | 判据 |
|---|---|
| `测试/宠物跟随重叠回归测试.gd` ① | 死数 245 不得残留；`跟随比例 := 0.9`、`基础跟随 := 125.0`、`Physics.WALK_SPEED` 与 `DataCenter.as:2783` 两处出处必须在注释里；`_地面y - 18.0` 不得回来 |
| ② | 两只脚点与主人 `y` 完全相等（300 = 300），横向仍是 100 / 200 / 100 |
| ⑥ | 台阶那一层：宠物贴主人那条地面 ⇒ `y = 300`（以前烘的是 282） |
| ⑦ | 把 delta 直接喂进 `_process`：主人 175 ⇒ 一帧追 **15.75**；主人 300 ⇒ 同一帧追 **27**；主人速度没到账 ⇒ 退回 **112.5** |

变异对照（三条，都逐条变红再 `cp` 还原复绿，md5 与还原后字节一致）：把 `- 18.0` 加回去 ⇒ ①/②/⑥ + ⑦ 共 5 红；
`跟随比例` 改 1.0 ⇒ ① + ⑦ 三条共 4 红；`_跟随速度()` 改成不看主人属性 ⇒ ⑦ 的 175/300 两条红、兜底那条仍绿（耦合确实被钉住）。

## ⑤ 未收口（如实）

1. **服务端出生坐标仍未消费**（`PetSpawnInfo.position` → 原版 `getPointOnFootholdBelow`）⇒ 上线时宠物一律从"主人身后阈值处"
   起步，不是服务端那个点。要修得先接 `pet_spawned`。
2. **拉回口径**：原版 `MAX_RANGE = 500` + `moveToTarget` 带闪光特效与 `requestPetEffect`；本工程 `瞬移距离 = 420`、无特效。
3. **出战不为目标寻路**（`fireTo:37-39` 的 `movePetToPoint`、`PICK_DIST = 200` 捡东西整条没移植）。
4. **跨平台跟随**：原版 `beginPath` 走 `PathFinder`（含跳、爬梯）；本工程只有"竖直吸附 120px 直接吸到地面"。
5. 朝向语义只落到"左右镜像站位"，原版 `pet.direction` 还决定美术朝向 —— 本工程美术朝向在 `_update_animation:91-93`
   按位移算，两者在"主人不动、宠物在走"的短暂瞬态里可能不同步。
6. **0.9 倍带来的拖后**：主人**连续朝一个方向**跑时，宠物以 10% 的速度差被越拖越远（175 时速差 17.5px/s ⇒ 从 200 拖到
   420 约 12.6 秒），到 `瞬移距离` 才整只吸回。原版等速 ⇒ 间距恒定、不会触发拉回。这条是用户点名的偏离的**直接代价**，
   实测若嫌刺眼，两个方向可选（都要先问过用户）：把比例抬回 1.0（回原版），或给"超出稳态偏移"那段补一段追击加速。
