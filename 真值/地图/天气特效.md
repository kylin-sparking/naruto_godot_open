# 天气地图特效（雨雪雾）—— 服务端只发一个类型号，**画什么全是客户端定的**

用户 2026-10-25 报修 6：「天气对应的地图特效没有实装」。
详细过程与门账见 `开发记录（本地）` **§3.274**；本文件只留**可抄的真值**和**有意偏离**。

## ① 数据通路（移植侧本来就通，缺的只是消费者）

| 环节 | 出处 | 说明 |
|---|---|---|
| 服务端下行 | opcode **1570** `ReceiveOpCodes.CHANGE_WEATHER` | 只带一个 `天气类型` int，**不带素材号、不带浓度、不带地图名单** |
| 原版入口 | `Client.as:3790 onWeatherChange(param1:int)` | 先拿它算宠物属性（`PetAddValue` 撤了再加）、`setWeatherBuff`，最后才 `applyWeatherVisual` |
| 移植侧 | `后端连接.gd weather_received` → `游戏会话.hud_state["weather_type"]` | 早就通了 —— `头像面板` 那枚天气状态图标一直在吃它 ⇒ 用户看到"图标变了、地图上什么都没有" |
| 消费者 | `脚本/地图/天气特效.gd`（本轮新增） | 由 `地图根节点._ready()` 用**代码**挂上（见 §⑤） |

## ② 三张地图名单（`Client.as:3847-3849` 逐字搬运）

`applyWeatherVisual` 一进来就把当前地图号 `API.world.map.data.id` 算成三个布尔：

| 名单 | AS3 变量 | 内容 | 作用 |
|---|---|---|---|
| **A 静态装饰可见** | `_loc12_` | 109010000 / 109020000 / 109040000 / 110010000 / 110020000 / 110040000 / **111010000~111040000** / **112010000~112040000** | 地图里预置的 `nature_16/17/18` 装饰物 `visible = _loc12_`（`:3876`） |
| **B 永远不放动态** | `_loc13_` | 107010000 / 107020000 / 107030000 / **108010000~108040000** / 110030000 / **112010000~112040000** | `:3881` **直接 return**（连雪都不放） |
| **C 只跳雪** | `_loc14_` | 109010000 / 109020000 / 109040000 / 110010000 / 110020000 / 110040000 / **112010000~112040000** | 条件 `param1 >= 4 && param1 <= 6` 时才 return ⇒ **雨雪雾照放，只跳雪** |

**要命的三个细节**（都是量出来的，别"顺手统一"）：

1. **范围端点只到 `××40000`，子图不在名单里。** `112040002` 烘了 `nature_16/17/18` 装饰物，
   但 `112040002 > 112040000` ⇒ `_loc12_` 为假 ⇒ 原版在那些图上是把装饰**隐藏**，不是显示。
2. **A 有 `111010000~111040000`，B/C 没有。** 111 那族：装饰会亮，但**不禁止**动态天气。
3. **B 与 C 的差**只有 107010000/107020000/107030000/108010000~108040000/110030000 那几个：
   B 是"整张图什么都不放"，C 是"只跳雪"。写成一个名单就错。

## ④ 雪是**代码画的圆点**，不是素材（`Client.as:3960-4066`）

`startWeatherSnowVisual(类型)` 在 `API.world` 上挂一个 `weatherSnowLayer` Sprite，逐片画：

| 参数 | 类型 4 / 5 / 6 | 出处 |
|---|---|---|
| 片数 | **38 / 68 / 104** | `:3980` |
| 半径 | `0.9 + rand × (大雪 ? 3.6 : 2.8)` | `:3986` |
| 实心 | `beginFill(0xFFFFFF, 0.58 + rand×0.36)` | `:3988` |
| 十字 | **半径 > 2.3 才画**：`lineStyle(0.6, 0xFFFFFF, 0.48)`，两臂长 `r × 1.35` | `:3991-3997` |
| 横速 | `-0.22 + rand × 0.44` | `:4004` |
| 纵速 | `0.65 + rand × (0.9 / 1.35 / 1.9)` | `:4005` |
| 摆幅 | `0.12 + rand × (大雪 ? 0.62 : 0.42)` | `:4006` |
| 相速 | `0.018 + rand × 0.035` | `:4008` |
| 自旋 | `-0.45 + rand × 0.9`（Flash `rotation` 单位是**度**） | `:4009` |
| 风 | `sin(帧计数 × 0.015) × (大雪 ? 0.35 : 0.18)`，**全场同一个加数** | `:4025` |
| 回绕 | `y > H+24` ⇒ `y = -24 - rand×H×0.12`、`x = rand×W`；`x < -30` ⇒ `W+30`；`x > W+30` ⇒ `-30` | `:4035-4047` |

节拍：`onWeatherSnowFrame` 挂在 `ENTER_FRAME` ⇒ **60fps**（`Engine.as:13 STAGE_FRAME_RATE = 60`）。

## ⑤ 节拍与落点

* **帧动画 10fps**：`Animation.as:47-50` 的 `delay` 恒 100ms；`FrameQueueAnimation.as:55-57` 按帧取
  `_crtDelays[_frame]`，而 `:119` 是 `getFromObject(_loc1_,[帧,"delay"]) || 100`。天气件是
  `MapObject.fromObject` **现造的**（`:3905-3915`，帧表里没有 delay）⇒ 取默认 **100ms**。
* **落点**：动态天气件是挂在 `API.world` 的 `MapObjectRender`，`"x":25, "y":1`（`:3910-3911`），
  `alpha` 就是 §③ 那一档（`:3919`）。
* **层序**：`:3920 API.world.addChild` + `:3923 _loc2_.push(_loc3_)` 把 render **推到 `objectRenders` 末尾**
  ⇒ 画在物件之上、**角色之下**（原版雨在人身后）。

## ⑥ 有意偏离（4 条，都过用户口径：不为"像"而牺牲能跑）

| # | 原版 | 本机 | 为什么 |
|---|---|---|---|
| 1 | 挂在**世界坐标 (25,1)**，随相机滚 | 钉在**视口**上，屏幕 (0,0) 画素材 (25,1) 那一块 | 与原版"相机在该图左上角时看到的那一格"**逐像素相同**，但不会走到 x>5285 雨就没了（那张图宽 5260）。 |
| 2 | 天气件在**角色之下** | 整层在角色**之上**（CanvasLayer 10：世界 0 < 天气 10 < 小地图 20 < 聊天/技能 100） | 移植侧角色不在同一个 CanvasLayer 里，插不进"物件之上、角色之下"那一档。 |
| 3 | 20 帧整张进显存 | **从磁盘读原图、只裁视口那一块**再烘 `ImageTexture`；超预算等比缩小；**后台线程解图、主线程上传** | 素材 `.import` 是 `compress/mode=0`（无损 RGBA8）⇒ 整叠 nature_18 是 **745MB 显存**。裁 960×560 后 20 帧 ≈ 43MB。 |
| 4 | 波之国纪念雪常开 | `有纪念雪()` **当前恒假** | 判据查 `CharacterConfig.mapData._waveMemorialSnowMapIds`（`Client.as:3810-3823`），`mapData` 是原版 `1283` 的 **AMF 二进制**字段，文本协议不运 ⇒ 夹具发来的 1283 没这段。**不自己编地图号**（编了就是把客户端自造的名单当真值）。 |

## ⑦ 挂接方式

`地图根节点.gd` 用 **`preload` + 代码建节点**，不写进 `.tscn`：

```gdscript
const WEATHER_SCRIPT := preload("res://脚本/地图/天气特效.gd")
func _挂天气特效() -> void:      # _ready() 末尾
    if get_node_or_null("天气特效") != null: return
    var 节 := WEATHER_SCRIPT.new()
    节.name = "天气特效"
    add_child(节)
```

⚠ 代价（本轮踩过）：改 `地图根节点.gd` 会让 **174 张烘焙场景的 `bake_hash` 全部失配** ⇒
必须先 `"$G" --headless --path . --script res://开发工具/烘焙当前地图.gd -- --all` 重烤，
再跑全量门。否则 `地图烘焙回归测试` 红，且**烘了邀请托盘的 HUD 会连累别的门**
（`交易页回归测试` 在全量里红 5 条、单跑绿 168 —— 就是这个）。
同一份输入清单里还挂着**四枚 HUD**（`头像面板` / `小地图面板` / `聊天面板` / `技能面板` 的
`.gd` + `.tscn`）⇒ 改 HUD 一样要重烤（2026-10-28 全量红 174 条「陈旧」就是这么来的：
`48535d8`（§3.293 VIP 摘除）动了 `头像面板`，之后几轮都没烤）。

## ⑧ 服务端：天气**按大地图分池**（2026-10-28 用户点头的偏离原版，记账见 §3.303）

原版**全服只有一条天气**：`Buff.Weather` 权重 晴 34 / 雨·雪·雾三族各 11（合计恒 **133**），每 5 分钟
重摇一次，所有图同一个类型；`GameDataCatalog.weather_type_for_map()` 是个恒等函数（`del map_id`）。

用户 2026-10-27 口径（逐字见 §3.303）：每个大地图 + 其子图**同一个池**、池与池之间**有差别但别过大**，
没有对应大地图的散图**自己一个池**，副本**统一晴天**。⇒ 移植侧改成按池摇，`weather_type_for_map`
**已删除**（留着就是第二份"全服一条"的化身，别哪天"改回全局一条"）。

| 项 | 现规则 | 守住的原版口径 |
|---|---|---|
| 池 | `weather_pool_key(图)` = `图 // 10000 * 10000`，**它在地图表里 ⇒ 它和所有子图同池**；不在 ⇒ 该图自己是池 | 「大地图 + 子图同天气」 |
| 权重 | `weather_pool_weights(图)`：**大地图点名 `WEATHER_POOL_BY_BIG_MAP` → 区域 `WEATHER_POOL_BY_AREA` → 副本底色 `WEATHER_POOL_DUNGEON` → 原版默认 `WEATHER_POOL_DEFAULT`**；副本 = 区域号 ≥400 **或** `WEATHER_POOL_DUNGEON_BIG_MAPS` 点名（跨服战场/竞技场挂在区域 100 下面） | `WEATHER_POOL_DEFAULT = (34, 33, 33, 33)` **就是原版**（晴 34、其余九档各 11） |
| 量纲 | 一律四族 (晴, 雨, 雪, 雾)、**每池合计恒 133**、族内恒 3 档 ⇒ `weather_type_weights(图)` **恒等于 133** | 与原版同分母，任何图概率可逐条对照（原版晴 34/133 ≈ 25.6%） |
| 区间 | 野外最高 木叶本村 `(70,24,8,31)` ≈ 晴 52.6%、最低 雨隐村本村 `(10,76,14,33)` ≈ 晴 7.5%；波之国本岛 `(20,56,5,52)` 雨+雾 ≈ 81%；副本底色 `(120,5,3,5)` ≈ 晴 90%（另一条口径，不受"差别不过大"管） | 「做一定差别，但差别不能过大」 |
| 族内 | `weather_family_split(档)` 均分、**余数给最轻那档** ⇒ 小雨 ≥ 中雨 ≥ 大雨 | 原版族内三档 ratio 全相等（11） |
| 种子 | `"%d:%d" % (池号, 期号)` 的**字符串** | 同池同图同刻恒等；两整数相乘会让「池 100 第 3 期」撞「池 300 第 1 期」 |
| 发报 | `_refresh_weather` 按**当前这张图**的池发；GM 指定天气**压过池**；「天气有变」公告只在**换期摇出结果**时发（走进另一张图只发 1570，不发公告） | 客户端仍只认一个 `天气类型` int（协议零改动） |

`weather_type_for_map()`（原版那条恒等函数）**已删除**，别"改回全局一条"。
