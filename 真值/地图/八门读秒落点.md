# 八门贯通读秒（`_maiNum`）—— 原版把 33 px 的数字**垂在头顶下面**，我们改成落在头顶之上

用户 2026-10-22 报修 2：「八门，贯通穴位成功，读秒动画显示的位置有点偏下，应该在人物上方，
现在在人物头部的位置」。

查下来这**不是漏抄常数**：上一版 `脚本/角色/玩家.gd` 确实少抄了一个 `+3`，但 3 px 撑不起这句报修。
真正的账是原版自己就把数字挂在头上 —— 那一行 `y` 钉的是数字画布的**顶边**，而素材的墨迹贴着画布**下沿**。
所以本轮按**有意偏离**处理（先例：§3.203 商城删充值键、§3.236 堆叠上限抬到 9999、`真值/窗口/字体与整像素落点.md`）：
把整串的**底边**摆到原版顶边那个位置 ⇒ 数字整体落到头顶之上，`+3` 与间距 `5` 两个常数照旧保留。

## ① 原版的竖直账（逐行读，不是推的）

| 出处 | 原文 | 说明 |
|---|---|---|
| `Character.as:293-329` | `tickMaiDelay(param1)` | 每秒 `Math.ceil(_maiLastTime/1000)` 变一次才重建，**换秒才挪一次**（不是逐帧） |
| `Character.as:310` | `this._maiNum = API.characterHandler.getColorNumMai(_loc2_)` | 造数字串 |
| `CharacterHandler.as:916-919` | `return new ColorNumber(param1, ColorNumber.NoBlue0)` | 蓝色那组；**没有 `tick()`** ⇒ 不上浮、不淡出 |
| `Character.as:311-312` | `addChild` → `adjustLayer()` | 排层序（见 §③） |
| `Character.as:313` | `this._maiNum.y = -this._crtCharHeight - 5;` | **唯一一行竖直落点** |
| `Character.as:2380` / `:2508` | `_crtCharHeight = animation.charHeight + 3` | `afterTick()` 里逐帧刷（`:2508` 是换帧那条） |
| `CharacterSprite.as:1538-1568` | `render()` 里 `this._crtCharHeight = _loc3_.height`；`ci.setOrigin(origin)` | `charHeight` 就是**当帧 body 位图像素高**，注册点来自帧数据的 `origin` |

`ColorNumber` 侧（`com/mxw/skills/effects/num/ColorNumber.as`）：

* `:42` `dicts = [null,"0","1",...,"9","miss"]` ⇒ **数字 d 用第 `d+1` 帧**（本工程同款偏移，别再抄成 `d`）。
* `:54-72 addCell()` `_loc3_.x = 上一枚的 right + gap - 本枚.getRect(this).left` ⇒ 按**墨迹左缘**接 x，`gap=0`。
* `:101` `this.container.x = -this.container.width / 2` ⇒ 末了整串**左右居中**。
* `:74-102 draw()` 从头到尾**没有一行写 y** ⇒ 竖直落点完全由元件自己的注册点决定。
* `:110-118 tick()` 只做上浮+淡出，且**只有伤害数字那条链调它**（`getColorNumMai` 不调）⇒ 读秒是死的。

## ② 素材实测：墨迹贴下沿 ⇒ 注册点在顶上，数字往下长

`Effect_colorNumber.swf`（`2.2.3/www/act_web_nya_208_isolated/swf/Effect/`，CWS 66167 B，
SymbolClass 里 `NoBlue0 = chid 174`）导出的 `素材/特效/Effect_colorNumber/NoBlue0/1..10.png`：

| 组 | 画布 | 墨迹水平 | 墨迹竖直 | 本工程 `数据/特效.json` 的 `原点` |
|---|---|---|---|---|
| `NoBlue0`（读秒用） | **31×33**（十帧全一样） | 大致居中 | **顶空 0~1 px、底空 0** ⇒ 贴下沿 | 每帧 `[0,0]` |
| `NoRed0`（伤害那组） | 98×38 | x 34..65（居中） | 同样贴下沿 | `[0,0]` |

把两件事合起来：`_maiNum.y = -(位图高 + 3) - 5` 钉的是这枚 33 px 画布的**顶边**，
而墨迹从顶边往下长满 33 px ⇒ **原版显示效果是数字压在头顶到额头之间**（头顶 ≈ `-origin.y` ≈ `-位图高+1`）。
`+3` 只把顶边抬高 3 px，改不动"垂下来 33 px"这件事 —— 这就是"偏下"的全部来源。

## ③ 层序：读秒盖在名字牌之上

`Character.as:1626`（`adjustLayer` 的排布数组）里 `_maiNum` 排在 `_namePane` **之后** ⇒ 数字画在名字牌上层。
名字牌自己的落点在**脚点下方**（`:1484 this._namePane.y = this._namePane.paneHeight - 3`），
所以把读秒往上抬**不会**跟名字牌撞 —— 这条是"敢抬"的前提。
本工程对应 `_八门读秒节点.z_index = 2000`（同 `玩家.gd` 头顶特效那批的写法）。

## ④ 本工程落点算式

```gdscript
# 玩家.gd
_八门读秒节点.position = Vector2(0.0, -高 - 八门读秒抬 - 八门读秒距 - _八门串高)
#                                    ↑当帧贴图高   3.0（AS3 的 +3） 5.0（AS3 的 5）  整串墨迹高（=画布 33）
```

`-高-抬-距` 就是原版那条顶边 y；再减 `_八门串高` ⇒ **同一个数值从"顶边"改口成"底边"**。
实测（stand 第 0 帧：贴图高 123、原点 (39,122)）：底边 `-131.0`，头顶 `-122.0` ⇒ 缝 9 px，
墨迹盒 `[-164, -131]` 整个在头顶之上。

两条例外口径：
* **量不到高 ⇒ 不动**（`if 高 <= 0.0: return`）—— 同 `玩家.gd` 手里剑箭头那条（`:968` `_更新头顶挂件位置`、守卫在 `:976`）的口径；
  按 0 算会把数字甩到身上，而原版压根没有"高为 0"的这一帧（`render()` 走 `_waitingRes` 分支时不画）。
* **跟帧**：`_process` 每帧调 `_更新八门读秒位置()`，站立/跳跃/爬绳贴图高不同 ⇒ 数字跟着贴头顶，
  只在换秒那一刻重建串（跟原版 `:302` 的 `if(this._nowColorNumber != _loc2_)` 一致）。

## ⑥ 门与反向对照

门：`测试/八门读秒落点回归测试.gd` —— **绿 30 红 0**，`--headless` 能跑（纯算几何，不截屏）。
期望值只有手抄字面量 `3`、`5` 和素材的 `31×33`，其余（贴图高、头顶）跟着真实帧实测走。

| 变异 | 改什么 | 结果 |
|---|---|---|
| M2 | 去掉 `- _八门串高`（＝退回原版锚法，复现报修） | **5 红**：底边 / 头顶之上 / 留缝 / 换秒底边 / 跟回公式 |
| M1 | `八门读秒抬` 3.0 → 0.0 | 3 红（底边、换秒、跟回公式） |
| M1b | `八门读秒距` 5.0 → 0.0 | 3 红（同上三条） |
| M5 | 串高取**宽**而不是高 | 3 红（同上三条） |
| M3 | 摘掉 `if 高 <= 0.0: return` 守卫 | **1 红**（第 6 条：量不到高不许按 0 甩到 -41） |
| M4 | `z_index = 2000` → `-1` | **1 红**（第 8 条层序） |

M1/M1b/M5 打在同一组判式上不是重复：那三条（③底边、⑤换秒、⑦跟回公式）是**同一条算式在三个时刻的采样**，
少任何一项常数都会三处一起红 —— 反过来，单点改动不会串咬到"头顶之上"和层序那两条。

⚠ 日后要还原成原版观感：把 `_八门串高` 当 0 用（即 M2 那条写法）就够了，两个常数不用动。
