# 头顶那排状态图标 —— 每格的框与图标各是什么尺寸、谁缩放谁不缩放

用户 2026-10-21 报修 2.2「人物形象下的写轮眼境界小图标，有点太小了」。
查下来不是"美术把图画小了"，而是**两条 AS3 线在移植时抄串了**：那排图标里每一枚的缩放口径其实不一样。

## ① 共用的骨架：每格 = 20×20 底框 + 里面一枚图标

`Character.as:706-718`（`insidePositionStatusIconPane`）：`getChildAt(i).x = 20 * i`，整排
`_statusIconPane.x = -10 * 数量`；`y` 在 `:1497-1512` 取**称号牌 / 家族牌 / 名字牌里最下面那张非空牌**
（`:1501` `_statusIconPane.y = _namePane.y`、`:1505` `= _banghuiPane.y`、`:1510` `= _chenghaoPane.y`）。
⚠️ 取的是那张牌的**原点**，不是"文字墨迹底"—— 这两个字差了 4 个像素行，见下面 ⑤（用户 2026-10-22 报修 8）。
底框每格都是同一张 `Effect_CharStatus_Kuang`（20×20，与家族族旗同款）。

本工程对应 `脚本/地图/地图实体.gd` 的 `_排状态图标排()`：`状态图标块 = 20.0`、
`左 = -10 * 数量 + 20 * 序号`，图标额外加一份"内缩"把它摆进框里。

## ② 三枚图标各自的真值（关键：**不是同一个比例**）

| 图标 | AS3 出处 | 偏移 | 缩放 | 素材原尺寸 | 落进 20 的框里 | 本工程内缩 |
|---|---|---|---|---|---|---|
| 家族家徽 | `Character.as:1449` | — | `18/34` | 34×34 | 18×18 | 1.0 |
| 忍术境界 | `setTotalSkillLevel:1890-1897` | `x = y = 10` | **`18/30`** | 30×30 | 18×18（小一圈） | 1.0 |
| 写轮眼状态 | `setXieLunYanState:2623-2643` | `x = y = 0` | **没有** | 20×20 | **20×20（撑满）** | 0.0 |

写轮眼那段的原文只有一行位置语句，整段找不到 `scaleX/scaleY`：

```as3
// Character.as:2632-2641
if(param1 > 1 && param1 <= 12) {
   _loc2_ = new UISwfMovieClipAgent("UISwf_xielunyanState_state" + param1, true);
   _loc3_ = _loc2_.mcIgnoreLoading;
   this._xieLunYanClip = new MovieClip();
   this._xieLunYanClip.addChild(InstanceManager.createInstance("Effect_CharStatus_Kuang") as MovieClip);
   this._xieLunYanClip.addChild(_loc3_);
   this._xieLunYanClip.mouseEnabled = this._xieLunYanClip.mouseChildren = false;
   _loc3_.x = _loc3_.y = 0;                 // ← 只有这一句，没有缩放
   this.addCharStatus(this._xieLunYanClip);
}
```

⇒ 眼睛**本来就和底框一样大、撑满那一格**；境界那枚才是"小一圈"的那一个。
移植时把 `18/30` 也套到眼睛上（旧注释还写「AS3 同样缩 18/30（`Character.as:2645`）」），
20×20 被压成 **12×12** ⇒ 用户看到的「太小了」。

⚠ **`:2645` 是个假引用**：那一行是 `adjustHeights()`（管说话气泡/血条的 y），
跟状态图标没关系。旧注释的"原版那个小一圈的观感"是**照着错的比例反推出来的描述**。

## ③ 范围与素材

- 画的档位 `param1 > 1 && param1 <= 12` ⇒ **2..12 阶**，1 阶和 13 阶都不画。
- 素材 `素材/界面/原版窗口/人物/血继界限/写轮眼状态/世界状态/世界状态02..12.png`，

## ⑤ 「底边」那一个字：牌原点比文字墨底低 4 个像素行（用户 2026-10-22 报修 8）

报修原文：「人物形象下面的家族名称文字与下方的家族徽章、忍术境界图标、写轮眼境界图标略微有一点重叠」。
代码里图标排的锚一直写成 `牌.position.y + _行高(牌)`（注释也照 AS3 说"取牌的底边"）——
**AS3 说的"底边"是那张牌 `bg` 盒的底边（= 牌原点），不是文字的墨迹底**：

| `RoleNamePane.as` 的账 | 行号 | 结论 |
|---|---|---|
| `paneHeight = _tf.textHeight + 10` | `:180-182` | 牌盒比文字高 10 |
| `_tf.height = _tf.textHeight + 10` | `:171` | TextField 自己被撑到同样高 |
| `_bg.y = -paneHeight` | `:122` | **牌原点 = bg 盒底边**（盒在 `[原点−paneHeight, 原点]`） |
| `_tf.y = _bg.y + 4` | `:134` | 文字盒顶 = 盒顶 + 4 |
| TextField 自带 2px 内缩 | Flash 行为 | 墨迹顶 = 盒顶 + 6 ⇒ 墨迹底（不含）= 原点 − 4 |

⇒ **牌原点比该行墨迹底低 4**；`Character.as:1486` 家族牌 `= 名字牌.y + paneHeight - 6` 同样给出
"上一行墨迹底 + 4"的行缝（`:1490/:1494` 称号牌也是 `- 6`）。所以原版三处（名字→家族、家族→称号、
末行→图标排）**都留 4 个空像素行**，而移植版把缝写成了 0 ⇒ 图标框上沿直接压在文字下沿上。

像素实测（`开发工具/_probe_头顶重叠量测.gd`，真渲染三趟：底图 / 只文字 / 只图标）：

| | 家族牌 y | 图标锚 y | 文字墨迹行 | 图标墨迹行 | 缝 |
|---|---|---|---|---|---|
| 改前 | 19.0 | 32.0 | 79–91 | 92–111 | **0 px**（紧挨） |
| 改后 | 18.0 | 35.0 | 78–90 | 95–114 | **4 px** ＝ AS3 账 |

（角色原点放在屏幕 y=60；字体 `simsun_原版.ttf`@12 实测行高 13 ⇒ 墨迹底 = `position.y + 行高 − 1`。）

实装：`脚本/地图/地图实体.gd` 新增 `const 名牌行距缝 := 4.0`（`_新建家族牌`、`_排状态图标排`
两个分支、`_刷远程境界图标` 共四处用它）；`const 世界名字行高 := 13.0` 只给"名牌节点还不存在"的
兜底分支量行高。⚠ **别拿 `称号间距补量`（5）套人物**：那条出自 `NPCSprite.as:240` 的 `- 5`，
是 NPC 功能称号的另一行算式。

门：`测试/家族页回归测试.gd`（钉家族牌行距 + 族徽/底框 y，4 手抄字面量）、
`测试/写轮眼状态图标回归测试.gd` ⑦（收起家族牌 ⇒ 整排锚回名字牌原点）、
`测试/忍术境界图标回归测试.gd`（远程那枚 y）。

五刀 `cp` 配对变异（每刀只该咬自己那条腿；跑完全部还原，产品码 md5 逐次核回）：

| 刀 | 改哪里 | 家族页 | 忍术境界 | 写轮眼 |
|---|---|---|---|---|
| `M1` | 整条缝归零（退回报修 8 那一版） | 3 红 | 1 红 | 1 红 |
| `M2` | 只摘家族牌分支的缝 | 2 红 | 0 | 0 |
| `M3` | 只摘家族牌自己的行距（徽/框跟着它一起挪 ⇒ **只有绝对判据咬得住**） | 1 红 | 0 | 0 |

## ⑥ 换样式**不许"释放再新建"**：撞名的那枚会被引擎改名成匿名的 `@Sprite2D@N`（用户 2026-09 起报修 11）

报修原文：「家族升级后，人物下方的家族徽章图标位置不对」。家族升级 ⇒ 服务端 `1552:4` 广播来新的
`flag_style` ⇒ 走 `_刷家族标示` 的"样式 A→B"这条路。旧写法是"贴图不一样就 `徽.queue_free()` + 新建同名节点"。

三件事全部**实测**在 `开发工具/_probe_同名让位.gd`（`--headless` 跑，父节点在树/不在树两趟结果一致）：

| 实测 | 结果 |
|---|---|
| `queue_free()` 当帧摘树吗 | **不摘**：`is_queued_for_deletion()` 当帧 `true`，节点仍挂在树里、仍顶着 `FamilyEmblem` |
| 同帧再 `add_child` 一枚 `name = "FamilyEmblem"` | 被引擎改名成 **`@Sprite2D@139`**（⚠ **不是** `FamilyEmblem2`：照 `FamilyEmblem2` 钉的判据变异实测**一条不红**） |
| 一帧之后按名字读 | 读到 `null`（旧件真摘了，留下的那枚已经匿名） |

⇒ 后果链：同帧后面跑的 `_排状态图标排`（`地图实体.gd:2267`）**按节点名**找块，摆的是那枚**即将被释放的旧件**
⇒ 留下那枚停在 `(0,0)`（角色脚下）；下一帧旧件真摘 ⇒ 再换一次样式又新建一枚，那枚匿名的**没人再摆位、也没人释放**
⇒ **每升一级在脚下漏一枚族徽**。位置错与节点漏是同一个根。

原版不犯这病：`Character.as:690-716` 握的是 DisplayObject **引用** + 固定优先级 `setChildIndex`，
换样式只是 `removeChildren()` 后往同一个 `_banghuiPane` 里重画，不存在"名字被将死的兄弟占着"这种状态。

实装：`_刷家族标示` 只在 `徽 == null` 时新建，样式变化**原地换 `texture`**
（同排另两枚 `_刷忍术境界图标` / `_刷写轮眼图标` 本来就是"只在 null 时建、之后原地换图"⇒ 不受此坑影响）。
`queue_free()` 只留给"退族 / 没这张图"两条**收掉后当帧不再建**的路。

门：`测试/家族页回归测试.gd` ①b（样式 1002→1003 一趟 + 回 1002），三条腿：
**不许冒出匿名活兄弟节点** / 按名字读到的那枚**不许是待释放的** / **同一枚节点 id 不变**。
⚠ 位置那几条判据在变异态**照样绿**（它们读的就是被名字找到的旧件）—— 与 ⑤ 段 `M3` 同一族盲区。

`cp` 配对变异（退回报修 11 那一版）：**3 红** = 匿名件 `["@Sprite2D@139"]` / 读到待释放的旧件 / 贴图仍是 `家徽_1002.png`；
跑完 `cp` 还原，产品码 md5 核回 `c9a2917e19980bbf1959de5ec1f9f455`。
