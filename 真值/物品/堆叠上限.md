# 一摞能装多少（`slotMax` / `stack_max`）—— 真值与那条登记过的偏离

> 2026-10-21 §3.236 建。起因是用户报修 1.2：「商城买东西，如果商城输入数量超过堆叠上限，本次仅结算
> 99 件，未多扣货币，**这一点没问题**，不过我希望把能堆叠的道具物品数量如果是 99、999 的都改成 9999」。
> ⇒ 「超上限只结算、不多扣钱」= **保留原版行为**；「99/999 抬到 9999」= **用户点名的有意偏离**。

## ① 原版真值（一个数都没改数据）

| 量 | 值 / 取法 | 出处 |
|---|---|---|
| 一摞上限 | GameData `info.slotMax` | `ItemData.as:248` `maxCount = ObjectAccessor.getFromObject(wzBigObject,["info","slotMax"])` |
| 它用来干什么 | **合并堆叠**的闸：`quantity + 增量 <= maxCount` 才并进那一格 | `DataCenter.as:1159`（`getBagPileEmptyPosition`） |
| 商城购买窗的数量上限 | `floor(余额 / 单价)` —— **不是**堆叠上限 | `BuyEqpWindow.as:249`，超了就夹 `:467-469` |
| NPC 商店那页的数量上限 | 帧里的 `buyCount` | `UI.as:2039` `_loc6_.maxCount = _loc5_.buyCount` |
| 报文类型 | 商店帧第 5 字段 `readUnsignedShort` ⇒ 上限 65535 | `ShopItem.as:11/39`；服务端同口径 `NATIVE_ITEM_QUANTITY_MAX = 0xFFFF`（`fake_flash_server.py:78`） |
| 本工程导出 | `数据/物品.json` 的 `stack_max`（`开发工具/生成数据扩展.py:169` 从 `info.slotMax` 导） | 全表分布 **1→775 / 99→1380 / 999→83 / 5000→2 / 9999→459** |

⚠️ 导出表**保持原版值**：偏离只落在代码里。哪天有人"顺手"把 `数据/物品.json` 改成 9999，
就再也对不回原版（门 ② 就是钉这条的）。

## ② 那条偏离：作者值 99 / 999 → 9999

只抬 **99 和 999** 两档；**1（装备、不可叠的东西）和 5000 原样**。9999 在 `unsigned short` 内，不动 wire 类型。

一处口径、四个闸口，**必须同表**（漏一个就表现为"买 200 只结算 99"或"客户端 999 封顶"）：

| 闸口 | 在干什么 | 落点 |
|---|---|---|
| 服务端唯一入口 | GM 发放 / 商城结算 / NPC 商店结算 / 堆叠合并全读它 | `服务端/runtime/tools/fake_flash_server.py:2075 STACK_LIMIT_RAISE_TO = {99: 9999, 999: 9999}` → `:2084 _item_stack_limit` → `:2102 return STACK_LIMIT_RAISE_TO.get(authored_limit, authored_limit)` |
| 服务端两条结算腿 | 「只结算 N 件、未多扣货币」那句就是它 | `:55771` / `:55822` `quantity = min(quantity, _item_stack_limit(item_id))` |
| 服务端两帧的 `slotMax` 字段 | NPC 商店帧发**有效上限**，不发 authored（否则客户端将来按它封顶会自相矛盾） | `:55476`（普通页）/ `:55518`（捕获页 else 支） |
| 夹具分批 | `grant_items` 的分批值取同一个函数；拿 authored 分批会**比服务端更保守**（作者值 99 切成 101 发，`(16000016, 9999)` 那类整条发失败） | `开发工具/本地服务端夹具.py:573 per = int(server._item_stack_limit(int(item_id)) or 0)` |
| 客户端映射 | 离线发放物品按它堆 | `脚本/单例/游戏数据.gd:218 堆叠上限抬升表` ＋ `:220 static func 堆叠上限()`；用点 `脚本/单例/游戏会话.gd:1004` |
| 客户端报文硬闸 | 原来夹 `1..999`（**本工程自加，原版没有**）⇒ 抬到 `1..9999` | `脚本/单例/后端连接.gd:1364 request_cash_shop_buy` |

`gm_admin.py` 三处"单次发放堆叠上限"校验、GM 网页那枚 `stackMax`（`gm_admin.py:231`）都走
`_item_stack_limit` ⇒ 改一个函数就全一致，不用逐处补。

## ③ 门与反向对照

`测试/堆叠上限回归测试.gd`（147 门里的一条，25 判式）：① 客户端五档 authored 各一个真 id ＋ 查不到的 id；
② `数据/物品.json` 反证 authored 没被改；③ **行为腿**：`_离线发放物品("10000001", 300)` 只占 1 格
（旧口径按 99 切会占 4 格）＋ authored=1 那档不许抬；④ **报文腿**（`测试/测试后端连接.gd` 替身只记不发）：
5000 原样进报文、70000 夹成 9999、0 夹成 1；⑤ 服务端五处字面钉死；⑥ 夹具必须是 `server._item_stack_limit(`
且不许再用 `definition.stack_max` 取分批值（**带点号括号**，防注释与 `has_method` 喂绿）。
