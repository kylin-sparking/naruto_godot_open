# PK 判定（打其他玩家）真值对照表

> 判的是**一件事**：切了 PK 模式之后，点一个玩家，游戏该不该出手、不该出手时该说哪一句。
> 代码落点：客户端 `脚本/角色/PVP判定.gd`（纯函数）＋`脚本/地图/地图实体.gd`（拼输入）＋
> `脚本/角色/玩家.gd`（出手那一步）＋本地夹具 `服务端/runtime/tools/fake_flash_server.py`
> （`_ordinary_pvp_denial_reason`）。门：`测试/PK判定回归测试.gd`（离线判定表）＋
> `测试/PK打人在线回归测试.gd`（在线端到端，见 §7 状态）。

## §1 ⚠ 先记一条真值分叉：同一棵树里有**两份** MainLib 反编译，代码不一样

取证时间 2026-10-25 晚。起因是这条链做完之后，把文案回 core 语言包逐字对，发现
同一个键在两份反编译里字面不同 ⇒ 顺着查下去，两份连**分支数量**都不一样。

| 目录（`2.2.3优化版/HYSJ/logs/swfprobe/`） | `.as` 个数 | 反编译自哪个文件 | 字节 | md5 | 文件日期 |
|---|---|---|---|---|---|
| **`as3_MainLib` ← 认这份** | **1898** | `www/act_web_nya_208_isolated/asset/MainLib.swf` | 2,151,305 | `3ef4ccb48c5fb6065f7d09d8d9c880a3` | 2026-08-17 |
| `as3_MainLib_plain` | 1830 | 同目录 `MainLib_plain.swf`（与 `MainLib_pvp.swf` **md5 相同**，是同一份的改名副本） | 4,393,375 | `736b6a2c6eaffe9c1105f05d99bc7829` | 2026-07-25 |

凭什么说玩家加载的是上面那一行（三条独立证据）：

1. `nya-208-isolated-manifest.json` 与 `original-client-manifest.json` 里被登记成
   **`asset/MainLib.swf`** 的都是 2,151,305 那一份；`_plain` / `_pvp` 只出现在旁边的
   `path` 清单里（备用副本），加载器要的名字是 `MainLib.swf`。
2. 同目录那份 `MainLib.xml`（ffdec 对**实机 SWF** 的整包转储，33,666,553 字节）里
   `PVP_SAME_ZHENYING_NO_ATTACK`、`PVP_HUSONG_NO_ATTACK`、`很抱歉1%级之后才能PK`
   **三条全在**，而 `_plain` 那份 core 包里的 `对方处于和平保护模式状态下…`、
   `很抱歉%1级之后才能PK` **两条都不在** ⇒ 实机跑的是 `as3_MainLib` 的字面。
3. 工程归档此前已用全树 diff 证明等于 2.2.3，那个数是 **1898 个 `.as`**（= `as3_MainLib`）。

两份在这道判定上**实测差四处**（都够改变游戏行为，不是排版差异）：

| # | 差什么 | 实机 `as3_MainLib` | `_plain` | 后果（照错的那份会怎样） |
|---|---|---|---|---|
| 1 | 护送闸 | `:319` / `:406`：`showHuSongIcon && !isDoubleTime` ⇒ 打不了，话 `非活动期间，不能打劫` | **整段没有** | 护送活动期间可以打护送者（原版不让） |
| 2 | 阵营 case | switch 有四档：`:355` `case PVP_ZHENYING` ⇒ 同阵营打不了 | 只有三档 | 阵营模式下把队友/同阵营的人当可打目标 |
| 3 | 忍者3v3 | `:323` 四合一，`:325` 的队友保护是 `nowIn3v3 \|\| nowInNinja3v3` | 没有 `nowInNinja3v3` | 忍者3v3 里会打到自己队友 |
| 4 | 两道保护的位置 | 在**最后**（`可打玩家:376`、`的话:444/448`） | 在**最前** | 同一件事说的不是同一句话（见下面的例子） |

第 4 条举个能看见的例子：和平模式（1 档）点一个刚复活、带系统保护的人 ——
实机走到 switch 就 `return false` ⇒ 屏幕上那句是「很抱歉，您当前的PK模式为和平模式，
无法对该玩家造成伤害」；照 `_plain` 的写法会先撞上保护 ⇒ 说「玩家复活后处于系统保护状态」。
**能不能打是一样的，说的是哪一句不一样** ⇒ 这正是 `话` 与 `可打` 必须分开钉的理由（§5）。

另外两份的文案字面在三句上不同（其余十句同）：

| 键 | 实机（认这个） | `_plain` |
|---|---|---|
| `PVP_REALIVE_PROTECTION_NO_ATTACK` | 玩家复活后处于系统保护状态 | 对方处于和平保护模式状态下，无法攻击 |
| `PVP_NIGHT_PROTECTION_NO_ATTACK` | 玩家处于夜间挂机保护状态 | 对方处于夜间保护模式状态下，无法攻击 |
| `PVP_LOW_LEVEL_NO_ATTACK` | 很抱歉**1%**级之后才能PK（⇒ 换成 45） | 很抱歉**%1**级之后才能PK（⇒ replace 不到，屏幕上留 `%1`） |

⚠ 第一版（当晚 21 点前后）整条链是按 `_plain` 那份写的，包括「阵营档没有 case ⇒ 一路往下走」
和「`%1` 是原版自己的不一致」这两条**结论**——两条都是错的。工程里对两份反编译的引用普查：
`as3_MainLib` 32 处 / `as3_MainLib_plain` 5 处 ⇒ 少数那一侧（`导出PVP配置.py`、本篇、
`竞技场.md`、`组队.md`、`PVP判定.gd`）已随本轮改正；`竞技场.md` / `组队.md` 里**由 plain 推出的
行号与分支结论还没逐条重验**，记在 §7。

`数据/PVP配置.json`（生成工具 `开发工具/导出PVP配置.py`，源 = 原版 GameData `Pvp/open` 段；
钉到 `NARUTO_GAME_ROOT = <原版目录>`，
`dat/GameData.dat` = 2,681,869 字节、md5 `bbe7900d6595ab8beecabe1d1a38d339`）：

| json 键 | 值 | 原版读它的地方 | 谁用 |
|---|---|---|---|
| `pkLevel` | **45** | `PVPHandler.as:109` → `minPkLevel` | 客户端两道等级闸（`:368/:372`、`:437/:441`）+ 服务端 |
| `player2playerLevel` | **15** | `:110` → `pkLevelScope` | ⚠ **读进来之后这个类再没用过** ⇒ 客户端不拦等级差，只有服务端拦 |
| `configLevel` | 40 | `:96` → `minPanelLevel` | `canOpenPKPanel():557-559` —— 而该函数在整份 MainLib 里**零调用点**（两份都验过）⇒ 那颗钮和那张面板**不受等级限制**，照抄 |
| `protectTime` | 1800 | `:111` → `protectBuffTime` | 复活保护时长（服务端 buff 帧，本工程未接，#324） |
| `defenceTime` | 30 | `:97` → `beatBackDuration = ×1000` | 记仇时长（`signEnemy:542-553`） |
| `peaceMaps` | 5 张，第一张 **100000000 = 木叶村** | `:98-103` | 安全图闸 `:364` ⇒ **在村里打不了人是原版规则**，不是缺陷 |
| `unprotectedMaps` | 10 张 BOSS 图 | `:104-107` | `isUnprotectedMap:303-305`（无保护无惩罚） |

⚠ `GAME_DATA.取表()` 走 `JSON.parse_string` ⇒ 表里的数**全是 float**。
图闸必须按**数值**比（`_表里存过` 里 `int(项) == 数`）；写成 `Array.has(100000000)`（int）
恒假 ⇒「本地图禁止PK」整条失效、木叶村变成可以打人（实测踩过，门里钉了一条 + 一条变异）。
顺带记一句：GDScript 的 `==` 本来就会跨 int/float 比数 ⇒ 会栽的只有 `.has()` 这一种写法。

## §3 两个函数的逐句对照

`as3_MainLib/scripts/com/mxw/game/world/handlers/PVPHandler.as`
→ `脚本/角色/PVP判定.gd`。`switch` 用 `if` 链搬（GDScript 的 `match` 不穿透，而原版
`PVP_ZHENYING` 那一档**没有 break**）。

### `canAttackPlayer:313-381` → `可打玩家(模式, 我, 目标)`

| AS3 | 内容 | 我们 |
|---|---|---|
| `:315` | `if(!Config.ENABLE_PVP) return false` —— `Config.as:68` 是 `ENABLE_PVP:String = "1"`，**拿字符串当布尔**，只要不是 `""` 就恒真 ⇒ 这一支永远不拦 | `const 允许PVP := true`，照抄不"顺手修" |
| `:319` | `showHuSongIcon && !isDoubleTime` ⇒ false | `目标.护送旗 && !我.护送双倍` |
| `:323-333` | 3v3 / 忍者3v3 / 战场 / 跨服 四合一：其中两种 3v3 里 `isInTroop(目标)` ⇒ false，否则**直接 true** | `我.在3v3 / 在忍者3v3 / 在战场 / 在跨服` |
| `:335` | `isEnemy(目标)` ⇒ **true**（记仇，在 switch 之前） | `我.仇人` |
| `:342` | `case NONE`（=1 和平）⇒ false | `模式 == 和平` |
| `:344-349` | `case PVP_TEAM`（=2）：同队⇒false，否则 break | `模式 == 组队 and 我.同队` |
| `:350-354` | `case PVP_FAMILY`（=3）：同族⇒false，否则 break | `模式 == 家族 and 我.同族` |
| `:355-359` | `case PVP_ZHENYING`（=5）：同阵营⇒false（最后一个 case） | `模式 == 阵营 and 我.同阵营` |
| `:360` | `!isProtectedInPeaceMap()` ⇒ **true**；`Character.as:1658` = `!isFlagFighting` ⇒ 「目标在打架态 ⇒ 直接可打」 | `目标.打架旗` |
| `:364` | `isPeaceMap(本图)` ⇒ false | `是安全图(int(我.图号))` |

| `全体`（=4 `PVP_NONE`） | switch 里**没有这一档** ⇒ 一路往下 ⇒ 这就是"能打任何人"，也**不保护队友** | 同 |

### `getNoAttackWarning:392-453` → `打不了的话(模式, 我, 目标)`

顺序**与上面不同**（原版就是这样，别"对齐"它）：
`:394` 3v3 四合一 ⇒ `""`（**在最早**，比目标死亡还前）→ `:398` 目标死 ⇒ `""` →
`:402` 我死 ⇒ `WARNING_DEAD_NO_ATTACK` → `:406` 护送 ⇒ `PVP_HUSONG` →
`:412-430` switch 四档（和平/同队/同族/同阵营）→ `:432` `isPeaceMap && isProtectedInPeaceMap()`
⇒ `PVP_PEACE_MAP`（= 「安全图 且 目标**没**在打架态」）→ `:437/:441` 两道等级闸（各自
`.replace("1%", minPkLevel)`）→ `:444/:448` 两道保护 → `:452` `""`。

⇒ 由此产生两类**必须两个都问**的不一致，门里各钉了一条：
① 目标已死：`可打` 不看死亡（判在 `SkillHandler.canAttack`）⇒ 可打=true，而 `话`=""；
② 和平模式 + 带保护的目标：`可打`=false 且 `话`=和平那句（保护那两道轮不到）。

## §5 门：`测试/PK判定回归测试.gd`（表驱动判定门）

跑法与实测末行（原文照抄）：

```

PK判定门：判 91 条 / 红 0 条（通过）        （退出码 0，日志里 `^ERROR` 0 行）
```

- 判定表 **36 行**（`_一行`），每行同时钉 `可打`；`可打=false` 的行再钉"该说哪一句"
  （`"‹空串›"` = 必须一声不吭）。`可打=true` 的行**不判话** —— 原版只在打不了那一刻才问
  `getNoAttackWarning`，能打时那句永远不会显示，钉它就是把我的猜测当原版。
- 参照值来源：三个数写死成常数（不读被测模块）；每行的期望是**按 §3 的行号手推**；
  字面只在 §4 比对一次，门里只判"该说哪一句"（键）。
- ⚠ `话` 的期望值是从被测模块的 `话` 表取键值再算 ⇒ 它判的是**键**，不是字面；
  字面被改动（如 M5 那种把 `1%` 换成 `%1`）由独立的 `填数` 判据抓，不是由行抓。
- 输入用 `_我(等级, 图号, {…})` / `_标(等级, {…})` **具名覆盖**拼，不用一长串位置参数
  （#327 栽过 `bind` 实参错位）。⚠ `Dictionary.merge` 的第二参 `cover` **默认 false** ⇒
  必须写 `merge(覆盖, true)`，少一个 `true` 就是所有覆盖项静默失效、整表退化成"全默认"，
  一大半行变成 0 比 0（本轮就是这么红了十几条才逮到）。量具自检第 ⓪ 段专钉这一条。
- 计数自查用 `_查(条数 == 36, …)` 放在**最后**，`36` 不含自查本身（实参先于函数体求值）。

变异实测（六条，全部把被测模块改回 `_plain` 那份的写法；`<临时目录>/变异PK判定2.py`，
